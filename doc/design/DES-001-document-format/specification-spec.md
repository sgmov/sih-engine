# 规格文档特异化规范

本规范承载规格文档类型特异化的格式规则。按司衡哲学结构收敛对照的双视角论证，结构性元规则归决策文档，类型特异规范归本规范。本规范承接仓库结构决策与通用格式规范设计，定义规格文档的必选章节、归位判据、粒度判据与 CI 校验规则。规格文档承接道四规约与实现必有间隙命题，规格是契约，是验收依据。

本规范的元依据是仓库结构决策。本规范本身是设计文档，遵守通用格式规范设计与本规范自身的约束。

## 结构 {#structure}

规格文档承载接口契约与验收标准的定义，承接道四规约与实现必有间隙命题：规格是规约的载体。规格文档必选章节如下，每章节是必选。

- 接口签名：方法签名、输入输出、错误类型
- 数据契约：数据结构定义
- 状态转换：状态机定义，如适用
- 验收依据：可独立验收的工程单元

## 必选章节 {#required-sections}

本节承载规格文档必选章节的存在性校验，WRITING-SPEC-001 至 WRITING-SPEC-004 是 CI 校验规则。

- WRITING-SPEC-001 校验必须包含「接口签名」章节
- WRITING-SPEC-002 校验必须包含「数据契约」章节
- WRITING-SPEC-003 校验状态机定义章节如存在必须使用 mermaid 围栏代码块
- WRITING-SPEC-004 校验必须包含「验收依据」章节

## 归位判据 {#classification-criteria}

规格文档归位判据如下。

归位判据
: 一份内容核心是定义接口契约或验收标准，则为规格文档。

判据承接规格作为契约与验收依据的工程实践：规格是规约的载体，是验收依据。

## 粒度判据 {#granularity}

一份规格文档以一个可独立验收的工程单元为边界，承接可独立验收工程单元的工程实践归纳。

- 一个 trait 接口
- 一个状态机
- 一个验证管道
- 一个数据契约

不以整个模块为粒度，太粗；不以单个函数为粒度，太细。

## 与设计文档的关系 {#vs-design}

规格与设计是平级关系，不是包含关系。

- 规格答「是什么」：接口签名、数据契约、状态转换，是契约
- 设计答「怎么做」：架构选型理由、模块组织、依赖关系，是思路

## CI 校验规则 {#ci-rules}

CI 校验规则覆盖规格文档的类型特异校验项，不重复通用格式规范设计已承载的字符集、标题、锚点校验。WRITING-SPEC-001 至 WRITING-SPEC-005 是 CI 校验规则全集。

- WRITING-SPEC-001 校验必须包含「接口签名」章节
- WRITING-SPEC-002 校验必须包含「数据契约」章节
- WRITING-SPEC-003 校验状态机定义章节如存在必须使用 mermaid 围栏代码块
- WRITING-SPEC-004 校验必须包含「验收依据」章节
- WRITING-SPEC-005 校验接口签名的方法签名必须符合 Rust 或 Python 等目标语言的规范，如适用

## 认识论立场 {#epistemic-stance}

本规范的核心规则为设计推论（design-corollary）：工程设计选择，非逻辑必然。

- 必选章节清单与 CI 校验规则为设计推论（design-corollary）：判据是工程实践归纳，承接仓库结构决策的元规则下沉
- 归位判据为设计推论（design-corollary）：判据承接规格作为契约与验收依据的工程实践归纳
- 粒度判据为设计推论（design-corollary）：判据承接可独立验收工程单元的工程实践归纳
- 可证伪条件：若规格文档的接口签名与实现代码出现不可恢复的漂移，如三成接口签名与代码不一致，则规格作为契约的权威性失效，需强制引入代码生成或双向同步机制
