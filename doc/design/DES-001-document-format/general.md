# 通用格式规范

本规范使用标记语言（markdown），后续行文统一用中文。司衡引擎规定所有文档类型共享的格式规则。本规范承载通用格式规范，覆盖标记语言语法即标题、列表、定义列表、行内代码、链接等，文档结构骨架即标题层级、章节归属、渐进式披露，字符约束即 ASCII 与 CJK 字符集、标点规范、术语规则，适用于文档区所有受治理文档与治理区文档。本规范不覆盖各类型的必选章节、必选元素、归位判据，详见类型特异规范，不覆盖治理流程规则即哲学检验与留痕规约，详见治理流程规约。

本规范的元依据是「文档格式原则」决策。本规范本身不是治理信息，不承载元数据，是项目通用规约，遵守该决策的格式约束。

按司衡哲学结构收敛对照的双视角论证，三类内容归位不同文档层。

- 元原则「文档不自包含」归决策文档
- 通用格式规则归本规范
- 类型特异规范归后续设计文档

## 语法 {#syntax}

约束文档可使用的全部标记语言原生标记与自定义导航语法，未列明的标记一律禁止。

### 标题 {#syntax-heading}

行首使用 `#` 标记层级，`#` 数量对应标题级别，最多四级标题。二级至四级标题行末必须附加 `{#锚点名}` 显式定义锚点，用于中文标题的稳定导航引用。一级标题不带锚点，文档身份由文件名承载，锚点是文件名本身。

标题内中文之间不插入空格。含编号标记的标题即子决策或轮次或问题，编号标记与中文正文之间不插入空格。中文与英文或代码之间插入一个空格，适用英文混排规则。

### 正文 {#syntax-body}

使用空白行将一行或多行文本分隔创建段落，不要用空格或制表符缩进段落。

### 导航分隔符 {#syntax-nav}

仅用于文档内导航列表项，固定格式 `章节简述::[链接文本](#锚点)`，描述在前、链接在后，`::` 紧贴方括号 `[`，避免 `::` 后紧跟字母触发 emoji 短码渲染。

`::` 左右禁止添加任何空格，紧贴前后文本，仅允许半角双冒号，全角冒号、三连及以上冒号组合禁止。

`::` 仅在此导航列表语法中合法，文档其他位置禁止出现行首 `::`。

### 有序列表 {#syntax-ordered-list}

在每个列表项前添加数字并紧跟一个英文句点，列表应当以数字 `1` 起始，后续条目顺序递增。

### 无序列表 {#syntax-unordered-list}

在每个列表项前面添加连字符 `-` 并紧跟一个空格，支持缩进生成嵌套列表。

### 定义列表 {#syntax-definition-list}

第一行为术语，换行后键入一个冒号 `:` 并紧跟一个空格，后接填写释义内容。一个术语只能有一个冒号定义，不允许一个术语对应多行冒号释义。释义内容为纯文本段落，不允许嵌套其他列表。

### 任务列表 {#syntax-task-list}

在任务列表项之前添加连字符 `-` 和方括号 `[ ]`，并在 `[ ]` 前面加上空格，完成项标记为 `[x]`。

### 行内代码 {#syntax-inline-code}

使用单反引号包裹单词或短语，表示为代码或术语，内容内含反引号时改用双反引号包裹。

### 文本绘图图表 {#syntax-mermaid}

文本绘图图表（Mermaid）使用围栏代码块 ` ```mermaid ` 绘制流程图、时序图、状态图等，是绘图语法，用于表达流程、依赖、状态转换等结构关系，目的是提升人类视觉理解效率。

### 目录树结构 {#syntax-filetree}

目录树结构（filetree）使用围栏代码块 ` ```filetree ` 表达节点关系，是结构表达语法，用于呈现节点的层级与归属关系，性质是结构表达不是绘图。块内仅承载逻辑节点关系，不预声明物理形态，文件后缀、存储方式等物理实现细节由后续设计文档承载。

### 链接 {#syntax-link}

普通链接的链接文本放在方括号内，链接地址放在后面的圆括号中，格式 `[链接文本](链接地址 "可选悬停标题")`，悬停标题为可选项。引用样式链接在正文书写 `[文本][标签]`，文档末尾统一集中定义 `[标签]: <目标地址> (目标标题)`，目标标题为可选项。

### 业务文档围栏代码块禁用 {#syntax-fenced-code}

业务文档禁止使用标记语言围栏代码块。文本绘图图表与目录树结构围栏代码块除外。例外一：格式规范类文档可使用标记语言围栏代码块进行示例展示，但需在文档声明此例外。

### 头部元信息块禁用 {#syntax-frontmatter}

文档头部默认不使用头部元信息块（frontmatter）；会被司衡引擎阻断。如果用户开启了司衡引擎的宽松治理模式，会被标记但不阻断，确需使用头部元信息块，与一级标题之间不允许出现文本、空行、标记，头部元信息块结束后首个内容必须为唯一一级标题。

## 结构 {#structure}

下列规则约束文档整体骨架、标题层级、正文归属、链接排布等全局结构，统一所有文档的组织形式，保障可读性与自动化解析兼容性。

- 文档默认首行直接为一级标题，标题前方禁止放置任何内容
- 全文仅允许存在单个一级标题，禁止多处使用一级标题标记 `#`
- 一级标题下方紧邻文档概述，中间无任何其他内容
- 概述段落完成后，全文第一个二级标题统一命名为「概览」，承载渐进式披露的摘要层功能：概览本文档产出了什么即决策点、规格项、发现项，而非章节索引。全项目所有文档类型共用此标题，不按类型特异化
- 二级标题不能脱离一级标题独立存在，下级标题不可脱离直属上级标题
- 标题禁止跳级：`#` 后仅可接 `##`，`##` 后仅可接 `###`
- 推荐层级上限 3 级，全局最大允许 4 级标题 `####`
- 同一文档内，所有层级标题名称不得重复
- 除各级标题以外，文档其余内容均归类为正文
- 正文内容必须归属某一级标题，禁止存在无归属的孤立正文片段
- 行内代码仅用于标识术语、代码标识符、字段，禁止将整段文本包裹为行内代码，规范类文档的语法示范除外，需在文档声明此例外
- 外部资源使用引用样式链接，全部外部链接统一汇总至文末独立章节，不可零散穿插正文
- 项目内部跨文档跳转使用链接，链接地址使用相对路径
- 跨项目资源链接统一归类为外部链接
- 列表组织范式：引导短语末尾用冒号独立成段后接列表的写法禁用。按语义关系选择结构：正反面对立用有序列表嵌套无序列表，单纯列举用完整引导句加无序列表

## 字符 {#characters}

限定文档允许的字符集、标点规范、语种混写规则，保障文档字符纯度的同时确保与大语言模型（Large Language Model，以下简写为：LLM）的兼容性。

### 字符集 {#characters-charset}

文档仅允许 ASCII 与 CJK 标准字符集，禁止非标点类的 Unicode 扩展字符如 Emoji 及装饰符号、全角特殊符号等，禁止破折号 `——`，破折号是视觉污染，会混淆成「一」或 `--`，中文连接场景用全角冒号 `：` 替代。

### 中日韩标点 {#characters-cjk-punctuation}

CJK 标点按 GB/T 15834 规范使用，允许以下类别：

- 基础标点：`，`、`。`、`；`、`：`、`？`、`！`
- 引号：中文段落 `「」`；英文段落 `""`
- 书名引用：`《》`
- 括号：`（）`
- 复合标点：`……`、`·`

### 中英标点分用 {#characters-punctuation-split}

按语种段落分用。

1. 中文段落
   - CJK 标点加必要的 ASCII 标点，用于跨语种引用，如 `(...)` 包英文术语
2. 英文段落
   - 仅 ASCII 标点

### 字母与数字 {#characters-letter-number}

中文段落中的 ASCII 字母与数字有四种合法使用形式，与英文使用四类合法形式一致，清单与字符约束的规则张力在此显式调和。

1. 行内代码包裹
   - 用于术语、代码标识符、字段名
   - 如 `yaml`、`tree-sitter` 等无释义术语
2. 显式标注
   - 用于外来术语原文置于括号内
   - 如「事件层（event）」「编排器（orchestrator）」
3. 命名符号
   - 用于组合标识符
   - 如 NNN-slug、DES-ARC、DEC-001
4. 锚点 id、产品名、已展开缩写
   - 用于标记语法、产品名、已展开缩写
   - 如锚点 `{#event-layer}`、缩写 LLM、CJK

英文段落中 ASCII 字母与数字自由使用。

### 行内代码豁免 {#characters-inline-code-exempt}

行内代码内的标识符、字段名不受上述规则限制。围栏代码块内的内容不受字符约束限制。

### 术语规则 {#characters-term}

正文首次出现非当前行文语言的术语、词汇、短语，按是否有当前行文语言的释义分两种处理。

1. 有释义的
   - 以当前行文语言为主，将外来语原文置于括号内标注
   - 如中文段落中「编排器（orchestrator）」
2. 无释义的专用术语，无公认翻译或约定俗成不译
   - 直接以行内代码包裹，不套释义
   - 如「`yaml` 文件」「`tree-sitter` 索引」

术语在正文重复出现时的处理：有释义术语首次括号标注后，后续以当前行文语言裸用，不得将括号内英文搬到正文裸用；唯一例外是声明了「下文简写为」的缩写形式可在正文裸用。无释义术语每次出现均以行内代码包裹。

### 缩写规则 {#characters-abbr}

全大写缩写即代表一组词的首字母缩略，如 CJK、ASCII、LLM、API，在项目内首次出现时展开释义并声明简写，如「大语言模型（Large Language Model，以下简写为：LLM）」；项目内后续裸用缩写，不以行内代码包裹。

判别缩写与外来术语的边界：全大写且代表一组词的首字母缩略方为缩写；`OAuth`、`JSONL` 等首字母大写的专名不是缩写，按外来术语规则处理。

### 编号指代 {#characters-doc-id}

文档编码如 DEC-NNN、REQ-NNN、DEC-001 等文档编号，不是术语，性质同缩写，裸用不包裹。文档编码仅在明确需要翻阅原文档时使用，方便人类快速查找关键文件，不作为常规引用形式。

### 括号内裸用 {#characters-paren-bare}

括号最小化使用，能不用就不用，必须用时按本规则。括号内的内容属于正文补充，不属于正文，不适用行内代码包裹规则：括号内一律裸用，不论内容是术语、路径、编号、状态值还是其他。唯一例外：展示标记语言标记符号本身时，如粗体 `** **`、块引用 `>`，反引号用于阻止渲染而非正文包裹，保留。

## 禁用格式 {#forbidden}

下列标记语言语法、视觉标记一律不允许出现在业务文档内，仅作查阅参考，不参与核心规则导航。

- 粗体：`** **`
- 斜体：`* *`
- 非文本绘图图表、目录树结构类围栏代码块
- 表格
- 块引用：`>`
- 水平分割线：`---` `***`
- 所有本规范未明确列出的标记语法

## 示例章节 {#sample-section}

仅本规范类文档可用。本规范作为通用格式规范的载体，可在文档底部设立二级标题「示例」章节，承载标记语言围栏代码块的示例展示。其他业务文档如决策、设计、规格、规约、知识库、提案、需求，禁止设立示例章节，不得内嵌示例代码。

示例章节有以下使用约束。

- 仅规范类文档如通用格式规范、治理流程规约等可用
- 围栏代码块内容必须是格式示范，不是业务内容
- 业务示例应通过独立知识库文档承载，不在本规范内

## 决策后果 {#decision-consequence}

本规范的决策后果分正反两面。

### 决策正面后果 {#consequence-positive}

- 所有文档类型共用一套格式约束，跨类型可读性一致
- 格式约束可自动化校验，降低人工审阅负担
- 标题锚点稳定，跨文档导航可靠
- 字符约束保证大语言模型解析兼容性

### 决策负面后果 {#consequence-negative}

- 通用规范不覆盖类型特异结构需求，需配套类型特异规范
- 规范类文档享有围栏代码块例外，需在文档内声明
- 中英文混用治理增加术语首次出现的书写成本

## 备选方案 {#alternative-plan}

通用规范承载类型特异结构规则
: 已拒绝。混淆通用与特异的分工。按结构收敛对照的双视角论证，通用格式规则与类型特异规范分属不同视角，混装会让通用规范的稳定性被类型特异的迭代频率拖累。

字符集由类型特异规范各自定义
: 已拒绝。字符集约束即 ASCII 与 CJK、标点规范，跨类型一致，是文档可读性与大语言模型兼容性的统一保证。各类型各自定义会造成字符约束碎片化，自动化校验无法统一。

仅约束语法不约束结构骨架
: 已拒绝。语法即标题、列表等，与结构骨架即章节归属、渐进式披露，是文档可读性的两层基础，缺一不可。仅约束语法会让不同文档骨架差异大，自动化解析兼容性受损。

## 认识论立场 {#epistemic-stance}

本规范的认识论标签混合两种。

核心规则为设计推论（design-corollary），是工程设计选择，非逻辑必然。覆盖项：标记语言语法约束、文档结构骨架、禁用格式清单、示例章节约束、列表组织范式。

字符规则部分为外部锚定（external-anchor），承接外部技术约束：ASCII 与 CJK 字符集约束与大语言模型兼容性是外部技术约束。

可证伪条件一
: 若 CJK 段落实战中「」引号被证明与主流大语言模型解析器不兼容，则字符约束引号规则须修正

可证伪条件二
: 若文档结构约定导致自动化解析失败率超过一成，则结构规范须重新审视

可证伪条件三
: 若通用规范无法覆盖某文档类型的结构需求，且该需求无法通过类型特异规范承载，则通用规范需扩展

## 附录 {#appendix}

### 自反性声明 {#self-reflexive}

本规范作为规范类文档，享有以下例外，在对应规则处已声明。

- 行内代码规则：允许整段标记语言语法示范被反引号包裹，用于展示语法模式
- 围栏代码块规则：允许规范类文档使用标记语言围栏代码块进行示例展示

除此之外，本规范遵守自身定义的所有规则。基于全文扫描：标题锚点扫描 37 处二级至四级标题全部带锚点；字符集扫描全文无破折号与 Emoji 越界；连字符命名扫描全文使用一致称为连字符；列表组织范式扫描 15 处列表全部合规；英文使用扫描全文全部为四类合法形式。

### 术语表 {#glossary}

[^1]: 结构收敛对照：司衡哲学的双源对照方法论，将哲学推导侧命题与工程实践发现逐项对照检验，分骨架、结构、决策三类。双视角论证是其对照项之一：哲学侧与工程侧分属不同视角，元方向与实施规则分归不同文档层。

[^2]: 四柱石分层 + 元层：司衡哲学的五个治理分层。道层确立原则；法层确立方法；鉴层检验与去蔽；应层处理已发生/未形成的扰动；元层治理分三治，即治病、治益、治强，治理司衡哲学的治理命题本身。本规范归法层，承接的「文档不自包含」元原则归道层。
