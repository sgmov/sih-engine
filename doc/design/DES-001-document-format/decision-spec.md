# 决策文档特异化规范

本规范承载决策文档类型特异化的格式规则。按司衡哲学结构收敛对照的双视角论证，结构性元规则归决策文档，类型特异规范归本规范。本规范承接仓库结构决策与通用格式规范设计，定义决策文档的必选章节、归位判据与 CI 校验规则。

本规范的元依据是仓库结构决策。本规范本身是设计文档，遵守通用格式规范设计与本规范自身的约束。

## 概览 {#overview}

- 决策文档的概览章节特异化为「决策集」，固定二级标题骨架含决策集、决策后果、备选方案、关系图谱、认识论立场::[结构](#structure)
- WRITING-DEC-001 至 WRITING-DEC-009 校验必选章节的存在性::[必选章节](#required-sections)
- 决策归位判据承接治理动作产物的边界，与设计文档的技术选型分流::[归位判据](#classification-criteria)
- 子决策需包含决策内容、决策理由、关联规则::[必选元素](#required-elements)
- WRITING-DEC-010 至 WRITING-DEC-013 校验必选元素与拒绝理由::[CI 校验规则汇总](#ci-rules)
- 决策与设计文档的边界是治理动作产物与技术选型::[与设计文档的关系](#vs-design)
- 决策与提案是状态区别，已通过与待审议::[与提案文档的关系](#vs-proposal)
- 本规范承接仓库结构决策与通用格式规范设计::[关联](#relation)
- 本规范为设计推论（design-corollary），附可证伪条件::[认识论立场](#epistemic-stance)

## 结构 {#structure}

决策文档的二级标题骨架固定如下，承接通用格式规范设计的结构骨架。概览章节特异化为「决策集」，其余二级标题如下所列，各二级标题是必选。

- 决策集：渐进式披露的摘要层，列出本文档产出的所有决策点
- 决策后果：正面与负面影响
- 备选方案：考虑过但拒绝的方案及理由，使用定义列表格式
- 关系图谱：与其他决策、设计、规约的引用关系
- 认识论立场：决策的认识论标签、可证伪条件

子决策承载于「决策集」下，使用三级标题，每个子决策标题文字自定义。

## 必选章节 {#required-sections}

本节承载决策文档必选章节的存在性校验，WRITING-DEC-001 至 WRITING-DEC-009 是 CI 校验规则。

- WRITING-DEC-001 校验必须包含二级标题「决策集」
- WRITING-DEC-002 校验必须包含至少一个三级子决策标题，决策集下至少一项
- WRITING-DEC-003 校验决策集下每个子决策必须包含至少一个必选元素的描述
- WRITING-DEC-004 校验必须包含二级标题「决策后果」
- WRITING-DEC-005 校验决策后果必须包含「决策正面后果」与「决策负面后果」两个三级标题
- WRITING-DEC-006 校验必须包含二级标题「备选方案」
- WRITING-DEC-007 校验备选方案必须使用定义列表格式
- WRITING-DEC-008 校验必须包含二级标题「关系图谱」
- WRITING-DEC-009 校验必须包含二级标题「认识论立场」

## 归位判据 {#classification-criteria}

决策文档归位判据如下。

归位判据
: 一份内容核心是做了一个选择并记录理由和否决项，且为治理动作产物，不是技术选型，则为决策文档。

判据承接治理动作产物与技术选型的分流。治理动作产物即元规则确立、流程定义、归位判据等，归决策文档。技术选型决策如选用 SQLite、选用 markdown 归设计文档。

## 必选元素 {#required-elements}

决策集下每个子决策需包含以下元素，承接 WRITING-DEC-010 校验。

- 决策内容：陈述句承载决策本身
- 决策理由：哲学依据、SETSP 参考、其他文档引用
- 关联规则：被约束于某规则，影响范围

## CI 校验规则汇总 {#ci-rules}

CI 校验规则覆盖决策文档的类型特异校验项，不重复通用格式规范设计已承载的字符集、标题、锚点校验。WRITING-DEC-001 至 WRITING-DEC-013 是 CI 校验规则全集。

- WRITING-DEC-001 至 WRITING-DEC-009 校验必选章节存在性，详见必选章节
- WRITING-DEC-010 校验每个子决策必须包含「决策内容」段落
- WRITING-DEC-011 校验备选方案的拒绝理由不得为空
- WRITING-DEC-012 校验认识论立场必须包含可证伪条件
- WRITING-DEC-013 校验关系图谱必须包含至少一个外部引用，如 DEC、DES、SPEC、GOV 等

## 与设计文档的关系 {#vs-design}

决策文档承载治理动作产物，设计文档承载技术选型决策。同一议题若落到治理动作即元规则确立、流程定义，归决策文档。若落到技术选型即选用 SQLite、选用 markdown，归设计文档。两者承接关系不同，决策文档是设计文档的元依据。

## 与提案文档的关系 {#vs-proposal}

决策是已通过治理方案，提案是待审议治理方案，区别是状态，不是格式自由度。决策与提案都遵循仓库结构决策的格式约束与通用格式规范设计，都使用定义列表格式承载候选与备选方案。提案经审阅后由痕迹决定是否迁移为决策。

## 关联 {#relation}

- 元依据：仓库结构决策 DEC-001
- 承接：通用格式规范设计 DES-001
- 衔接：其他类型特异规范，覆盖设计文档、提案文档、需求文档、规约文档、规格文档、知识库文档各自的特异规范
- 流程衔接：审阅机制 PRO-006，类型归属由审阅痕迹决定
- 工程参考：SETSP 工程桥的治理文档约定，Stage 编码标记 decision 阶段表示已通过评审并获得批准
- 哲学对应：决策是应在治理语境下的具体形态，承接结构收敛对照的骨架论证

## 认识论立场 {#epistemic-stance}

本规范的核心规则为设计推论（design-corollary）：工程设计选择，非逻辑必然。

- 必选章节清单与 CI 校验规则为设计推论（design-corollary）：判据是工程实践归纳，承接仓库结构决策的元规则下沉
- 归位判据为设计推论（design-corollary）：判据承接治理动作产物与技术选型的分流边界
- 与设计文档的边界为设计推论（design-corollary）：边界是工程约定，承接 SETSP 工程桥的治理文档约定
- 可证伪条件一：若实践中超过三成的决策文档不遵守本规范的必选章节约束，且违反不影响决策可追溯性，则本规范的强制约束须重新审视
- 可证伪条件二：若归位判据在实战中出现大量边界模糊案例，既像决策文档又像设计文档，则判据须重新审视
