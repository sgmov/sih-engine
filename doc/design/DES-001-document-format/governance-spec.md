# 规约文档特异化规范

本规范承载规约文档类型特异化的格式规则。按司衡哲学结构收敛对照的双视角论证，结构性元规则归决策文档，类型特异规范归本规范。本规范承接仓库结构决策与通用格式规范设计，定义规约文档的必选章节、归位判据与力度分级。规约承接法·有度「治有分限」与法·知止「知止而后有定」，是持续生效的治理规则。

本规范的元依据是仓库结构决策。本规范本身是设计文档，遵守通用格式规范设计与本规范自身的约束。

## 结构 {#structure}

规约文档承载持续生效的治理规则，承接法·有度「治有分限」与法·知止「知止而后有定」。规约文档必选章节如下，每章节是必选。

- 适用范围：规约适用对象与边界
- 规则正文：具体规则条目，每条规则独立编号
- 失败模式：规则可能失效的情形
- 认识论立场：规则的认识论标签、可证伪条件

## 必选章节 {#required-sections}

本节承载规约文档必选章节的存在性校验，WRITING-GOV-001 至 WRITING-GOV-004 是 CI 校验规则。

- WRITING-GOV-001 校验必须包含「适用范围」章节
- WRITING-GOV-002 校验必须包含「规则正文」章节
- WRITING-GOV-003 校验规则正文必须使用有序列表，每条规则独立编号
- WRITING-GOV-004 校验必须包含「失败模式」章节

## 归位判据 {#classification-criteria}

规约文档归位判据如下。

归位判据
: 一份内容核心是定义持续执行的治理规则，即引擎运行时遵守的约束，则为规约文档。

## 与决策文档的关系 {#vs-decision}

决策是治理决策动作的产物，一次性固化，变更走 `supersede`。规约是持续生效的约束，区别于决策的一次性固化。

DEC 承载「为什么这样定」的论证，GOV 承载「具体规则条文」的正文。

## 与设计文档的关系 {#vs-design}

设计文档承载工程实现思路，回答怎么建的问题。规约文档承载治理流程规则，回答治理动作怎么做的问题。两者不重叠：DES 是工程实现层，GOV 是治理流程层。

本规范不承载通用格式规范或类型特异规范，那些是文档内容规范，不是治理流程规则。

## CI 校验规则汇总 {#ci-rules}

CI 校验规则覆盖规约文档的类型特异校验项，不重复通用格式规范设计已承载的字符集、标题、锚点校验。WRITING-GOV-001 至 WRITING-GOV-005 是 CI 校验规则全集。

- WRITING-GOV-001 至 WRITING-GOV-004 校验必选章节存在性，详见必选章节
- WRITING-GOV-005 校验每条规则必须包含力度标记，即 F、G、J 三级或类似分级标识

## 认识论立场 {#epistemic-stance}

本规范的核心规则为设计推论（design-corollary）：工程设计选择，非逻辑必然。

- 必选章节清单与 CI 校验规则为设计推论（design-corollary）：判据是工程实践归纳，承接仓库结构决策的元规则下沉
- 归位判据为设计推论（design-corollary）：判据承接规约作为持续生效治理规则的工程实践归纳
- 可证伪条件：若规约文档的规则被普遍忽略，例如三成规则无人遵守，则规约的持续生效约束失效，需重新评估规则的必要性或降低规则力度
