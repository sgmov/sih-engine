# 体系定义特异化规范

本规范承载体系定义特异化的格式规则，覆盖 `doc/design/architecture/` 子目录下 ARC-NNN-slug.md 文档的类型特异格式规则。体系定义作为设计文档的子类型，按司衡哲学结构收敛对照的双视角论证，结构性元规则归决策文档，类型特异规范归本规范。本规范承接仓库结构决策与通用格式规范设计及设计文档格式规范，定义体系定义的必选章节、归位判据与系统本体结构约束。体系定义按哲学仓 `convergence/02-structure-convergence.md` 结构视角归类，承接元层即哲学仓 `convergence/09-on-arche.md` 的工程化表达，是元层约束的工程化承载。

本规范的元依据是仓库结构决策。本规范本身是设计文档，遵守通用格式规范设计与本规范自身的约束。

## 结构 {#structure}

体系定义文档承载系统本体结构的描述，承接元层约束的工程化表达。体系定义文档章节如下。

- 系统构成：系统由哪些部分组成
- 组织原则：各部分如何组织、依据什么原则
- 约束关系：各部分之间的约束、相互引用
- 演化路径：历史演化、当前状态、未来演进方向

前三项为必选章节，演化路径视情况设立。

## 必选章节 {#required-sections}

本节承载体系定义文档必选章节的存在性校验，WRITING-ARC-001 至 WRITING-ARC-004 是 CI 校验规则。

- WRITING-ARC-001 校验必须包含「系统构成」章节
- WRITING-ARC-002 校验必须包含「组织原则」章节
- WRITING-ARC-003 校验必须包含「约束关系」章节
- WRITING-ARC-004 校验约束关系章节必须使用 mermaid 围栏代码块绘制关系图

体系定义文档归位判据如下。

归位判据

## 与设计文档的关系 {#vs-design}

设计文档承载「怎么建」即技术设计与模块组织，体系定义承载「系统是什么」即构成与组织原则。两者交叉引用：

- 设计文档引用体系定义的体系约束作为设计依据
- 体系定义引用设计文档的工程实现作为约束落地

物理上体系定义在 `design/` 子文件夹，不独立为顶层类型，见 DEC-001 体系定义子类型章节。

## CI 校验规则汇总 {#ci-rules}

CI 校验规则覆盖体系定义文档的类型特异校验项，不重复通用格式规范设计已承载的字符集、标题、锚点校验。WRITING-ARC-001 至 WRITING-ARC-005 是 CI 校验规则全集。

- WRITING-ARC-001 校验必须包含「系统构成」章节
- WRITING-ARC-002 校验必须包含「组织原则」章节
- WRITING-ARC-003 校验必须包含「约束关系」章节
- WRITING-ARC-004 校验约束关系章节必须使用 mermaid 围栏代码块绘制关系图
- WRITING-ARC-005 校验系统构成必须明确每个组成部分的职责，以一句话概括

## 认识论立场 {#epistemic-stance}

本规范的核心规则为设计推论（design-corollary），承接哲学仓 `convergence/01-skeleton-convergence.md` 的元层映射，元原则的显式承载与元层作为独立支柱。

可证伪条件：若体系定义文档失去对设计或规约文档的引用权威性，如设计文档普遍忽略体系约束，则体系定义作为「元约束」失效，需重新评估子文件夹方案，可能升级为顶层类型。
