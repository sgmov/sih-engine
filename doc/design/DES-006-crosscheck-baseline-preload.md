# 参验基准预置机制

本设计定义文档修改场景下的参验基准预置机制。参验承接 DES-003 参验组件协议，本设计不改变参验的状态机与独立性约束，只在参验执行前加一个基准预置步骤，解决文档修改后遗忘参验的可靠性问题。

问题来源。实测中三次修改文档后仅运行 sih-doclint 即认为完成，遗漏了参验环节。sih-doclint 校验格式合规即参验路径一，查不出声明与正文的语义一致性偏差即参验路径二。三次遗漏引入的偏差均由人类提醒后发现，证明生成后参验依赖主动回忆触发不可靠。

## 概览 {#overview}

- 参验基准预置在文档修改前锁定检查对象，修改后对照清单参验不依赖回忆::[机制定义](#mechanism)
- 四类检查对象覆盖声明一致性、数据准确性、标题正文一致性、上游承接::[清单模板](#checklist-template)
- 文档修改触发基准预置，文档创建不触发::[触发时机](#trigger)
- 本机制在参验状态机 Pending 态之前加基准预置前置步骤，不改变状态机::[与参验协议的关系](#vs-crosscheck-protocol)
- sih-doclint 是路径一的实例候选查格式合规，基准清单是路径二的前置输入查语义一致性，两条路径互补::[与 sih-doclint 的分工](#vs-doclint)
- 承接 Phase 2 的提取判断分离原则，确定性锁定检查对象执行者只对照不回忆::[选型理由](#rationale)

## 技术设计 {#tech-design}

### 选型理由 {#rationale}

基准预置采用文档层落地，不采用脚本层或工具层。选型依据三条。

第一条，当前是手动阶段。AGENTS.md 标注当前协助人类决策者模拟司衡引擎的治理动作，sih-doclint 暂借旧仓二进制。脚本层或工具层自动化在工具链迁移后才有稳定基础，当前落地文档层最贴合阶段状态。

第二条，Phase 2 验证提取判断分离的有效性。Phase 2 实验中确定性提取脚本在 LLM 判断前生成固定清单，LLM 只判断不抽取。此机制使判断不依赖回忆，可靠性高。本设计将同一原则迁移到文档修改场景：修改前锁定清单，修改后对照参验。

第三条，文档层固化可渐进升级。先以流程规范固化行为，验证有效性。若实践中清单仍无法防止语义偏差漏检，再升级到脚本层自动提取检查对象，最终升级到工具层自动参验。三层渐进，不在当前阶段过度投入。

### 机制定义 {#mechanism}

参验基准预置机制含两个步骤，按顺序执行。

第一步基准预置。文档修改前，填写参验基准清单。清单逐条记录本次修改涉及的检查对象。检查对象分四类，详见清单模板。清单是参验的基准，锁定后修改过程对照清单执行。

第二步修改后参验。文档修改完成并经 sih-doclint 校验通过后，对照预置清单逐条参验。参验按参验协议两层执行，反映层呈现差异事实，处置层做偏差分类。发现偏差即修复，修复后重新参验，直至无偏差。

两步的关系。基准预置在修改前，参验在修改后。预置锁定检查对象消除回忆依赖，参验执行语义校验。两步不可合并：预置若在修改后做，检查对象会受修改结果影响失去独立性；参验若在修改前做，没有材料可参验。

### 清单模板 {#checklist-template}

参验基准清单含四类检查对象。每类对象有明确的检查问题与偏差分类。

第一类声明一致性。检查问题：文档自检小节的声明与正文实际内容是否对应。偏差类型：过度实现即声明了正文未实现的内容，低度实现即正文实现了声明未覆盖的内容，不一致即声明与正文矛盾。此类的典型场景是自检声明引用了已删除的代码格式或已改名的组件。

第二类数据准确性。检查问题：文档引用的数据与数据来源是否一致。偏差类型：不一致即引用数据与来源不符。此类的典型场景是引用实验百分比与聚合分析输出不符。

第三类标题正文一致性。检查问题：标题表述与正文归因或论述是否矛盾。偏差类型：不一致即标题方向与正文方向相反或矛盾。此类的典型场景是正文修正了归因但标题保留旧表述。

第四类上游承接。检查问题：修改处与被承接的上游文档是否一致。偏差类型：不一致即修改引入了与上游文档矛盾的内容。此类的典型场景是命名变更传播不完整，部分文档仍用旧名。

### 触发时机 {#trigger}

基准预置的触发时机是文档修改。文档修改定义为对已存在文档的正文字段、数据、声明、标题的实质性变更。以下情况触发基准预置。

正文修订触发。修改文档正文内容，含数据更新、归因修正、措辞调整。触发后预置清单覆盖修改涉及的声明一致性、数据准确性、标题正文一致性、上游承接四类。

命名传播触发。组件或概念的命名变更，须传播到全仓引用此命名的文档。触发后预置清单覆盖上游承接类，重点检查是否所有引用处已同步更新。

以下情况不触发基准预置。

文档创建不触发。文档创建时整篇文档是新材料，经完整参验。创建后首次参验覆盖全文，不需要预置清单。

格式微调不触发。仅修改空格、标点、排版等不涉及语义的格式调整，经 sih-doclint 校验即可，不需要参验。判据是修改是否涉及声明、数据、标题、承接这四类检查对象的任何一项。

### 与参验协议的关系 {#vs-crosscheck-protocol}

本机制不改变参验状态机。参验状态机定义在 SPEC-003 规格文档，含 Pending 即待校验、Checking 即校验中、Completed 即已完成三态。DES-003 定义参验的组件协议即反映层与处置层的职能划分，SPEC-003 定义参验的接口契约与状态机。

本机制在 Pending 态之前加一个基准预置前置步骤。完整流程变为：基准预置、材料生成即文档修改、参验执行含路径一格式校验与路径二语义校验、留痕。参验的两条路径同属参验，sih-doclint 是路径一的实例候选不是独立于参验的并列步骤。基准预置是材料生成的前置条件，不是参验的内部状态。

本机制不改变参验的独立性约束。参验仍在材料生成后执行，参验不参与生成过程。基准预置锁定的是检查对象不是判断结论，预置清单不含预期答案，只含检查项。

### 与 sih-doclint 的分工 {#vs-doclint}

sih-doclint 与参验基准清单是参验两条路径的分工，互补不替代。

sih-doclint 是参验路径一确定性规则校验的实例候选，当前暂借旧仓二进制，待 sih-engine 工具链迁移后正式落位。路径一检查格式合规，含字符集、标题锚点、结构、列表、禁用格式。sih-doclint 的检查是确定性的，同一输入同一输出，可机械复现。

参验基准清单是参验路径二语义校验的前置输入。路径二的执行按 SPEC-003 定义，含 N 等于 4 隔离采样、多数投票、tie-break 机制，LLM 产出语义判断材料，确定性聚合程序做度量。在当前手动阶段，文档修改场景的路径二参验由人类或 agent 对照基准清单执行，N 采样机制的全自动化待工具链迁移后承载。基准清单锁定检查对象即声明与正文对应、数据准确、标题正文一致、上游承接，路径二的参验执行对照清单判断语义一致性。

两路径的覆盖不重叠。sih-doclint 查不出声明与正文的语义矛盾，参验基准清单查不出字符集违规。两路径串联执行：先 sih-doclint 过格式，再参验基准清单过语义。

## 工程实现 {#implementation}

### 参验基准清单实例格式 {#checklist-format}

参验基准清单以列表形式承载，每条含四个字段。

序号字段。整数，从 1 起。

检查对象字段。四类之一即声明一致性、数据准确性、标题正文一致性、上游承接。

检查项字段。具体检查内容陈述。例如自检第 N 行声明与正文第 M 行内容对应。

来源字段。检查项的依据出处。例如 DES-003 第 65 行、Phase 2 重跑聚合分析输出。

清单实例随修改提交，不单独存储为文档。清单实例是修改过程的伴随产物，归事件流留痕。

### 回顾验证 {#retrospective}

本设计定义的清单模板可用于回顾验证历史修改场景。以本次设计链中三次遗漏参验的场景做回顾验证。

场景一，DES-003 参验协议修订。修改涉及组件命名即映照改参验、职能两层划分、数据格式补字段。若预置清单，检查对象覆盖声明一致性即自检声明是否反映两层划分、上游承接即其他文档的映照引用是否同步更新。遗漏上游承接类导致命名传播缺口延后才发现。

场景二，SPEC-003 起草。修改涉及 Rust 代码块改文字描述。若预置清单，检查对象覆盖声明一致性即自检声明符合 Rust 规范与正文无 Rust 代码矛盾。遗漏声明一致性类导致自检遗留偏差。

场景三，Phase 2 结论更新。修改涉及结论三归因修正。若预置清单，检查对象覆盖标题正文一致性即标题真实信号与正文归因修正矛盾。遗漏标题正文一致性类导致标题偏差。

三个场景覆盖声明一致性、标题正文一致性、上游承接三类检查对象。数据准确性类基于典型场景预设即引用实验百分比与聚合分析输出不符，尚未在实测中触发，但作为预防性检查项保留。

## 认识论立场 {#epistemic-stance}

本设计为设计推论（design-corollary），是工程流程设计选择，非逻辑必然。

可证伪条件一
: 若实践中参验基准清单仍无法防止语义偏差漏检，即清单预置后修改仍引入清单未覆盖的偏差，则文档层固化不足以保证可靠性，须升级到脚本层自动提取检查对象。

可证伪条件二
: 若实践中基准预置的成本即填写清单的时间开销超过偏差修复的成本，则本机制的收益不足以支撑其流程开销，须简化清单或调整触发时机。

可证伪条件三
: 若 sih-engine 工具链迁移后 sih-doclint 可扩展承载语义一致性检查，则路径二的参验基准清单可被工具层替代，本机制降级为工具层校验的前置输入。

## 自检 {#self-check}

### 形式合规自检 {#formal-self-check}

- 一级标题无锚点，仅一个
- 二级及以上标题均带锚点
- 首个二级标题命名为概览
- 无破折号、无装饰符号、无 Unicode Emoji
- 全角括号仅用于单一治理编号

### 内容自检 {#content-self-check}

- 基准预置承接 Phase 2 提取判断分离原则，不凭空设计
- 四类检查对象中三类经回顾验证即声明一致性、标题正文一致性、上游承接，数据准确性类基于典型场景预设
- 触发时机区分文档修改与文档创建，判据明确
- 与参验协议的关系明确，不改变状态机只加前置步骤
- 与 sih-doclint 分工明确，两路径互补不替代
- 认识论立场标注为设计推论，附三条可证伪条件含升级路径

### 自反性结论 {#reflexive-conclusion}

本设计定义参验基准预置机制，解决文档修改后遗忘参验的可靠性问题。本机制不改变参验的哲学约束，只在流程层加基准预置步骤。本设计本身须按其定义的清单模板参验，详见本次修改的伴随清单。
