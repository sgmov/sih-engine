# 裁决材料基线核对设计

## 概览 {#overview}

- 本设计承接 OQ-21 人节点全退化决议与 OQ-22 二层裁决结构，定义 facet 裁决材料进入 sih-engine 确定性基线核对的规则集与闸三态映射表::[结构定位](#positioning)
- 核对规则七条，每条映射工程基线条目并给出机械化判据，全部由确定性程序计算不调用 LLM::[核对规则集](#rule-set)
- facet 闸三态加温度探针判定到裁决处置的映射，stable_clear 加核对全过才构成裁决通过::[闸三态映射](#gate-mapping)
- 输出契约承接 SPEC-004 crosscheck_completed 事件与 event_class 分类，异常信号进视图，人只在异常时介入::[输出契约](#output-contract)
- 桥接件是参验组件的确定性裁决入口，正式名执契英文对 tally，立名承 DEC-019::[桥接件定位](#bridge)
- 合规性不等于正确性，语义正确性由审计事后追偿与 flywheel 全历史承担::[认识论立场](#epistemic-stance)

## 结构定位 {#positioning}

二层裁决结构。上层是 facet 范式，LLM 席位对锚定命题采样，锚定白名单机械剔除，闸 v3 产出三态裁决与全历史 trail，全部产物定位为符号材料。下层是 sih-engine 确定性程序，消费材料，执行基线核对，通过则写裁决事件进事件流，全程留痕审计。

该结构是工程基线第一条的字面构成。facet 是材料生成器，不拥有写入权限。基线核对器是执行者，拥有核对权与写入权。两层之间的唯一接口是本设计定义的材料契约与输出契约。

上层材料进入下层时不依赖任何实时人节点。人的参与形态退化为两类事后动作。第一类是异常介入，核对不过、挂起、席位异常以视图告警形态出现，人按工程基线第三条只在告警时介入。第二类是审计追偿，人可随时复核 trail 与事件流，哈希链保证历史不可篡改。

## 核对规则集 {#rule-set}

七条规则，每条标注承接的工程基线条目与机械化判据。核对程序对每份裁决材料逐条计算，输出通过项与失败项清单，失败项进入映射表的处置逻辑。判据全部为确定性计算，不调用 LLM。

规则 R1 执行者归属。承接工程基线第一条。判据一，裁决事件的 actor 字段必须是系统类型程序标识，event_stream append 已内置该校验，Agent 类型 invoked_via 含 LLM 模式串即拒绝写入。判据二，核对过程中 facet 材料文件以只读方式消费，核对程序不得写 proposition 目录。判据三，裁决事件 details 须记录核对程序自身的版本标识。

规则 R2 来源可追溯。承接工程基线第四条第一性质。判据一，材料必须含 gid、topic_sha256、dc_fingerprint 三字段且类型正确。判据二，材料引用的 topic.md 与 trail 文件在核对时真实存在。判据三，topic_sha256 与 topic.md 全文复算结果一致，防止材料与命题文本错位。

规则 R3 结果可机械校验。承接工程基线第四条第二性质。判据一，闸裁决值属于 stable_clear、near_threshold、boundary 三值集合，criteria_version 等于 v3。判据二，per_actor 记录七字段齐全，decision 值属于 comply、violate 集合。判据三，核对程序自身的输出可被独立机械程序复核，规则失败项必须携带规则标识与失败位置。

规则 R4 历史不可篡改。承接工程基线第四条第三性质。判据一，裁决事件写入前对目标 trail 文件执行 verify_chain 且通过。判据二，写入后重读文件复算末事件哈希与事件内记录一致。判据三，trail 文件按日期命名追加写，禁止重写历史行。

规则 R5 席位有效性。承接 OQ-21 待定二的强度下限约束。判据一，材料产出席位的当日温度探针判定为可用。判据二，探针判定为基线异常时该席位当日全部材料核对直接失败。判据三，探针判定为漂移告警时该席位当日材料进入挂起处置，历史判据重估完成前不得通过核对。

规则 R6 预算上限。承接工程基线第二条与第五条。判据一，同一 gid 的累计采样发数不超过 9，即 facet 延采机制的上限值。判据二，裁决事件 details 记录本次裁决消耗的采样发数与 token 估算值。判据三，单日裁决事件总量超过阈值时核对程序产出视图告警，不阻断当日裁决。

规则 R7 谱系完整。承接 facet topic 哈希锁与改写谱系机制。判据一，同 gid 重复测量时 topic 哈希锁由 facet runner 强制，核对程序复核 trail 内全部记录的 topic_sha256 一致。判据二，改写重测使用新 gid 时，材料 authored 字段必须含前置 gid 与改写理由的谱系披露。判据三，谱系链上同一命题的改写次数超过 3 时核对程序产出视图告警，提示钓邻域风险。

## 闸三态映射 {#gate-mapping}

facet 闸三态与温度探针判定到裁决处置的映射。处置枚举四值，裁决通过、材料退回、挂起、打回重作。映射先查席位有效性，再查闸三态，最后叠加核对规则结果。

第一优先级，席位异常。温度探针判定基线异常，该席位当日全部材料处置为挂起，写 inconsistency 事件，event_class 取可消费。判定漂移告警，该席位当日材料处置为挂起，写 inconsistency 事件，登记历史判据重估任务。

第二优先级，boundary。闸裁决为 boundary，处置为打回重作，裁决不通过。打回后改写重测必须走新 gid 加谱系披露，受规则 R7 约束。写 crosscheck_completed 事件，负载偏差记录含闸裁决与变卦率。

第三优先级，near_threshold。闸裁决为 near_threshold，处置为挂起，裁决不通过。挂起材料的升级路径为池化多席位重测，池化形态待 OQ-21 待定二裁决，裁决前挂起材料累积不消化。写 crosscheck_completed 事件，负载偏差记录含闸裁决与近临界指标。

第四优先级，stable_clear。核对规则 R1 至 R7 全过，处置为裁决通过，裁决方向沿用席位众数方向，写 crosscheck_completed 事件，负载通过记录含闸裁决、方向、v3_rule、规则版本、材料指纹。任一规则失败，处置为材料退回，裁决不通过，写 crosscheck_completed 事件，负载偏差记录含失败规则标识与失败位置。

处置为退回、挂起、打回的 crosscheck_completed 与 inconsistency 事件，event_class 取可消费进视图。处置为裁决通过的事件，event_class 取仅记录，不进人类视图，异常时由审计追偿路径复核。

## 输出契约 {#output-contract}

核对程序的全部输出为事件流事件，承接 SPEC-004 五类事件与负载定义。裁决通过与不通过统一写 crosscheck_completed，负载结构在 SPEC-004 已定义的差异事实与偏差记录或通过记录基础上扩展六个字段，gid、topic_sha256、dc_fingerprint、闸裁决、规则版本、采样发数。席位异常写 inconsistency，负载含席位标识、探针判定值、影响材料清单。

事件写入复用 event_stream append 接口，trail 文件按日期命名。核对程序不自行实现写入，不绕过 append 的四项内置校验。

## 桥接件定位 {#bridge}

核对程序是参验组件的确定性裁决入口，承接 SPEC-003 两条路径共享的度量权威约束，度量值永远由确定性程序计算，LLM 在两条路径中都是材料生成器不是度量权威。核对规则集是路径一形态的规则集，作用对象是路径二形态的语义材料，即用确定性规则校验语义材料的形式合规与来源合规，不重新计算语义方向。

正式名执契英文对 tally。按 PRO-001 立名本体论走完整立名三段，2026-08-29 用户逐名签署，登记见 DEC-019。该件落地后同时承接三个落点。第一，OQ-09 doclint 迁移获得组件协议承接方。第二，OQ-10 旧仓 MCP 的 record_trail 职能获得新仓等价实现路径。第三，OQ-11 OQ 机制的消化获得确定性程序承载形态。

## 边界 {#boundary}

本设计不含核对程序代码实现，实现归后续 SPEC。不含组件正式立名，立名归后续 DEC。不修改 facet 仓任何代码与判据，facet 判据 v3 交付定格不动摇。不改变 Phase 2 语义验证结论的固化状态。不承接 OQ-21 待定二的池化形态裁决，映射表中挂起处置已为该裁决预留接口。

## 认识论立场 {#epistemic-stance}

本设计的核心结论标注 design-corollary，基于工程基线与 facet 实测知识的工程推断，非逻辑必然。

基线核对保证合规性不保证正确性，是本设计的认识论边界声明。核对规则校验执行者归属、来源、可校验性、不可篡改性、席位有效性、预算、谱系，全部是形式与来源维度的判据，不触碰语义方向本身的真值。语义方向的正确性由三重事后机制承担，flywheel 全历史累积、审计追偿、席位温度与漂移监测。

可证伪条件一：若基线核对通过的裁决在审计抽查中语义错误率显著高于人类实时签核的对照基线，则二层结构须重新引入实时人闸或强制池化多席位下限，本设计的映射表作废重立。

可证伪条件二：若出现核对规则无法覆盖的越权形态，例如新 LLM 通道绕过执行者归属校验，则规则集版本升级完成前裁决通道整体降级为挂起，本设计暂停执行。

可证伪条件三：若挂起队列在无池化裁决的情况下持续累积超过消化能力，即 OQ-21 待定二长期悬置，则本设计的挂起处置退化为遗忘清单，与旧仓 OPEN-QUESTIONS 失败模式同构，须视为设计失败。

## 自检 {#self-check}

### 形式合规自检 {#formal-self-check}

- 一级标题无锚点，仅一个
- 二级及以上标题均带锚点，首个二级标题命名为概览
- 无破折号、无装饰符号、无 Unicode Emoji
- 全角括号仅用于治理文档编号引用
- 导航行使用半角双冒号加锚点链接格式

### 内容自检 {#content-self-check}

结构定位小节承载二层分工与人的两类事后参与形态，未混入规则细节。核对规则集七条各自标注工程基线承接与机械化判据，判据全部确定性可计算。闸三态映射按优先级排序，席位异常先于闸三态，stable_clear 叠加核对结果的通过与退回两分支均定义事件与 event_class。认识论边界显式声明合规性与正确性的分离，可证伪条件三指向旧仓遗忘清单失败模式，不回避本设计自身的失败可能。桥接件立名已落 DEC-019，正式名执契英文对 tally，暂名基线核对器退役为描述语不复用作名。

### 自反性结论 {#reflexive-conclusion}

本文档按 DES-001 格式自我审视，规则集与映射表均为机械可执行判据，不依赖本文档之外的口头共识。本设计自身将作为首个被测对象进入二层结构，本文档的修订即为该结构的第一次实战检验。
