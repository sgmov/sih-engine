# 第一阶段组件清单与协议

本设计定义 sih-engine 第一阶段的最小闭合治理环组件。第一阶段目标是打通一次完整的意图到执行到参验到留痕闭环，验证核心机制的可验证性。

第一阶段不追求功能完整，只追求闭环可验证。第一阶段不引入多 Agent 协同组件。多主体协作作为鉴层检验机制保留，但不在第一阶段的执行环节启用。

## 概览 {#overview}

- 最小闭合治理环含四个节点，对应四个组件::[治理环结构](#governance-loop)
- 每个组件给出最小语义定义、数据格式、trail 集成三样::[组件协议总则](#protocol-general)
- 意图锚定组件承载人类意图的结构化声明::[意图锚定组件](#intent-anchor)
- 符号材料生成是 LLM 的唯一职能，产出待校验材料::[符号材料生成](#symbol-generation)
- 参验以意图为基准对照符号材料，一次穿透::[参验](#crosscheck)
- trail 是不可篡改的留痕物理载体，承接应而不藏::[trail 物理载体](#trail-carrier)

## 治理环结构 {#governance-loop}

最小闭合治理环含四个节点，按因果方向排列。

第一节点是意图锚定。人类意图经结构化声明写入知识包，成为参验的唯一基准。承接道二意图先于代码，因果方向不可逆。

第二节点是符号材料生成。LLM 消费知识包产出符号材料即代码或文档或方案，产出仅作为待校验材料，不直接写入治理对象。

第三节点是参验校验。参验以意图锚定为基准，对照符号材料是否对齐意图，一次穿透同时完成验证与度量。

第四节点是留痕。意图锚定、符号材料生成、参验校验的结果全部经书简写入 trail，留痕不可篡改。

四个节点构成闭合环：意图锚定产生基准，符号材料生成产生待校验材料，参验校验产生偏差记录，偏差记录反馈到意图锚定触发下一轮。承接 PRO-08 应而不藏，留痕是应鉴循环的构成性条件。

## 组件协议总则 {#protocol-general}

每个组件的协议给出三样东西。

第一是最小语义定义。一段话讲清这个组件是什么、做什么、不做什么。最小语义定义须在组件被其他组件引用前给出，不可先用未定义的工程造词搭骨架。

第二是数据格式。含必须字段、可选字段、校验规则。数据格式须满足可验证性约束：来源可追溯、结果可机械校验、历史不可篡改。

第三是与 trail 的集成方式。含哪些操作经书简写入 trail、事件类型、负载结构。trail 集成须承接 GOV-001 失败推导的设计约束。

组件协议的写入权限归确定性程序。LLM 只生成待校验材料，不拥有写入权限。这是根 AGENTS.md 工程基线第一条的落地。

## 意图锚定组件 {#intent-anchor}

最小语义定义。意图锚定组件承载人类意图的结构化声明，是参验的唯一基准。它做什么：接收人类意图，结构化为意图声明，写入知识包。它不做什么：不生成意图，LLM 不可代替人类声明意图。承接 convergence 层 P1.3 意图保真路径与 R8 意图锚定原则。

数据格式。意图声明的必须字段：意图 ID、正向目标即系统应该做什么、负向约束即系统不应该做什么、边界条件即适用范围、理由陈述即为什么这样做。可选字段：关联上游意图 ID、预期变更范围。校验规则：必须字段缺失则拒绝写入，理由陈述不可为空，LLM 不可作为意图持有者。

三维锚定承接 convergence 层 P1.3.1。正向锚定明确描述系统应该做什么，含为什么的理由陈述。负向锚定明确描述系统不应该做什么，对抗 LLM 的过度实现倾向。边界锚定明确描述约束条件，对抗 LLM 将特定方案泛化到不适用场景。

trail 集成。意图声明的写入产生 intent_anchored 事件，经书简写入 trail。事件负载含意图 ID、持有者标识即必须为人类、时间戳、意图声明哈希。意图声明的修订产生 intent_revised 事件，负载含旧意图 ID 与新意图 ID 与修订理由。

## 符号材料生成 {#symbol-generation}

最小语义定义。符号材料生成是 LLM 的唯一职能。它做什么：LLM 消费知识包与意图声明，产出代码或文档或方案作为符号材料。它不做什么：不直接写入治理对象，不拥有写入权限，产出仅作为待校验材料。承接根 AGENTS.md 工程基线第一条与第五条。

数据格式。符号材料的必须字段：材料 ID、关联意图 ID、生成者标识即 LLM 实例、生成时间戳、材料内容哈希。可选字段：消费的知识包条目列表、模型版本。校验规则：关联意图 ID 必须存在且未废弃，材料内容哈希须由确定性程序计算。

符号材料生成不经多 Agent 编排。第一阶段 LLM 只在单会话中生成符号材料。这是 GOV-001 FM-02 的设计约束落地。

trail 集成。符号材料的产出产生 symbol_generated 事件，经书简写入 trail。事件负载含材料 ID、关联意图 ID、生成者标识、时间戳、材料内容哈希。符号材料不直接写入治理对象，只在 trail 留痕后等待参验校验。

## 参验 {#crosscheck}

最小语义定义。参验以意图声明为唯一基准，对照符号材料，参比异同，量度偏离，给出方向。它做什么：接收符号材料与意图声明，执行参比与量度，产出差异事实与偏差记录。它不做什么：不创建新意图，不投射偏好。命名参验承接韩非子显学无参验而必之者愚也，参含参比义验含验证义。参验不取哲学命题硬套，参验非 PRO 命题，命名依据见 DEC-002。

职能两层划分承接 DEC-003。参验内部按鉴与应辨分两层，反映层与处置层。两层哲学归属不同，反映层属鉴的认识动作，处置层属应辨的处置动作。分层依据是 PRO-07 鉴不判断与 PRO-08 应辨处理已抵达挑战的原文职能分工。

反映层。反映层承接 PRO-07 鉴，如实呈现符号材料与意图声明的差异事实。它做什么：对照符号材料与意图声明，呈现材料做了什么与意图要求什么的差异，对每个检查对象产出符合状态的判定。它不做什么：不判断好坏，不量度偏离，不给纠正方向，不投射偏好。反映层产出是差异事实陈述与符合状态判定，符合状态回答一次穿透的验证部分即是否符合，不含好坏判定。符合状态与好坏判定的边界：符合状态是事实呈现即材料是否与意图声明一致，不涉及优劣评价；好坏判定是处置层的分类量度即偏差三维与偏差度量值。承接 PRO-07 原文三条核心约束，鉴只反映事实不判断好坏，判断是法与术的范畴不是鉴的范畴，验证报告只列事实不列应该怎样的建议。

处置层。处置层承接 PRO-08 应辨，对反映层呈现的已抵达偏差做分类量度与纠正方向判定。它做什么：对差异事实做偏差三维分类，计算偏差度量值，给出建议纠正方向。偏差三维承接 convergence 层 P1.2.2，第一维不一致即符号材料与意图声明明确冲突，第二维过度实现即符号材料实现了意图未要求的功能，第三维低度实现即符号材料遗漏了意图明确要求的功能。处置层的偏差即应辨的已抵达挑战，分类量度即辨明识别，纠正方向即处理已发生挑战的处置动作。

一次穿透。参验同时完成验证与度量，以意图陈述为唯一基准。验证回答是否符合，度量记录偏离多少。一次穿透避免分开执行导致的基准不一致。承接 convergence 层差异分析冲突 1 的要求：sih-engine 的验证设计不可只做二元判断，须补一次穿透。一次穿透由反映层与处置层协作完成，反映层产出符合状态判定即验证的回答是否符合，处置层量度偏离即度量的回答偏离多少。

数据格式。差异事实的必须字段：差异 ID、关联材料 ID、关联意图 ID、检查对象、符合状态即符合或不符合、差异位置、呈现时间戳。偏差记录的必须字段：偏差 ID、关联材料 ID、关联意图 ID、偏差类型即不一致或过度实现或低度实现、偏差位置、偏差度量值、校验时间戳。可选字段：建议纠正方向即修代码或修意图。校验规则：偏差度量值须由确定性规则计算，LLM 不可作为度量权威。此约束承接工程基线第一条，确定性程序是治理操作的唯一执行者。符合状态由反映层基于差异事实判定，符合即材料与意图声明一致，不符合即存在差异，不含好坏评价。

trail 集成。参验完成产生 crosscheck_completed 事件，经书简写入 trail。事件类型英文名承接 DEC-002 子决策三修正。事件负载含差异事实与偏差记录或通过记录、关联材料 ID、关联意图 ID、校验规则版本、时间戳。偏差记录反馈到意图锚定组件，触发意图修订或符号材料重新生成。

组件形态判定承接 DEC-003 子决策四。DEC-003 把反映层与处置层是否拆分为两个独立组件委托本设计判定。本设计判定：第一阶段保留单一参验组件，反映层与处置层作为参验内部的两个职能层存在，不拆分为独立组件。判据有三条。第一条，第一阶段的治理环以闭合可验证为目标，参验的反映层与处置层共享同一意图基准与同一符号材料，拆分会引入跨组件的数据传递与状态同步，增加闭合复杂度。第二条，反映层与处置层的哲学归属虽不同，但工程上构成一次穿透的不可分割协作，反映层产出符合状态判定供处置层消费，拆分违背一次穿透避免基准不一致的设计目标。第三条，第二阶段若引入更复杂的处置逻辑或独立的事件类型，可重新评估拆分。此判定为设计推论，非哲学必然。

## trail 物理载体 {#trail-carrier}

trail 是留痕的物理载体，归工程接口层。DEC-001 第 76 行与第 131 行声明 trail 为事件层子节点，语义是治理主体动作的实时伴随留痕。trail 是被操作的内容载体，不是操作组件。

最小语义定义。trail 是不可篡改的留痕载体，承接所有治理操作的记录。它是什么：治理主体动作的实时伴随留痕，以文本流式追加承载，人类可读，不依赖专有工具。它不是什么：不是操作组件，不自带写入与校验与检索能力，这些能力归书简操作组件。

物理存储承接 DEC-001 物理存储最小约束。事件单向写入，状态层从事件层合成，不得反向修改事件层。事件层只能追加写，禁止历史行改写。

数据格式。trail 的每行是一个事件，采用 JSON 序列化的单行文本。必须字段：事件 ID、事件类型、时间戳、操作者标识、负载、关联文档 ID。事件类型覆盖 intent_anchored、intent_revised、symbol_generated、crosscheck_completed 四类。负载结构因事件类型而异，由各组件协议定义。关联文档 ID 标识本事件关联的治理文档，用于跨事件串联同一治理对象的生命周期。字段级细化包含操作者标识的子结构展开与负载的字段命名，详见 SPEC-004。

哈希链。每个事件含前一个事件的哈希，形成不可篡改的哈希链。这是可验证性约束的落地：操作历史不可篡改。承接 convergence 层 P4.2 责任归属的四个可即可追溯与可审计与可反驳与可继承。

trail 不承载仅供人类过滤的预警信号。承接 GOV-001 FM-08 的设计约束：预警若不构成决策依据，归入仅记录事件不进入人类视图。trail 只承载构成决策依据的治理操作事件。

## 书简操作组件 {#shujian-component}

书简是操作 trail 的留痕操作组件，归治理层，承接 DEC-004 命名。书简的职能分第一性核心职能与附属支撑职能。

第一性核心职能是 append-only 持久化写入。书简承接治理主体动作产生的瞬时事件，按固定规范与哈希链结构新增记录写入 trail，绝不修改或删除已有条目。此职能承接 PRO-08 第 114 行留痕是应鉴循环的构成性条件。

附属支撑职能有两项。verify 即校验整条 trail 哈希链完整性，识别篡改与断链。query 即多维度检索历史留痕，用于审计复盘。两项职能依附写入存在，是配套支撑。

校验规则。事件 ID 全局唯一。时间戳单调递增。前事件哈希须与实际前一个事件的哈希一致。操作者标识须为合法的人类或确定性程序标识，LLM 不可作为操作者标识写入治理操作事件。

书简的哲学定位。书简承接 PRO-08 应层的留痕载体职能，不承接应辨与应几的动作职能，不承接鉴的职能。PRO-08 第 178 行至第 184 行确立应不替代鉴的三不原则，书简只负责把治理动作留痕固化，不对留痕做鉴层判断。

代码模块与工具承接。代码模块命名为 scribe，含 scribe append 与 scribe verify 与 scribe query 三个子模块。MCP Tool 从 Scribe 承接命名，旧仓 record_trail 不沿用。具体 Tool 拆分归 DES 层 MCP 协议设计承载。

## 数据流 {#data-flow}

组件间数据流按因果方向定义。

第一步，意图锚定。人类意图经意图锚定组件结构化为意图声明，写入知识包。写入产生 intent_anchored 事件，经书简追加到 trail。

第二步，符号材料生成。LLM 消费知识包与意图声明，产出符号材料。产出产生 symbol_generated 事件，经书简追加到 trail。符号材料不直接写入治理对象，等待参验校验。

第三步，参验校验。参验接收符号材料与意图声明，执行一次穿透校验，产出偏差记录或通过记录。校验完成产生 crosscheck_completed 事件，经书简追加到 trail。

第四步，偏差反馈。偏差记录反馈到意图锚定组件。若偏差类型是不一致或低度实现，纠正方向是修代码即重新生成符号材料。若偏差类型是过度实现且根因是意图不完整，纠正方向是修意图即修订意图声明，产生 intent_revised 事件。

数据流的闭合性。四个步骤构成闭合环：意图产生基准，符号材料产生待校验材料，参验产生偏差记录，偏差反馈触发下一轮。承接 PRO-08 应鉴循环，应触发新认识即偏差反馈，鉴产生新应即意图修订或材料重新生成。

第一阶段不启用视图组件与微积分引擎。视图组件负责信号聚合与异常告警，微积分引擎负责趋势指标产出。这两个组件在第二阶段引入。第一阶段的人类介入方式是直接查看 trail 的 crosscheck_completed 事件的偏差记录，不经过视图聚合。这是第一阶段的简化，第二阶段须按 GOV-001 FM-07 与 FM-10 的设计约束引入视图组件。

## 认识论立场 {#epistemic-stance}

本设计为 design-corollary，是工程设计选择。组件划分与协议设计是工程约定，非哲学必然。组件的哲学对照基础标注在最小语义定义中，区分流衍命题与 convergence 层对照命题。

可证伪条件一：若第一阶段的四组件闭环无法验证可验证性约束即来源可追溯与结果可机械校验与历史不可篡改，则组件协议需重新设计。

可证伪条件二：若实践中发现四组件不足以承载最小闭合治理环，则须扩展组件清单。扩展时多主体协作用于鉴层检验环节保留，用于执行环节禁止。

## 自检 {#self-check}

### 形式合规自检 {#formal-self-check}

- 一级标题无锚点，仅一个
- 二级及以上标题均带锚点
- 首个二级标题命名为概览
- 无破折号、无装饰符号、无 Unicode Emoji
- 全角括号仅用于单一治理编号

### 内容自检 {#content-self-check}

- 四个组件均先给最小语义定义再被数据流引用，无未定义工程造词被引用
- 写入权限归确定性程序，LLM 不可作为操作者标识写入治理操作事件
- 参验补一次穿透，不只做二元判断，承接差异分析冲突 1 要求
- 参验内部按鉴与应辨分两层，反映层产出符合状态判定不判断好坏，处置层承接应辨做分类量度纠正，承接 DEC-003 职能边界判定
- 参验组件形态判定为第一阶段保留单一组件内部分层，承接 DEC-003 子决策四的拆分判定委托
- 参验命名为参验，承接 DEC-002 命名决策，crosscheck_completed 事件类型名经 DEC-002 子决策二修正
- trail 物理载体含哈希链，书简操作组件执行写入与校验与检索，承接可验证性约束的操作历史不可篡改
- 视图组件与微积分引擎标注为第二阶段，第一阶段不启用，避免未定义组件被引用
- 每个组件的哲学对照基础标注来源类型，区分流衍命题与 convergence 层对照命题

### 自反性结论 {#reflexive-conclusion}

本设计定义第一阶段最小闭合治理环。本设计本身经过自我审视，未发现违反 DES-001 格式规范的形态。本设计的组件协议须在实现阶段承接 GOV-001 设计约束，特别是 trail 只承载构成决策依据的事件不承载仅供参考的预警。
