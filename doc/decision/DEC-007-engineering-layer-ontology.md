# 工程层级本体论决策

本决策确立司衡引擎的工程层级本体论，五层分级即引擎、基础设施、组件、模块、单元，两条边界即领域非层与全态非封存态。本决策承接 PRO-005 推荐方案即候选三全量立名，把提案的五层分级定义、层级结构、组件两类形态、层级归属判据落地为正式决策。

层级词此前散落在已立文档与代码中，未走立名决策，层级边界与判据不明。核心断点是单元与组件的名实不符，三问在旧仓定名为三问单元，其定名释义描述的是组件特征，PRO-005 诊断此为立名失败形态。本决策依据 PRO-01 立名本体论立名，名字是本体，名字一旦确立参与构成被命名者，层级名框定该层对象的可能内涵，后续新治理对象的命名须先判定属于哪一层，按层级的名实承诺取名。

## 概览 {#overview}

- 引擎层归属整体身份，承载一切，本仓实例 sih-engine::[引擎层子决策](#decision-engine)
- 基础设施层归属治理运行前提，不承接哲学命题，本仓已确认实例五项::[基础设施层子决策](#decision-infrastructure)
- 组件层归属治理动作网关，承接哲学命题，分直接治理动作与聚合输出两类形态::[组件层子决策](#decision-component)
- 模块层归属组件内部可插拔实现，替换不改变组件接口::[模块层子决策](#decision-module)
- 单元层归属最小功能原子，承接语义节点的本义::[单元层子决策](#decision-unit)
- 领域非层，是多组件联动涌现的治理效果，不是第六层::[领域边界子决策](#decision-domain-non-layer)
- 全态非封存态，是级联闭合后的运行形态，给建造侧提供知止锚点::[全态边界子决策](#decision-full-state)
- 备选方案两条已拒，即维持现状不立名与部分立名只统一单元与组件::[备选方案](#alternative-plan)
- 本决策为设计推论，层级五分是工程约定非哲学承接::[认识论立场](#epistemic-stance)

## 决策集 {#decision-set}

层级归属判据为四条组合判定，即是否承接哲学命题、是否有明确接口、是否可插拔、是否最小原子。基础设施、组件、模块、单元四层由判据组合区分，引擎层是整体身份不进入判据组合。领域与全态不参与层级判定，各立边界子决策承载。

### 子决策一引擎层归属整体身份 {#decision-engine}

决策内容
: 引擎是整体身份层，承载一切，是命名锚点，所有层级与领域都在引擎之内。本仓实例是 sih-engine。

决策理由
: 定义承接 PRO-005 层级定义段，引擎的职能是承载一切，不承接具体治理动作。引擎不进入四条判据组合的判定，任何治理对象先落在引擎之内，再按判据判定归属四层。基础设施在引擎之内，领域在基础设施之上展开，组件含模块、模块含单元，全部以引擎为容器与命名锚点。

关联规则
: 后续文档以引擎指称 sih-engine 整体，不用于指称局部实现。引擎身份不因组件增减而改变，组件级联闭合与否不改动引擎层归属。

### 子决策二基础设施层归属治理运行前提 {#decision-infrastructure}

决策内容
: 基础设施是治理运行前提层，不承接哲学命题，提供组件运行所需的物理与计算基础，组件不感知基础设施的实现差异。本仓已确认实例五项，即 worktree 加 2locks、度量服务、hash 与时间戳、持久化、索引。

决策理由
: 定义承接 PRO-005 层级定义段。归属判据是不承接哲学命题且提供运行前提。工程基线第一条确定性程序是治理操作的唯一执行者落在本层，度量服务即微积分计算器承载偏离率与置信度等确定性数学计算，hash 与时间戳支撑 trail 哈希链与 stable id 派生，索引按标识符确定性定位，都是确定性程序的承载。不承接哲学命题是本层与组件层的分界，提供运行前提是本层的职能。

关联规则
: 待判定子项形态如驱动、中间件、适配器的归类归后续 DEC 承载，本决策不一次闭合。后续新治理对象凡不承接哲学命题且提供运行前提者归本层，基础设施类文档按此归位。

### 子决策三组件层归属治理动作网关 {#decision-component}

决策内容
: 组件是治理动作网关层，有明确接口，承接哲学命题，每个组件承接至少一项哲学命题的工程职能。组件分两类形态，即直接治理动作组件与聚合输出组件，都在组件层展开。本仓实例即参验、书简、三问，参验承接鉴的反映职能，书简承接应的留痕载体职能，三问承接应几的前向约束职能。聚合输出组件以视图为代表，承接 FM-04 人类只在视图告警时介入，是介入点的接口，视图组件单独存在无意义，须联动直接治理动作组件的产出。

决策理由
: 归属判据是承接哲学命题且有明确接口两条组合。对基础设施层，组件承接哲学命题而基础设施不承接。对模块层，模块是组件内部实现，不单独承接哲学命题的工程职能。三问在旧仓定名为三问单元，其定名释义描述的是组件特征，构成 PRO-005 诊断的名实不符，本判据为三问正名提供层级依据，正名决策归 DEC-006 承载。

关联规则
: 后续组件命名决策须声明承接的哲学命题与明确接口，两者缺一者不归组件层。聚合输出组件按联动产出评审，不按单独存在评审。本子决策为 DEC-002 参验命名与 DEC-004 书简命名补层级归属判据。

### 子决策四模块层归属可插拔实现 {#decision-module}

决策内容
: 模块是组件内部可插拔实现层，同一组件可换不同模块，模块替换不改变组件接口，组件不感知实现差异。本仓实例即事件流模块 `src/event_stream`，存储模块可为内存或文件或数据库，组件调用存储模块的抽象接口。

决策理由
: 归属判据是可插拔，替换不改变组件接口者归模块层。外切孵化融回范式的落点在本层，工具在 sih-tools 孵化期治理自治，经可插拔机制融回后以模块形态进引擎治理域，围堰表述据此成立。

关联规则
: 组件设计文档声明模块接口契约，模块实现替换不触发组件命名变更。融回类任务的落点判据是模块形态，融回件以模块归位进引擎治理域。

### 子决策五单元层归属最小功能原子 {#decision-unit}

决策内容
: 单元是模块内部的最小功能原子层，不可再分，是数据与操作的最小粒度。本仓实例即数据单元的单条 trail 记录、单个语义节点、单条规则反例，操作单元的单次参验校验、单次书简写入、单次偏离率计算。

决策理由
: 归属判据是最小原子，不可再分者归单元层。单元回到最小功能原子的本义，承接 PRO-004 的语义节点用法，化解三问单元与语义单元同词不同义的混淆。旧仓以单元命名三问的理由出自旧仓语境，新仓该语境不存在，单元归本义。

关联规则
: 后续文档以单元指称最小功能原子，不用于指称有明确接口的治理动作载体。三问单元措辞的归位随 DEC-006 与 skill 修订承载，本子决策提供层级判据。

### 子决策六领域非层即联动涌现效果 {#decision-domain-non-layer}

决策内容
: 领域不是与五层并列的第六层，是多组件联动涌现的治理效果。单个组件不产出治理效果，效果永远在联动中涌现。视图组件单独存在无意义，须联动书简拿 trail 留痕、联动参验拿文档语义分析结果、联动判定器拿结构性分析结果，聚合后才产出减少人类介入这个治理效果。领域是这类联动效果的抽象总称，不是静态层级。

决策理由
: 领域不满足任何一条层级判据，不承接单一哲学命题，无组件级明确接口，非可插拔实现，非最小原子。层级判定判据作用于治理对象，不作用于涌现效果。若把领域立为第六层，静态层级与联动效果混淆，新治理对象会误归领域层。领域概念随本边界作为指称词登记使用，PRO-005 待定问题二据此了结。

关联规则
: 后续设计文档可引用领域指称联动效果整体，领域不是层级归属选项，新治理对象的层级判定在五层内进行。

### 子决策七全态非封存态即运行形态边界 {#decision-full-state}

决策内容
: 全态是司衡引擎开发完毕且 sih-engine 与其所有组件正常展开级联工作的运行形态，级联涵盖工具调用链，全态即引擎组件级联加工具调用链。全态是领域的运行态补全，即联动闭合后的运行形态本身。全态非封存态，到达全态后损补节律仍在运转，判据再校准、席位基线重测、规则退出与替换照常进行。全态给建造侧提供知止锚点，回答什么叫做完了。

决策理由
: 依据 PRO-005 全态段，概念于 2026-08-19 会话签署。法三知止要求每条规则能回答何时停止生效，全态回答建造侧的同一问题，无完成参照态的建造是治理自增殖的候选样本。运行态定位承法四损补的周期性，校准不是一次性动作是持续性节律，全态指建造完毕与级联闭合，不指系统静止。信息洪流治理是全态的运行效果本身，不是全态里的一个功能。

关联规则
: 主线向界 GOV-002 的渐进逼近全态表述与退出标准承接本边界，级联未闭合前不宣称到达全态。排序统一裁决标准即哪一步让级联更早闭合哪一步先做，以本边界的级联闭合为参照。

## 决策后果 {#decision-consequence}

### 决策正面后果 {#consequence-positive}

- 五层边界一次确立，后续新治理对象命名前先按四条判据判定层级，命名不再随机
- 单元与组件的名实不符获得层级判据支撑，三问正名与语义单元用法各归其位
- 领域与全态两条边界防止层级误判，治理效果不被当作静态层级，建造完毕不被当作系统静止
- 主线锁与已立文档的层级用词获得决策依据，用词与决策对齐，清偿 DEC 欠账

### 决策负面后果 {#consequence-negative}

- 全量立名的工程量大于部分立名，元层决策立名成本一次性付出
- 已有文档中层级词混用处须按本决策归位，存在修订成本
- 基础设施子项完整清单尚待后续 DEC 判定，层内边界暂未全闭合
- 聚合输出组件单独评审时价值不显，须按联动产出理解，存在认知门槛

## 备选方案 {#alternative-plan}

维持现状不立名
: 已拒绝。接受六个层级词混用，不走立名决策。拒绝理由是名实不符会自我放大，PRO-01 立名本体论明确名字与实体错位会导致后续推导沿名字承诺展开，实体沿另一路径演化，两者最终完全脱节，三问叫单元已实际造成与语义单元的概念混淆，不立名则混淆扩散。

部分立名只统一单元与组件
: 已拒绝。只立名三问从单元正名为组件，不立名完整五层分级。拒绝理由是只解单元与组件的混淆，不解组件与模块、模块与单元的边界判据，后续新治理对象仍须判定属于哪一层，无判据则命名随机，部分立名是头痛医头，五层的边界须一次性确立。

## 认识论立场 {#epistemic-stance}

本决策为设计推论（design-corollary），是工程层级结构的选择，非逻辑必然。层级五分与两条边界是工程约定，非哲学承接。哲学仓的流衍链是哲学命题的分级，不是工程实现层级，哲学给的是治理职能分工，不是工程对象粒度。层级立名的依据承接 PRO-01 立名本体论，但层级本身的五分选择是工程决策，哲学仓无对应命题。

可证伪条件一
: 若五层归属判据在实践中无法稳定判定新治理对象的层级，即同一对象按不同判据归入不同层，则五分结构须重新审视，可能须合并或拆分层级。

可证伪条件二
: 若领域作为多组件联动效果的定位在实践中无法与组件层区分，即领域退化为组件层的同义重复，则领域概念须重新审视，可能须取消领域只保留组件层。
