# 参验命名

本决策确立第一阶段验证类组件的工程命名，采用参验作为正式命名。

命名是司衡立名本体论的工程落地，名实相符是命名决策的核心判据。该组件的职能横跨鉴的反映与应的处置，以单一鉴义命名复合职能构成名实不符，映照义因此被排除出命名空间。本决策定参验为正式名，依据是工程命名贴合工程职能，承古典出处而不硬套哲学命题。

## 概览 {#overview}

- 参验是验证类组件的正式工程命名，取古典出处承命名美学，不取哲学命题硬套::[决策集](#decision-set)
- 映照义取自鉴三义之一，与组件职能跨鉴与应的结构性冲突使其被排除出命名空间::[备选方案](#alternative-plan)
- 参验出自韩非子显学，原义即参比验证断言之真伪，与组件职能同构::[命名出处与依据](#source-basis)
- 工程命名遵循贴合职能与承古典出处双原则，不取哲学命题避免越界::[命名原则](#naming-principles)
- 事件类型名从 assay_completed 修正为 crosscheck_completed，消除哲学柱石英文被工程组件冒用::[决策后果](#decision-consequence)
- 备选方案含鉴应组件与校验引擎，均因不同原因被拒绝::[备选方案](#alternative-plan)

## 决策集 {#decision-set}

### 子决策一采用参验作为验证类组件正式命名 {#decision-crosscheck}

决策内容
: 第一阶段验证类组件的正式工程命名为参验。

决策理由
: 命名判据有三条。第一条，工程名贴合工程职能。该组件的职能是以意图声明为基准，对照符号材料，参比异同，量度偏离，给出方向，核心动作是参比与量度。参验的参含参比义，验含验证义，覆盖定偏差与量偏离两项职能。第二条，承古典出处而不硬套哲学命题。参验出自韩非子显学第五十，原句为无参验而必之者愚也，释义为不经过参比验证就断然肯定是愚蠢的。此原义与验证组件的存在理由同构。哲学仓 sih-philosophy 无参验命题，故参验是工程原生命名而非哲学命题的借用，不构成对哲学层的越界。第三条，承司衡命名美学。参验与三问同属古典借名范式，即取古典术语命名工程机制，原义与功能紧耦合，文言双字。

关联规则
: 本命名约束 DES-003 第一阶段组件清单与协议的组件命名。事件类型名的英文对修正见子决策二。

### 子决策二确立参验英文对并修正事件类型名 {#decision-event-name}

决策内容
: 参验的正式英文对确立为 crosscheck。事件类型名从 assay_completed 修正为 crosscheck_completed。修正依据是 assay 是哲学层鉴的权威英文，工程组件不冒用。

决策理由
: 修正依据有两条。

第一条，assay 是哲学层鉴的权威英文。哲学仓 FORMAT 第 91 行确立四柱石权威英文为道是 Tao，法是 Canon，鉴是 Assay，应是 Settle，明令不得用拼音。README 第 33 行与第 114 行的柱石映射表把 Assay 锚定为鉴的权威英文。此英文对经命题级显式决策确立，记载于哲学仓证据链 T2。assay 不是普通英文词，是鉴的哲学权威英文，工程组件冒用哲学柱石英文违反本决策命名原则三，即命名不冒用哲学柱石权威符号。

第二条，crosscheck 贴合参验的古典词源与组件职能。参验出自韩非子显学第五十，原文为无参验而必之者愚也。参含参比交叉义，验含验证义。crosscheck 的 cross 承参的交叉参比义，check 承验的检验义，双字双义与中文参验一一对应。crosscheck 在工程与审计语境是标准术语，贴工程惯例。crosscheck 与四柱石权威英文 Tao、Canon、Assay、Settle、Arche 无碰撞，不冒充哲学承继。crosscheck 的取名排除了两个近义候选。不用 verify，因为 verify 只承验的单一动作，丢失参的交叉参比义。不用 corroborate，因为 corroborate 承用证据支持主张义，与组件以意图为基准找差异的方向相反。

本仓从零开始，无生产数据，改事件类型名不触发历史断裂。

关联规则
: 本决策约束所有引用参验组件的设计文档与规约文档，英文标识从 assay_completed 修正为 crosscheck_completed。修正范围覆盖事件类型名与组件英文对。

## 命名出处与依据 {#source-basis}

参验的出处与依据分三项。

出处。参验出自韩非子显学第五十。原文为无参验而必之者愚也，弗能必而据之者诬也。释义为不经过参比验证就断然肯定是愚蠢的，不能肯定却作为依据是欺诈。此句出自先秦法家经典，是参验一词的最早成词出处。

依据一，原义与职能同构。韩非子原句直接断言不经验证就采信是错的，这一断言与验证组件的存在理由同构。验证组件的存在就是让治理系统避免无参验而必之的错误。参验的参含参比义即以意图为基准参看材料，验含验证义即验证材料是否符合。双字覆盖该组件的定偏差与量偏离两项职能。

依据二，非哲学命题硬套。哲学仓 sih-philosophy 经检索无参验命题。参验是工程层取古典术语命名工程机制，与三问取古典问对传统命名意图拆解机制同属古典借名范式。参验不承自任何 PRO 命题，不构成对哲学层的越界，也不构成哲学命题的工程化伪托。

依据三，承司衡命名美学。参验是文言双字，克制不造作，与三问、司衡、鉴应等同属文言命名体系。参验有经典出处而非临时拼合，区别于参校这类普通词组合。参验作为成词有独立的经典出处支撑其命名重量。

## 命名原则 {#naming-principles}

本决策确立验证类组件命名的三条原则。

原则一，工程名贴合工程职能。命名以工程职能为核心依据，不要求与哲学命题一一对应。哲学层无对应的工程机制，命名取贴合职能的工程词。三问是先例，哲学层无三问命题，三问取古典问对传统命名意图拆解机制，工程名贴合工程职能。

原则二，承古典出处而不硬套哲学命题。命名取古典术语承司衡的文言命名美学，但不取 PRO 命题的术语硬套，避免工程层冒充哲学承继。参验出自韩非子，非 PRO 命题，是古典借名而非哲学硬套。

原则三，命名不冒用哲学柱石权威符号。哲学仓 FORMAT 第 91 行确立四柱石权威英文为 Tao、Canon、Assay、Settle，元层权威英文为 Arche。工程组件的中英命名不得等于这五个柱石权威符号，避免工程层冒充哲学承继。此原则由 assay 冒用 Assay 的名实混淆修正中提炼。

三条原则的边界。原则一确保名实相符，原则二确保命名美学一致，原则三确保哲学符号边界清晰。三条原则共同排除三类错误命名。一类是硬套哲学命题导致的越界，如直接叫鉴或映照。一类是丢弃命名美学的工程俗词，如叫校验引擎或基准校验组件。一类是冒用柱石权威符号导致的名实混淆，如事件类型名等于鉴的权威英文 Assay。

## 决策后果 {#decision-consequence}

### 决策正面后果 {#consequence-positive}

- 组件命名贴合职能，参验的参比验证义直接覆盖定偏差与量偏离，名实相符
- 命名承古典出处，与三问同属古典借名范式，司衡命名美学一致
- 参验非哲学命题硬套，工程层与哲学层边界清晰，不冒充哲学承继
- 映照义被排除出命名空间，鉴三义的去蔽与客观两义的承载去向可由后续设计显式承接

### 决策负面后果 {#consequence-negative}

- 参验一词现代使用频率较低，新读者需查注解理解，存在认知门槛
- 事件类型名从 assay_completed 修正为 crosscheck_completed，DES-003 与 SPEC-003 与 SPEC-004 的引用须同步，存在改动成本

## 备选方案 {#alternative-plan}

鉴应组件
: 已拒绝
: 直接拼接 PRO-07 鉴与 PRO-08 应，显式承认组件跨鉴与应的复合职能。拒绝理由是拼接两命题违背工程名贴工程职能的原则，且暴露组件职能跨哲学命题划分的内部张力，不如以工程原生命名化解。

校验引擎
: 已拒绝
: 贴合工程职能但丢弃文言命名美学，与司衡与三问的命名风格断层。

映照义命名
: 已拒绝
: 诊断分两层。第一层，映照只取鉴三义之一。PRO-07 原文定义鉴含三义，去蔽即去除验证偏见，客观即不预设立场，映照即反映而不投射。三义合一才是鉴。映照义只取第三义，去蔽与客观两义的承载去向未声明。第二层，映照义与组件职能存在结构性冲突。PRO-07 原文明确，鉴只反映事实不判断好坏，判断是法与术的范畴不是鉴的范畴，验证报告只列事实不列应该怎样的建议。DES-003 该组件的实际产出含三类。偏差类型即不一致或过度实现或低度实现，这是判断。偏差度量值，这是评判性的量度。建议纠正方向即修代码或修意图，这是应该怎样的建议。三项产出每一项都越出鉴的反映事实边界。以映照这个本质不评判的词命名本质评判的组件，是结构性名实冲突。结论是映照义的名实冲突不是补声明能弥补的，是命名与职能的结构性对立，映照义据此排除出命名空间。

鉴引擎
: 已拒绝
: 直接取 PRO-07 鉴全义。拒绝理由有二。其一，鉴只反映事实不判断好坏，而组件含判断与量度职能，叫鉴引擎仍名实不符。其二，鉴是 PRO 命题，硬套鉴作为工程名违反承古典出处而不硬套哲学命题的原则。

## 关系图谱 {#relation-graph}

- 本决策约束 DES-003 第一阶段组件清单与协议的组件命名
- 本决策承接 DEC-000 文档格式决策的元原则
- 本决策承接 PRO-07 鉴的映照义定义作为命名空间排除诊断的哲学依据，诊断引用鉴的反映而不投射原则
- 本决策不改动 GOV-001 失败推导的禁止条款与设计约束

## 认识论立场 {#epistemic-stance}

本决策为设计推论（design-corollary），是工程命名选择，非逻辑必然。

可证伪条件一
: 若实践中发现参验一词的认知门槛严重影响团队沟通效率，且替代命名的认知成本更低，则本命名须重新审视。

可证伪条件二
: 若后续设计发现验证类组件须拆分为反映与处置两个独立组件，则参验作为单一组件名须重新审视，可能需按拆分后的各自职能重新命名。

## 自检 {#self-check}

### 形式合规自检 {#formal-self-check}

- 一级标题无锚点，仅一个
- 二级及以上标题均带锚点
- 首个二级标题命名为概览
- 无破折号、无装饰符号、无 Unicode Emoji
- 全角括号仅用于单一治理编号

### 内容自检 {#content-self-check}

- 命名判据以工程职能为核心，不硬套哲学命题，不冒充哲学承继
- 参验出处韩非子显学已核实，非临时拼合的普通词组合
- 映照义的命名空间排除诊断基于 PRO-07 原文，不凭印象判断
- 备选方案的拒绝理由各自独立承载，含鉴应组件、校验引擎、映照义命名、鉴引擎四项
- 事件类型名从 assay_completed 修正为 crosscheck_completed，crosscheck 双字双义与参验一一对应，且消除 assay 冒用鉴的哲学权威英文的名实混淆

### 自反性结论 {#reflexive-conclusion}

本决策确立参验为验证类组件正式命名，以工程职能为命名核心依据，承古典出处而不硬套哲学命题。本决策本身经过自我审视，未发现违反自身命名原则的形态。
