# 文档格式原则

司衡引擎（sih-engine）[^1]规定文档承载内容的元原则：文档只承载人类可读信息，不承载治理元数据。

## 概览 {#overview}

- 文档只承载人类可读信息，治理信息归独立索引::[文档不自包含](#doc-no-include)
- 通用文档格式参考设计文档，本决策不承载具体规范::[通用格式规范引用](#document-format-reference)
- 决策后果分正负两面，正面四项负面两项::[决策后果](#decision-consequence)
- 备选方案拒绝了三种：头部元信息块承载元信息、决策承载通用规范、归入治理流程规约::[备选方案](#alternative-plan)
- 本决策承接司衡哲学治强命题与元层显式承载命题，派生到各类型特异规范::[关系图谱](#relationship-graph)
- 认识论立场：本决策为工程设计选择，附两个可证伪条件::[认识论立场](#epistemic-stance)

### 文档不自包含 {#doc-no-include}

文档只承载人类可读的信息：标题、列表、正文、文本绘图图表。

- 文档身份由其存放路径与文件名共同确定：文件夹定位文档类型，文件名即文档标识（Document ID）。文档身份不内嵌于正文
- 不得包含冗余附属信息：文档身份标识、哲学命题原文嵌入等。文档可引用其他文档，但在引用司衡哲学（sih-philosophy）[^2]时不得把哲学命题原文作为正文承载
- 不得嵌入任意治理元数据。涵盖范围包括状态与级别与签署人与可证伪条件等。治理相关信息统一存放于独立索引，通过文档标题锚点或原子编号建立关联

例外一
: 前提：当纯文本无法清晰承载结构关系时，具体表现为流程与依赖，目录层级等复杂场景，为提升人类视觉理解效率，允许使用文本绘图图表与目录树结构。
: 滥用警告：不得以文本绘图替代本可由列表与标题清晰承载的内容；不得在不具备显著结构收益的场景强行使用；不得因可绘而绘。详细判定标准与边界由通用格式规范承载。

### 通用格式规范引用 {#document-format-reference}

通用格式规范由设计层承载，本决策不重复定义。规范覆盖语法、文档结构骨架、字符约束等。按司衡哲学结构性元规则与类型特异规范，分工如下。

- 本决策承载元原则「文档不承载治理信息」归道层[^3]
- 通用格式规范，其范围是语法、字符与结构骨架，归法层[^3]，由设计层承载
- 各类型特异规范归法层展开，由对应设计规范承载。规范覆盖必选章节、必选元素、自动校验规则。
- 元信息与治理信息分离：元信息由文档身份标识、标题锚点建立关联，治理信息由独立索引管理
- 文档内容优先：文本绘图图表仅在显著提升结构理解效率时使用，避免滥用

## 决策后果 {#decision-consequence}

### 决策正面后果 {#consequence-positive}

- 文档视觉清爽，正文优先
- 治理信息单一来源，由独立索引承载，无冗余
- 状态变更只改索引文件，文档正文不变
- 格式约束可自动化校验

### 决策负面后果 {#decision-negative}

- 文档被移出索引时需通过文件名辨识
- 治理信息依赖索引可用性

## 备选方案 {#alternative-plan}

头部元信息块承载元信息
: 已拒绝
: 元信息以不可见方式嵌入文档头部，传统做法是添加`frontmatter`，违反元层治强[^4]。元信息的存在与变更对正文阅读者不可见，等于绕过鉴层[^3]检验。当前决策：文档不承载元信息，治理信息由独立索引承载，变更可见可审计。

本决策同时承载元原则与通用格式规范
: 已拒绝
: 混淆结构性元规则与实施规范的分工。按司衡哲学结构收敛对照[^5]的双视角论证，元方向与实施规则分属不同视角。元规则约束「是什么」，实施规范约束「怎么做」。两者混装会让元规则的稳定性被实施规范的迭代频率拖累。

通用格式规范归入治理流程规约
: 已拒绝
: 治理流程规约承载治理流程规则，约束的是「治理动作怎么执行」。规则覆盖哲学检验流程与留痕[^6]规约。文档内容规范约束的是「文档本身长什么样」，是产物规范不是流程规范。把产物规范塞进流程规范，会让治理流程规约的适用范围越界，且文档格式变更是高频动作，会触发低频的治理流程审阅，两者力度不匹配。

## 认识论立场 {#epistemic-stance}

本决策的核心规则「文档不自包含」是工程设计选择，认识论标签为：设计推论（design-corollary）。

之前版本曾标注为外部锚定（external-anchor）并声称「源自司衡哲学元层治强命题」，但未指明具体哲学命题编号，论证不足。经审阅降级为设计推论：元原则本身是工程构造，不是哲学命题的直接映射。哲学依据作为支撑，包括治强命题与应层留痕命题，但不构成强归约。

可证伪条件一
: 若在司衡引擎治理领域内，文档承载治理元数据反而提升可审计性，则本元原则失效，需重新审视「不自包含」的边界。司衡治理领域是本原则成立的边界：早期单一决策时文档是自包含的，通过治理展开讨论才决策为不自包含。

可证伪条件二
: 若在司衡引擎工程落地实践中，文档格式元规则与工程实践严重脱节，超出九成文档违反的水平，则需重新评估元原则的合理性。

## 附录 {#appendix}

### 自检 {#self-check}

按元原则「文档不自包含」与元层自反性要求，本文档需自我审视是否违反自身规则。

#### 形式合规自检 {#formal-self-check}

- 一级标题无锚点，仅一个
- 二至四级标题均带锚点
- 首个二级标题命名为「概览」
- 无破折号、无装饰符号、无 Unicode Emoji
- 全角括号仅用于单一治理编号，无论证/举例/补充

#### 内容自检 {#content-self-check}

- 「文档不自包含」:本决策正文不嵌入身份标识、状态、可证伪条件等治理元数据。相关元数据归独立索引与档案。术语表以脚注形式承载定义而非内嵌，符合「不重复元信息」要求
- 「不自包含」原则本身的元层约束:本决策无权单方面宣称符合或不合规，须按可证伪条件由实践证据或反例触发再审视
- 可证伪条件的可证伪性:两个条件分别聚焦「自包含反而提升可审计性」与「元规则与工程实践严重脱节」，覆盖了失效的两类典型场景
- 认识论标签降级记录:L72-74 的降级历史是元原则自检的诚实显示，符合应层留痕

#### 自反性结论 {#reflexive-conclusion}

本文档未发现违反自身元原则的形态。但自检本身具有边界，即形式合规可由 si-doclint 工具校验，内容自检依赖人的二次审视。工具校验通过不代表实质合规，仅代表字符/结构层面合规。

### 术语表 {#glossary}

[^1]: 司衡引擎（sih-engine）：本轮工程代码库，是司衡哲学的首要应用领域。哲学身份司衡（SiHankor）不变，工程产物身份锚定为 sih-engine。

[^2]: 司衡哲学：本工程的唯一权威指导源，承载道法鉴应元各层命题与元层三治。

[^3]: 四柱石分层 + 元层：司衡哲学的五个治理分层。道层确立原则；法层确立方法；鉴层检验与去蔽；应层处理已发生与未形成的扰动；元层治理分三治，即治病、治益、治强，治理司衡哲学的治理命题本身。

[^4]: 治强：元层三治之一，禁止绕过鉴层直接批准。

[^5]: 收敛对照：司衡哲学的双源对照方法论，将哲学推导侧命题与工程实践发现逐项对照检验，分为骨架、结构与决策三类。

[^6]: 应层留痕：应-鉴反馈循环的构成性条件，即应辨/应几的判断、动作、结果必须留痕，涵盖可回溯与可审计，否则反馈循环中断。

[^7]: 元层显式承载：元原则必须显式记录在独立文档，不得隐含。
