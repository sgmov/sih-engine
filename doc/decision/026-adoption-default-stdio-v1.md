# DEC-026 缺省采纳路径决策：单项目 stdio 为缺省档

本决策立司衡引擎 MCP 线的缺省采纳路径：单项目走 stdio 形为缺省档，HTTP 多域与管理台为进阶档，令源即用户 2026-09-17 缺省采纳路径裁定。判词：采纳第一公里决定治理入口成败，首触者尚未获得第一份治理价值，不应先付清后台服务、令牌、多域三件套的运维概念成本；本工作区自用实态即纯 stdio 全治理在役，缺省档与实态同形。载体位序承 DEC-023：Rust 载体 sihmcp 双面在役，stdio 面与 8765 HTTP 面的位序由本档划为缺省与进阶两档，载体能力零裁减。本档随 adoptface 工地批在 worktree 分支 msh/adoptface 落档。

## 概览 {#overview}

- 首触学习曲线不对称：HTTP 档需后台服务与令牌与多域三件套，stdio 档一块配置即通::[背景](#background)
- 缺省档即单项目 stdio 形：单项目即单域即一块配置，零后台服务零端口零令牌::[决策内容](#content)
- 进阶档即 HTTP 多域加管理台：能力保留现役不退役，文档后置非首触路径，两形不可混写::[决策内容](#content)
- sih init 薄壳为 stdio 首触配套位，实施随批另钉，本档只立方向与形约束::[影响面](#impact)
- 依据承注意力稀缺基线与本工作区纯 stdio 自用实证与三件套运维面整体消去::[依据](#reason)
- 备选三案即 HTTP 为缺省与双档并列缺省与 sih init 直出 HTTP 形俱拒绝::[备选方案](#alternative)

## 背景 {#background}

- 学习曲线不对称：HTTP 档首触需一次备齐三件套，即后台服务生命周期含进程拉起、存活、端口换防，令牌签发与管理含 /tokens 管理台签发撤销过期面，多域模型含 bootstrap 域接入全链五段；stdio 档首触只需一块注册配置。
- 成本前置违基线：首触者在获得第一份治理价值前先付清全部运维概念成本，审查注意力消耗在接入仪式而非治理实质，与工程基线第二条注意力稀缺及第三条人类注意力只投向异常信号相违。
- 本工作区实证：首域注册件 `.zcode/config.json` 即 stdio 形，`mcp.servers.sih` 节以 `command` 直指引擎 bin sihmcp、`env.SIH_ROOT` 指工作区根两键成立，无服务无端口无令牌；alpha 九读数具与 beta 十写具全量经此 stdio 面在役。
- 双面能力现状：8765 HTTP 面承载 /mcp streamable 端点与 /tokens 令牌管理台与 / 视图面板，bootstrap 全链五段为多域域接入正典路径，能力现役在案，承 DEC-023 段3 与 DES-015。

## 决策内容 {#content}

缺省档
: 单项目采纳走 stdio 形：单项目即单域即一块配置，`.zcode/config.json` 的 `mcp.servers.sih` 节 `type` 为 stdio、`command` 指引擎 bin、`env.SIH_ROOT` 指工作区根，零后台服务零端口零令牌。缺省档是接入指南与 AGENTS 模板的缺省叙事位，新项目首触文档与 sih init 产物均按此形承载。

进阶档
: HTTP 多域与管理台为进阶档：8765 面 /mcp streamable 加 /tokens 管理台加 / 视图面板加 bootstrap 域接入全链五段，能力保留现役不退役，文档后置。进阶档适用域为多项目集中治理与令牌边界有真实需求的场景，其采纳指南以进阶篇另载，不进入缺省首触路径。

两形不混写
: bootstrap 为新域写入的客户端注册为 HTTP payload 形，见 bootstrap.rs:741 client_entry，载荷为 type http 加 url 加 Authorization Bearer 头加 enabled 加 timeoutMs，与本工作区首域 stdio 形不同形。接入指南与 AGENTS 模板按档分形承载，禁止互抄：首域模板不抄 HTTP payload 形，新域签发形不冒充缺省档叙事。

首触配套
: sih init 薄壳为 stdio 首触配套位：一条命令生成首域 stdio 注册块，落 src/bin/sih.rs 源码位，实施随批另钉。本档只立方向与形约束，薄壳内部实现与可见性面不载于本档。

## 依据 {#reason}

- 注意力稀缺基线：工程基线第二条即信息洪流根因与人类注意力结构性稀缺，第三条即人类注意力只投向异常信号，见 BASELINE-v1.md 基线正文；缺省档把首触介入点压到一块配置，异常面最小。
- 自用实证：本工作区即单项目单域，全治理在役走纯 stdio 形，HTTP 面与管理台在案而不在用；缺省档与实态同形，文档与实态零落差。
- 生命周期消去：stdio 形无端口即无换防与端口攻击面，无令牌即无签发撤销过期管理，无后台服务即无进程存活与重启治理；三件套运维面整体消去而非简化。
- 单域充分：单项目即单域，多域管理需求在缺省场景缺位；bootstrap 多域全链价值集中于多项目集中治理，不构成缺省场景约束。

## 影响面 {#impact}

- 文档叙事两层化：接入指南与 AGENTS 模板按缺省档与进阶档分层，缺省篇前置，进阶篇后置；既有文档叙事按此修订随批承载。
- 管理台保留为进阶：/tokens 管理台与 / 视图面板与令牌签发撤销能力零裁减，bootstrap 全链五段与 client_entry HTTP payload 形现役保留，本档零退役令。
- sih init 为 stdio 首触配套：薄壳产物即缺省档注册块，产物形约束承两形不混写条款。
- 新域签发形差显式化：bootstrap --client-config 为新域写 HTTP 形，与本缺省档 stdio 形并存在档，文档两形并陈时须显式标注形差与适用档。

## 可证伪条件 {#falsifiable}

条件一
: 若单项目缺省场景出现 stdio 档无法承载而 HTTP 档必需的治理能力，且该能力差为实测在案而非文档缺位，则缺省档判定失效，须重裁缺省路径。

条件二
: 若本工作区采纳形态转为多项目多域常态，单项目即单域前提失效，则缺省档适用域收窄，须重裁档位划分。

条件三
: 若 stdio 面出现实证安全事件且其缓解必须引入令牌边界或端口边界，则零令牌零端口依据失效，须重裁两档分界。

## 备选方案 {#alternative}

HTTP 为缺省档
: 已拒绝
: 首触者先付三件套成本后得第一份治理价值，注意力消耗在接入仪式，违工程基线第二三条；本工作区纯 stdio 自用在案即现成反例。

双档并列缺省
: 已拒绝
: 并列即无缺省，首触文档须同载两形，注意力稀释且两形混写事故面放大；缺省的意义即替首触者裁掉选择。

sih init 直出 HTTP 形
: 已拒绝
: 薄壳若按现役 client_entry payload 直写首域，新项目首触即需服务与令牌在位，缺省档名存实亡；首触配套产物形由本档钉为 stdio 形。
