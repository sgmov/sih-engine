# DEC-006 三问组件正式化决策

本决策承接 PRO-003 三问设计方向提案的审议，承载三问组件的正式化七项决策即命名登记、形态裁定、责权拆分、旁路裁撤、组件不合并、LLM 边界、说话口接线。设计与接口归 DES-013 与 SPEC-005 承载，本决策不重复。本决策于 2026-08-22 经用户批准 T6-D 批落地。

## 概览 {#overview}

- 命名五件套登记在案即三问为中文正式名、ask3repeater 为代码标识符、ASK3 为内部代号、展示名保留不用、追问引擎为反向锚点，层级为组件不入名::[命名五件套登记在案](#naming)
- 形态裁定即 PRO-003 候选三通过，从命题推导组件形态，旧仓设计沉默参考::[形态裁定](#form)
- 责权拆分即责在三问锚点必产出与禁熔断、权在书简唯一写入与哈希链::[责权拆分](#duty-split)
- 旁路裁撤与组件不合并即无三机则无旁路、三问与参验时序分离::[旁路裁撤](#no-bypass)
- LLM 边界即不增调用总量只约束推演路径，计量字段与度量方案分落 SPEC 与 DES::[LLM 边界与调用计量](#llm-boundary)
- 说话口接线即 intent-refine skill 升格为手动期正式载体::[说话口接线](#port)

## 决策集 {#decisions}

### 命名五件套登记在案 {#naming}

决策内容：三问组件命名全集登记在案，中文正式名三问，代码标识符小写 ask3repeater，内部代号 ASK3 用于 trail 与日志字段，对外展示名 Ask 上标三 Repeater 保留不用，历史曾用名追问引擎为反向锚点。层级为组件，层级词不入正式名。

决策理由：名实复审会话查证旧仓 DEC-035 完整推导在册即哲学检索五条全中备选四案全拒反推五步全过，2026-07-25 用户签收；本仓承接其中文名实与五件套层次，剔除死语境即三机流水线引用。层级定位承 PRO-005 正名即旧仓称单元的唯一理由是避三机机字，本仓无三机，实际特征即边界自洽生命周期独立闭环完整承接哲学命题为组件特征。层级词不入名承仓例即核阅路择化格书简检词无一携带层级词，书简外切复用书简即先例，且四字违双字美学、层级缀与已死档器缀同罪。

关联规则：约束后续全部文档对三问的命名引用，不得新造别名；代号 ASK3 仅用于 trail 与日志字段；检词术语包收录本词条；措辞传播即活文档存量三问单元归位三问组件，推导记录 PRO-003 与 PRO-005 豁免。

### 形态裁定 {#form}

决策内容：PRO-003 候选三通过即从命题推导组件形态，旧仓四份设计文档为沉默参考只读不引，intent-refine skill 为已验证输入。

决策理由：直接迁移等于把未审查的高速生成材料当权威，违工程基线第二条；纯降级保留 skill 无留痕载体违反 PRO-08 留痕构成性。候选三的推导起点即承接应几为主，哲学检索四条全中。

关联规则：DES-013 与 SPEC-005 的推导顺序受此约束，从命题出发不从旧仓设计出发。

### 责权拆分 {#duty-split}

决策内容：责在三问即每个推演节点必须产出锚点并移交、禁止熔断为刚性约束；权在书简与事件流即唯一写入与哈希链由书简承载，三问不持有写入权限。

决策理由：承 PRO-003 待定问题四的更新裁决基准，旧仓实证即推理锚点子系统实装过且以回放为设计能力；本仓书简已立组件承应的留痕载体职能，写入权集中防多写入口。哲学依据为 PRO-08 留痕构成性与工程基线第一条确定性程序是治理操作唯一执行者。

关联规则：SPEC-005 的记录格式与经书简写入条款受此约束；三问确定性外壳工具将来若外切，其写入仍须经书简。

### 旁路裁撤 {#no-bypass}

决策内容：旧仓旁路机制即预制原子命题绕过三问，不保留。

决策理由：旁路的目标是三机流水线，本仓无三机，目标不存在。承 PRO-003 待定问题三裁决。

关联规则：SPEC-005 不设旁路接口。

### 组件不合并 {#no-merge}

决策内容：三问与参验不合并为一个组件。

决策理由：时序分离即三问在生成前参验在生成后，哲学归属不同即应层与鉴层。承 PRO-003 待定问题五与 PRO-008 应不替代鉴。

关联规则：两组件接口互不内嵌，时序衔接经事件流。

### LLM 边界与调用计量 {#llm-boundary}

决策内容：三问不增加 LLM 调用总量，只约束已有 LLM 调用的推演路径；调用总量计量为调用次数，度量方案入 DES-013，计量字段入 SPEC-005。

决策理由：工程基线第五条治理延伸是减少 LLM 参与而非增加。三问本质是 LLM 使用框架即调用内部的结构化约束。此张力须显式声明并给可证伪度量，承 PRO-003 待定问题二。

关联规则：DES-013 须给出度量方案即调用计数口径；SPEC-005 记录含 calls_in 与 calls_out；若实测调用总量增加，触发本决策可证伪条件二。

### 说话口接线 {#port}

决策内容：三问正式化的调用位为说话口，手动期正式载体为 intent-refine skill 升格，sih 触发协议与其协同，引擎组件落地后 skill 降回辅助。

决策理由：说话口即用户意图进入系统的位置，三问承接应几即在生成前预判微兆，时序吻合。skill 已跨三模型验证有效，升格为正式载体与 pre-output-self-check 承载自检同款模式。承 COURSE-v1 第 3 段方向。

关联规则：intent-refine skill 修订随本批执行；facet 会话模式信号经书简回流三问的方向登记于 DES-013，本批不实装。

## 决策后果 {#consequences}

### 决策正面后果 {#pros}

三问名实归位，五个已签组件名册即三问参验书简判定器视图中第三个获得正式化文档链；层级本体论欠账随 DEC-007 同批清偿；说话口有了明确的治理入口设计；旧仓最有价值的遗产即命名推导与锚点模式经复审激活。

### 决策负面后果 {#cons}

skill 载体与将来引擎组件存在双形态期，降回时点须再裁；LLM 认知组件的验收不如确定性工具可机械判定，有效性依赖可证伪条件一大规模复现的持续观察；调用总量度量引入计数负担。

## 备选方案 {#alternatives}

直接迁移旧仓设计
: 拒绝。旧仓起草时人类已被信息洪流淹没，设计完备性未审查，直接迁移把未审查材料当权威，且三机引用引入死语境污染。承 PRO-003 候选一拒绝理由。

永久降级保留 skill 不立组件
: 拒绝。skill 产出不进事件流无留痕载体，无法回溯核验，违反 PRO-08 留痕构成性，且不承载元层治理防御。承 PRO-003 候选二拒绝理由。

以 ASK3 为英文正名
: 拒绝。ASK3 是五件套第四层内部代号非正名，名实复审纠偏在案；以其为正名则词典无据且形制为仓内孤例。

正式名取三问组件四字
: 拒绝。层级词不入名为仓例，四字违双字美学，层级缀与已死档器缀同罪。

## 认识论立场 {#epistemic-stance}

本决策为 design-corollary 即工程设计承接哲学仓既有命题，不推导新哲学命题。哲学锚为 PRO-08 应几为主、00 自愈不成立、道四间隙不可消除、PRO-01 立名本体论，经 PRO-003 哲学检索四条全中。

可证伪条件一：若三问的向内诘察在大规模治理文档起草场景无法稳定识别意图歧义，即 skill 验证的有效性不复现，则核心职能承接须重新审视。

可证伪条件二：若调用总量实测增加，即违反工程基线第五条，组件形态须重审，可能回退永久降级 skill。

可证伪条件三：若展示名层长期无使用场景，五件套可裁撤该层，裁撤须显式决策留痕。
