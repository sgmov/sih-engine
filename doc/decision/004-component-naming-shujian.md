# 书简命名

本决策确立留痕操作组件的工程命名，采用书简作为正式命名，英文对确立为 Scribe。本决策同时承载留痕物理载体与留痕操作组件的二层关系界定，承接 PRO-002 推荐方案。

命名是司衡立名本体论的工程落地。DEC-001 声明了 trail 物理载体作为事件层子节点的存在，但操作 trail 的组件未立名，混在 DES-003 事件流一节里。PRO-002 诊断此为立名失败形态，推荐拆分两层并独立命名操作组件。本决策据此立名，依据是工程命名贴合工程职能，承古典出处而不硬套哲学命题。

## 概览 {#overview}

- trail 是物理载体节点名归工程接口层，操作组件是治理层命名归本决策::[载体与组件的关系界定](#carrier-component-relation)
- 书简出自左传襄公二十五年太史嗣书实录传统，书即逐条追加写入，简即载体::[命名出处与依据](#source-basis)
- 英文对 Scribe 词源拉丁语 scriba 古代官方记录者，与中文史官叙事同构::[英文对出处与依据](#english-pair-basis)
- 操作组件三项职能含写入与校验与检索，写入是第一性核心职能::[组件职能](#component-function)
- 工程命名遵循贴职能与承古典出处与不冒用柱石权威符号三原则，承接 DEC-002::[命名原则承接](#naming-principles-inherit)
- 备选方案含执简与衡简与循迹与陈迹与事件流保留，均因不同原因被拒绝::[备选方案](#alternative-plan)
- MCP Tool 与代码模块从 Scribe 承接命名，旧仓 record_trail 不沿用::[决策后果](#decision-consequence)

## 载体与组件的关系界定 {#carrier-component-relation}

本决策界定 trail 物理载体与留痕操作组件的二层关系，承接 PRO-002 推荐方案。

trail 是物理载体。DEC-001 第 76 行与第 131 行声明 trail 为事件层子节点，语义是治理主体动作的实时伴随留痕。trail 是被操作的内容载体，命名归工程接口层，词源 trail 即追随踪迹，贴工程语义。trail 的节点名不改，它是治理区的逻辑内容类别，不是操作组件。

留痕操作组件是操作 trail 的主体。组件的三项职能是对 trail 执行写入与校验与检索。组件此前混在 DES-003 事件流一节里，事件流是数据结构描述不是哲学职能描述，组件哲学承接未显式声明，构成 PRO-002 诊断的立名失败形态。本决策为组件独立命名，化解立名失败。

两层的关系。载体是被操作的静态存储介质，组件是操作主体的动态执行者。载体名归工程接口层即 trail，组件名归治理层即书简。两层命名各自归位，互不取代。载体不因组件立名而消失，组件不因载体存在而无名。

## 组件职能 {#component-function}

留痕操作组件的职能分第一性核心职能与附属支撑职能。

第一性核心职能是 append-only 持久化写入。组件承接治理主体动作产生的瞬时事件，按固定规范与哈希链结构新增记录写入 trail，绝不修改或删除已有条目。此职能承接 PRO-08 第 114 行留痕是应鉴循环的构成性条件。组件是痕迹的生产者与固化者，这是不可剥离的本体定位。

附属支撑职能有两项。verify 即校验整条 trail 哈希链完整性，识别篡改与断链。query 即多维度检索历史留痕，用于审计复盘。两项职能依附写入存在，是配套支撑，不是独立核心。

组件的哲学定位。组件承接 PRO-08 应层的留痕载体职能，不承接应辨与应几的动作职能，不承接鉴的职能。PRO-08 第 178 行至第 184 行确立应不替代鉴的三不原则，组件只负责把治理动作留痕固化，不对留痕做鉴层判断。

## 命名出处与依据 {#source-basis}

书简的出处与依据分三项。

出处。书简出自左传襄公二十五年。原文为大史书曰崔杼弑其君，崔子杀之，其弟嗣书而死者二人，其弟又书乃舍之。书在此处作动词即书写记录，简是竹简即记录载体。齐太史兄弟前赴后继以死续写，南史氏执简以往准备接替，是史官实录传统的源头叙事。此叙事的核心是竹简一经书写不可篡改与史官冒死追加与如实记录不隐恶三件事。

依据一，核心动作语义与 append 同构。书即逐条书写追加，直接对应组件的 append-only 写入职能。简即物理载体，对应 trail 文件。书简的书承嗣书与又书的书写动作，简承执简的竹简载体，二字各贴一项工程实体。

依据二，现代汉语意象无歧义。书简的现代汉语直观意象是书写记录与存档，无上朝奏事或追踪旧物的引申歧义。书简的认知割裂风险低于执简，执简的现代意象偏向持简上朝奏事，偏离纯存档职能。

依据三，非哲学命题硬套。哲学仓 sih-philosophy 经检索无书简命题。书简是工程层取古典术语命名工程机制，与参验取韩非子显学命名验证机制同属古典借名范式。书简不承自任何 PRO 命题，不构成对哲学层的越界。

## 英文对出处与依据 {#english-pair-basis}

书简的英文对确立为 Scribe，出处与依据分三项。

词源。Scribe 词源拉丁语 scriba，本义是古代官方记录者与笔录者，即西方史官传统的源头角色。scriba 的职能是逐条记录官方事务，书写即成定稿，与左传齐太史的实录职能同构。

依据一，与中文史官叙事跨语言同构。书简出自左传史官实录传统，Scribe 出自拉丁语 scriba 史官记录传统，中英两线分别从各自语言的史官传统取典，叙事内核是同一个即以记录不可篡改为天职的史官。这是比参验与 crosscheck 更强的中英对称，参验与 crosscheck 是动作同构，书简与 Scribe 是叙事同构。

依据二，操作主体与载体的二分清晰。Scribe 是操作主体即记录者，trail 是被操作物即存储载体，两者语义层级清晰不重叠。不用 Ledger 或 Journal，因为两者本身是存储载体语义，与 trail 重叠，会破坏本决策刚界定的二层关系。

依据三，无柱石权威符号碰撞。Scribe 与四柱石权威英文 Tao、Canon、Assay、Settle 及元层权威英文 Arche 无碰撞，承接 DEC-002 命名原则三即命名不冒用哲学柱石权威符号。

## 命名原则承接 {#naming-principles-inherit}

本决策承接 DEC-002 确立的三条命名原则。

原则一承接，工程名贴合工程职能。书简的书即写入动作，简即载体，双字各贴组件的写入职能与操作对象。Scribe 即记录者，贴组件的操作主体定位。

原则二承接，承古典出处而不硬套哲学命题。书简出自左传，Scribe 出自拉丁语 scriba，均非 PRO 命题，是古典借名与词源借名而非哲学硬套。

原则三承接，命名不冒用柱石权威符号。书简与 Scribe 均不等于 Tao、Canon、Assay、Settle、Arche。

三条原则的判据覆盖。书简满足贴职能与承古典与不冒用柱石符号三项。Scribe 满足贴工程惯例与词源同构与不冒用柱石符号三项。

## 决策集 {#decision-set}

### 子决策一采用书简作为留痕操作组件正式命名 {#decision-shujian}

决策内容
: 留痕操作组件的正式工程命名为书简，英文对为 Scribe。书简取代 DES-003 事件流小节对操作组件的无名状态。

决策理由
: 命名判据有三条。第一条，工程名贴合工程职能，书即写入动作，简即载体，双字各贴工程实体。第二条，承古典出处，书简出自左传襄公二十五年太史嗣书实录传统，原典叙事与 append-only 不可篡改同构。第三条，命名不冒用柱石权威符号，书简与 Scribe 均不等于四柱石与元层权威英文。

关联规则
: 本命名约束 DES-003 事件流小节的修订，修订时事件流小节拆分为 trail 物理载体描述与书简操作组件协议两部分。本命名不改动 DEC-001 的 trail 节点名，trail 是内容载体节点，书简是操作组件。

### 子决策二 trail 物理载体与书简操作组件二层划分 {#decision-two-layer}

决策内容
: trail 是物理载体，归工程接口层命名。书简是操作 trail 的组件，归治理层命名。两层各自归位，互不取代。此划分承接 PRO-002 推荐方案。

决策理由
: 两层混在事件流一个名下是 PRO-002 诊断的立名失败形态。事件流是数据结构描述，不是哲学职能描述，操作组件承接 PRO-08 留痕载体职能未被显式声明。拆分后载体归工程接口层，组件归治理层，哲学承接显式声明，手动构造 trail 行有独立契约参照。

关联规则
: 本决策触发 DES-003 与 SPEC-004 的修订，修订范围是事件流小节拆分为载体描述与组件协议两部分。修订后须重过 sih-doclint 校验。

### 子决策三 MCP Tool 与代码模块从 Scribe 承接命名 {#decision-tool-inherit}

决策内容
: 新仓 MCP Tool 与代码模块从 Scribe 承接命名。代码模块命名为 scribe，含 scribe append 与 scribe verify 与 scribe query 三个子模块。MCP Tool 的具体拆分即单 Tool 或多 Tool 归 DES 层 MCP 协议设计承载，本决策只登记承接方向。

决策理由
: 立名了书简与 Scribe，操作接口若沿用旧仓 record_trail 等以被操作物命名的标识，构成命名与使用脱节，立名白立。参照参验组件事件类型从 assay_completed 修正为 crosscheck_completed 的先例，操作接口须承接组件名而非沿用被操作物名。旧仓 record_trail 是旧仓遗产，新仓从零构建，无历史断裂约束。

关联规则
: 本决策约束新仓 MCP Tool 与代码模块的命名方向。具体 Tool 拆分协议归 DES 承载。trail 物理载体名保留，它是被操作物不是操作接口。

## 决策后果 {#decision-consequence}

### 决策正面后果 {#consequence-positive}

- 留痕操作组件有正式命名，化解 PRO-002 诊断的立名失败形态
- 书简的书即写入，简即载体，双字各贴工程实体，名实相符
- 书简与 Scribe 分别从左传史官传统与拉丁语 scriba 史官传统取典，中英叙事同构
- trail 载体与书简组件二层划分，哲学承接显式声明，手动构造 trail 行有独立契约参照
- MCP Tool 与代码模块从 Scribe 承接，命名与使用一致

### 决策负面后果 {#consequence-negative}

- DES-003 与 SPEC-004 须修订，事件流小节拆分为载体描述与组件协议两部分，存在改动成本
- 书简一词现代使用频率低于事件流，新读者需查注解理解，存在认知门槛
- MCP Tool 从 record_trail 改为 Scribe 承接，新仓虽无生产数据但 AGENTS.md 与文档中对 record_trail 的引用须同步

## 备选方案 {#alternative-plan}

执简
: 已拒绝
: 出自左传襄公二十五年南史氏执简以往，史官原典正向。拒绝理由是执简的现代汉语直观意象偏向持简上朝奏事，偏离纯存档职能，存在认知割裂。且执即持有动作，持有简不等于在简上写入，与 append 写入职能是间接关系。书简的书即书写动作，直接对应 append 写入，同构度优于执简。

衡简
: 已拒绝
: 衡突出哈希链校验 verify 职能，承司衡命名体系。拒绝理由是写入 append 是组件第一性核心职能，衡的校验义弱化写入语义，以附属职能命名核心职能构成主次倒置。书简的书直接承 append 核心职能，校验归附属子模块 scribe verify 承载。

循迹
: 已拒绝
: 字根与旧仓形迹层同源。拒绝理由有三条。其一，循迹是动名复合词，循即顺随追随已存在事物，与组件生迹的本体定位对立。其二，循迹固定词组出自淮南子说山训循迹者非能生迹者也，是道家批判只得形迹不得神髓的贬喻，以贬喻命名生迹组件是本体论级名实对立。其三，组件复用迹字根与形迹层及 trail 三层概念共享语义词根，人工阅读时易混淆产物与介质与生产者的边界。

陈迹
: 已拒绝
: 含迹字根。拒绝理由是陈迹出自庄子天运夫六经先王之陈迹也岂其所以迹哉，是庄子学派对迹的本体论贬低，迹是末用所以迹才是本体。以被贬低的末用命名产生留痕的主体，本体论对立比循迹更深。

事件流保留
: 已拒绝
: 维持现状不拆分不立名。拒绝理由承接 PRO-002 候选一的拒绝理由，事件流是数据结构描述不是哲学职能描述，操作组件哲学承接未显式声明，构成立名失败。

## 认识论立场 {#epistemic-stance}

本决策为设计推论（design-corollary），是工程命名选择与关系界定，非逻辑必然。

可证伪条件一
: 若实践中发现书简一词的认知门槛严重影响团队沟通效率，且替代命名的认知成本更低，则本命名须重新审视。

可证伪条件二
: 若后续设计发现留痕操作组件须拆分为写入与校验与检索三个独立组件，则书简作为单一组件名须重新审视，可能需按拆分后的各自职能重新命名。

## 自检 {#self-check}

### 形式合规自检 {#formal-self-check}

- 一级标题无锚点，仅一个
- 二级及以上标题均带锚点

- 无破折号、无装饰符号、无 Unicode Emoji
- 全角括号仅用于单一治理编号

### 内容自检 {#content-self-check}

- 载体与组件二层关系界定明确，trail 归工程接口层，书简归治理层，互不取代
- 书简出处左传襄公二十五年已核实，书作动词即书写记录，简即竹简载体
- 书简的书即写入动作直接对应 append，同构度优于执简的持有动作
- Scribe 词源拉丁语 scriba 古代官方记录者，与左传史官叙事跨语言同构
- 三条命名原则逐条对照，贴职能与承古典与不冒用柱石符号三项全满足
- 备选方案的拒绝理由各自独立承载，含执简与衡简与循迹与陈迹与事件流保留五项
- MCP Tool 与代码模块从 Scribe 承接，不沿用旧仓 record_trail，命名与使用一致
- 组件哲学承接限于 PRO-08 留痕载体职能，不承接应动作职能与鉴职能

### 自反性结论 {#reflexive-conclusion}

本决策确立书简为留痕操作组件正式命名，英文对为 Scribe，同时界定 trail 物理载体与书简操作组件的二层关系。本决策本身经过自我审视，未发现违反自身命名原则与关系界定的形态。
