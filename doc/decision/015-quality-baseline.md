# DEC-015 质量基线三度量衡决策

本决策成立司衡治理全态的质量基线，由三把度量衡合成即外切贡献度、引擎内贡献度、零信任置信度。承接 2026-08-27 用户裁定即两目的之分与三条质量判据与视图归属令，本决策只立基线不建视图不建计量新件。

## 概览 {#overview}

- 三度量衡即外切贡献度与引擎内贡献度与零信任置信度，合成治理全态质量基线::[度量衡构成](#measures)
- 两目的之分即外切为融回门判据、引擎内为收敛治理有效度计量::[目的之分](#purposes)
- 引擎内贡献度即消耗三资源换质量，三条判据防返工浪费与防丢回滚点与防全量重吃::[引擎内贡献度](#engine-contribution)
- 载体盘点即时间与调用与质量侧在役、账单资源空白、聚合面未建，三条如实登记::[载体盘点](#carriers)
- 视图归属即聚合展示面为后期视图组件内容之一，本决策零视图实装::[视图归属](#view-ownership)

## 度量衡构成 {#measures}

三把度量衡各承其位。外切贡献度即孵化期工具在真实治理工作中的实际作用与产出，形态承 pk-015 既裁即证据全部从留痕取数不另立载体。引擎内贡献度即引擎治理动作的消耗对质量兑换计量，由本决策立定义。零信任置信度即既有零信任机制即 MCP 层信任分与 trust.yaml 持久化凭证与引擎侧身份验正。三者共同构筑质量基线，任何一把单独不构成基线。

## 目的之分 {#purposes}

两把贡献度的目的不同且不可混用。外切贡献度服务于融回门即两重门槛与贡献度主判据，达标由用户裁量，承 DEC-013 与孵化环既裁。引擎内贡献度服务于收敛治理的有效度计量即让 LLM 与 agents 与人类明确知道并理解治理的消耗换取的是更高的质量，是收敛侧的核心机制不是融回侧判据。两账并行不并算。

## 引擎内贡献度 {#engine-contribution}

定义即治理消耗与治理质量的兑换关系账。消耗三资源在案：时间资源即批内耗时，可自链上事件时间戳机械算出；调用资源即确定性件调用次数，meter 在役记账；账单资源即 LLM token 与费用消耗，当前空白仅 redteam 一件记 token，agent 会话级账单零计量，登记为方案占位待另批。

质量三条判据承用户裁定原文：一即不因返工而浪费更多资源，返工账本已天然在档即每批结果档的偏离与修正记录节，偏离数可机械计数；二即不因决策错误回退而找不到具体回滚点，回滚点账本已天然在档即 git 段结算提交加链上认证哈希加内容哈希绑定，回退目标清清楚楚；三即不因状态丢失而全量去吃透项目，由温故组件的检索面与压缩节点规则共同守界即已沉淀物机械在场与净态压缩判定。

三条判据的证据形态均已就位不需要新建载体，质量侧已是留痕的机械可读数，缺的只是聚合与展示即归视图。

## 载体盘点 {#carriers}

- 时间资源：链上事件时间戳在役，批内耗时可机械算，聚合未建
- 调用资源：meter 在役即逐日计数落 ndjson，现役范围限引擎件 scribe 承用户裁定即名随 DEC-017 修订二回滚，扩界待人另裁
- 账单资源：空白即仅 redteam 记 token 用量，agent 会话级账单零计量，方案占位待另批
- 返工账本：结果档偏离与修正记录节在役
- 回滚点账本：git 段结算加链上认证哈希在役
- 状态守界：温故检索面与压缩节点规则在役
- 置信度：零信任信任分与身份验正在役

## 视图归属 {#view-ownership}

三度量衡的聚合展示面属后期视图组件内容之一，承用户 2026-08-27 裁定。视图是聚合输出组件承 DEC-007 即人类介入点的接口，质量基线聚合为其内容事项而非本决策工程面。本决策零视图实装零聚合面建立，视图批另开待令。

## 决策后果 {#consequences}

- 质量基线理念有档可引不再悬于对话
- 引擎内贡献度的载体盘点给出三个后续批占位即账单计量批、meter 扩界裁、视图内容批
- 两把贡献度账目并行不并算即融回评估不读引擎账、收敛计量不读融回账

## 备选方案 {#alternatives}

维持散置不立文
: 已拒。核心理念悬于对话则每会话重述且措辞漂移，返工与回退的风险恰是本机制要防的对象。

三度量合并一账
: 已拒。两目的之分是用户裁定核心即融回判据与收敛计量混账会使两边评估互相污染。

## 关系图谱 {#graph}

本决策上承用户质量基线裁定令与 pk-015 贡献度形态与 DEC-013 融回门贡献度主判据，侧承 DEC-007 视图聚合输出形态与 DEC-010 零信任身份与 SPEC-007 温故检索面，下接账单计量批与 meter 扩界裁与视图内容批三个占位。

## 认识论立场 {#epistemic-stance}

本决策为工程机制决策，哲学锚定标待锚即工程层不创造命题。可证伪条件一即若三度量衡在实践中无法从留痕机械取数即任何一把账算不出来，载体盘点须重审。可证伪条件二即若两目的之分在实践中造成计量死角即某消耗既属外切又属引擎无账可归，两目的之分须重审。
