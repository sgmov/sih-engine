# 三问单元设计方向提案

本提案登记一个待审议的治理方案：从命题出发重新推导三问单元组件的设计方向。本提案不立即实施，登记以待审议。审议通过后，由后续 DEC 承载立名决策，由后续 DES 承载完整设计，由后续 SPEC 承载接口契约。

旧仓曾起草三问单元的设计，含立名决策、完整设计、Tool 接口、持久化格式四份文档，均作沉默参考，不挂旧仓原子 id 与路径，因旧仓文档发布后不可稳定触达。旧仓起草时人类已被信息洪流淹没，不确定设计是否完备，故不直接迁移，须从哲学命题出发重新推导。sihankor-intent-refine skill 的手工模拟经验，是已验证的输入来源。

## 核心问题 {#core-problem}

三问单元（ASK3）的设计方向当前由两条来源同时供给，来源不一致须判定如何承接。

来源一。旧仓曾起草三问单元的设计，含立名决策与完整设计与 Tool 接口与持久化格式四份文档，立名决策含基础命名五件套、定名释义四要点、模块定位三要点、核心职能三要点、刚性约束三要点。此来源的命名部分承接哲学仓 PRO-01 立名本体论，是纯哲学承接，不依赖旧仓工程概念。但模块定位三要点依赖 iCL 明晰机、iWW 消息机、iCT 方圆机三机流水线概念，核心职能依赖三机接口契约，刚性约束依赖旧仓持久化格式文档，这些部分不能直接迁移。

来源二。sihankor-intent-refine skill 是三问单元三层推演职能即 query_surface 析出显层、query_hidden 挖掘隐含、query_atomize 递归细化的手工降级复现，承接应层应几为主应辨为辅，含触发时机四项、提炼三动作、执行约束四项、失败模式四类。该 skill 跨 DeepSeek、MiniMax、GLM 三个模型验证有效，ROI 是 AGENTS.md 措辞修订的 3 到 5 倍，见 sih-engine/sih/state/calibration/agents-revision-effect/CONCLUSION.md。此来源是已验证的工程输入，但只覆盖三层推演职能，不覆盖推理 DAG 持久化、认知域契约、推理锚点这些工程化载体。

两条来源不一致的根因。旧仓设计在三机流水线已立的前提下推导组件定位，本仓无三机流水线，无 iCL/iWW/iCT。本仓当前只有参验组件与书简组件两条已立组件，三问单元是本仓的第三个待立组件。直接迁移旧仓定位会把不存在的前置概念引入本仓，造成 DEC-002 修复过的同类上下文污染。

本提案要解决的具体问题：在本仓无三机的前提下，从命题出发判定三问单元的组件形态、职能边界、与已立组件的关系，为后续 DEC 立名与 DES 设计提供审议基础。

## 承接分类 {#transferable}

旧仓三问单元设计按对本仓的关系分三类。

哲学承接类。基础命名五件套中文名三问单元与定名释义四要点即 Ask 严禁外部问、三层推演、Repeater 机芯意象非通信意象、单元非机。这些名实释义承接哲学仓 PRO-01 立名本体论与 01-ontology-of-names 代号选取规则，承接 C-Cs2 追问引擎命题。哲学检验五条即自愈不成立、应辨应几、留痕构成性、立名本体论、C-Cs2。这些是纯哲学承接，权威源在哲学仓，对本仓构成性约束本来就生效。

工程重新推导类。模块定位三要点的三机流水线引用，核心职能三要点的三机接口契约引用，刚性约束三要点的旧仓持久化格式引用。这些依赖旧仓已立的工程概念，本仓无对应概念，须从命题出发重新推导。

待判定类。刚性约束三要点本身即禁止熔断、认知域契约、推理锚点持久化。这些约束的哲学依据承接 PRO-08 留痕构成性与道四间隙不可消除，本身不依赖三机。但落地形态在本仓无对应持久化格式文档的前提下未定，须重新判定持久化是否必要、以何种形态落地。

## 候选方案 {#candidates}

候选方案一 直接迁移旧仓设计
: 待审议
: 把旧仓三问单元设计全部迁移到本仓，按旧仓设计落地。拒绝理由：旧仓起草时人类已被信息洪流淹没，不确定设计是否完备，直接迁移等于把未审查的设计当权威。且模块定位与核心职能依赖三机概念，本仓无对应。此方案违反工程基线第二条信息洪流是失败根因，把未审查的高速生成材料当治理决策依据。

候选方案二 纯降级保留 skill
: 待审议
: 不立三问单元为正式组件，永久保留 sihankor-intent-refine skill 作为三问单元三层推演职能即 query_surface 析出显层、query_hidden 挖掘隐含、query_atomize 递归细化的对话层手工降级实现。拒绝理由：skill 只覆盖三层推演职能，不覆盖推理 DAG 持久化、认知域契约、推理锚点这些工程化载体。skill 的产出是生成契约不进入事件流，无留痕载体，无法回溯核验，违反 PRO-08 留痕构成性。且 skill 是对话层降级，不承载 PRO-09 元层要求的治理框架防御机制。

候选方案三 从命题推导组件形态
: 待审议
: 抛开旧仓设计，从哲学仓已立命题出发推导本仓三问单元的组件形态、职能边界、与参验与书简的关系。旧仓设计作沉默参考只读不引。skill 手工作为已验证输入。拒绝理由：重新推导的成本高于直接迁移。此代价被评估为可接受，因直接迁移的失败根因是信息洪流，信息洪流是结构性约束不可妥协。方案仍被推荐，但代价真实存在不是零成本。

## 推荐方案 {#recommended}

推荐候选方案三即从命题推导组件形态。

推导起点。三问单元的工程职能是承接应几为主，即在生成前预判微兆。这是哲学仓 08-on-settle 第 13 行应变之未形正在形成的微兆预判介入的工程载体。该职能当前由 skill 手工降级实现，skill 验证有效证明职能本身成立，但 skill 不具备留痕载体与回溯能力，职能成立不等于组件形态可永久降级。

推导边界。三问单元承接应层的应几为主与应辨为辅，不承接鉴的职能即 PRO-08 第 178 行应不替代鉴。三问单元与参验的关系是时序分离，三问单元在前即生成前的意图提炼，参验在后即生成后的相容性核验。三问单元与书简的关系是承接关系，三问单元的产出经书简写入事件流，三问单元本身不持有写入权限。

推导张力。工程基线第五条治理延伸是减少 LLM 参与而非增加。三问单元本质是 LLM 使用框架，是 LLM 调用内部的结构化约束，不是新增 LLM 调用。此张力须显式声明：三问单元不增加 LLM 调用总量，它约束已有 LLM 调用的推演路径。若后续验证发现三问单元实际增加了 LLM 调用总量，则违反基线五，须重新审视。

立名方向。倾向沿用三问单元中文名，因 skill 已承接应几诘察语义且名实一致，且该名承接哲学仓 PRO-01 立名本体论。工程标识符与对外展示名待 DEC 立名承载，本提案不预定。若审议认为立名须连名重立，转 PRO 立名路径。

## 哲学检索 {#philosophy-search}

哲学仓检索结果如下。

PRO-08 应几为主适用于三问单元的核心职能承接。原文 sih-philosophy/emanation/proodos/08-on-settle.md 第 13 行，应变之未形即正在形成的微兆，趋势已显现、风险在酝酿、机会在浮现，数据成熟度低预判介入。三问单元的工程职能是生成前的意图歧义与提示诱导与格式缺失这些尚未抵达但即将导致塌缩的风险预判，直接承接应几。边界约束是 PRO-08 第 178 行应不替代鉴，三问单元只做前向约束不做事后核验。

00 自愈不成立适用于三问单元的向内诘察机制。原文 sih-philosophy/emanation/proodos/00-why-sihankor.md 第 34 行，人工智能不会拒绝自己的生成物也不会因为觉得这不对而停手。三问单元的向内诘察是 AI 主动审视自己推理过程的工程化，直接回应自愈不成立困境。该命题的承接关系在本仓对 PRO-00 与道四与 PRO-08 与 PRO-01 构成性约束本来就生效。

道四间隙不可消除适用于三问单元的职能必要性。原文 sih-philosophy/emanation/proodos/05-on-fourth-tao.md 第 17 行，规约与实现必有间隙，间隙不可消除只能识别记录治理。三问单元在意图到规约的第一次有形化阶段做前向约束，缩小意图进入规约前的间隙。三问单元不消除间隙，只识别与记录意图歧义。

PRO-01 立名本体论适用于三问单元的立名必要性。原文 sih-philosophy/emanation/proodos/01-ontology-of-names.md，名字是本体，名字一旦确立参与构成被命名者。三问单元的名字当前由 skill 承载，skill 是对话层降级无治理地位。若三问单元职能须正式化，须走立名决策路线。立名本体论权威源在哲学仓，对本仓构成性约束本来就生效。

## 待定问题 {#open-questions}

待定问题一。信息洪流内建防护边界。三问单元本身是 LLM 使用框架，起草其完整设计是高速生成材料。如何在设计三问单元时不重蹈信息洪流。倾向：分阶段产出，PRO 先登记方向，DEC 立名，DES 分节承载，不一次性产出完整设计。

待定问题二。LLM 框架与基线五的张力判定。三问单元约束已有 LLM 调用还是增加 LLM 调用总量。倾向：三问单元是约束不增加，但须在 DES 设计时用调用次数度量验证。

待定问题三。旁路机制是否保留。旧仓三问单元模块定位含旁路机制即预制原子命题可绕过三问单元。本仓无三机流水线，旁路的目标不存在。倾向：不保留旁路，因无流水线可绕。

待定问题四。推理 DAG 持久化是否必要。旧仓刚性约束含推理锚点持久化承接留痕构成性。本仓书简组件已承接留痕载体职能。三问单元的推理过程是否须持久化为 DAG，还是经书简写入事件流即可。倾向：经书简写入事件流即可，三问单元不独立持有持久化格式。

待定问题五。组件拆分边界。三问单元与参验是否合并为一个组件。倾向：不合并，因时序分离即三问在前参验在后，且哲学归属不同即应层与鉴层。

## 认识论立场 {#epistemic-stance}

本提案为设计推论（design-corollary），是工程设计方向的登记，非已验证的机制。

组件形态推导为外部锚定（external-anchor），承接 PRO-08 与 00 与道四与 PRO-01 四项哲学命题。立名方向为设计推论，是工程约定。

可证伪条件一
: 若三问单元的向内诘察在实际生成中无法稳定识别意图歧义，即 skill 验证的有效性在大规模治理文档起草场景不复现，则核心职能承接须重新审视。

可证伪条件二
: 若三问单元经 DES 设计后发现实际增加了 LLM 调用总量，即违反工程基线第五条，则组件形态须重新审视，可能须回退到候选方案二即永久降级 skill。
