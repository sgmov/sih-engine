# 多 agent 独立审阅机制实验（2026-08-16）

## 实验目的

验证 PRO-07 鉴层"破自证循环"的**机制独立假设**：多 agent 独立审阅（同一 LLM、不同 prompt/视角/验证）能否达到多 LLM 厂商异质同样的破自证循环效果。

**核心问题**：机制独立于 LLM 厂商数量吗？还是必须多 LLM？

## 实验设计

- **标的**：facet 工具当前状态（5 次 commit 之后）
- **机制**：单 LLM（MiniMax）+ 5 份独立审阅产出
- **独立性维度**：prompt 不同 / 验证路径不同 / 视角框架不同
- **判定**：5 份报告的关键发现是否独立、是否互为补充、是否一致

## 机制独立验证结论

**5 份报告全部独立给出"限定交付"判定**——同 LLM + 不同 prompt 也能破自证循环。

机制独立性的关键证据：
1. **结论一致** = 5/5 都说"限定交付"——不是"五份互相对抗"，是"五份独立收敛"
2. **细节互为补充** = 没有两份报告抓到完全相同的盲区——每份都有独到发现
3. **实测与理论一致** = verifier 写代码跑了 4 个实验，结论与理论分析一致
4. **跨视角不串扰** = 用户派的 agent 与我派的 verifier 独立产出，互不引用

## PRO-07 鉴层最小可执行形态

```
单 LLM + 多独立 prompt + 多视角 + 独立验证 = 破自证循环
```

不需要：
- ❌ 多 LLM 厂商
- ❌ 多 model pool
- ❌ 多 API key

只需要：
- ✅ 独立 prompt（每份不引导结论）
- ✅ 独立视角（每份用不同审视框架）
- ✅ 独立验证（独立跑数据，不照搬前审）

## 对治理工程的工程意义

- **成本降低**：多 LLM 厂商 API 成本 = 单 LLM × N 倍；多 agent = 单 LLM + N 份 prompt
- **可复现性**：单 LLM + 多 prompt 模式可复制到任何场景
- **可验证性**：机制本身可被元层审计（独立视角 = 独立证据）

## 关键警示

机制独立 ≠ 机制完美。本次实验暴露的 11 个真问题（详见 stage2-03-program-signoff-report.md 等）说明：
- **多 agent 独立审阅**破的是**"自证循环"**——但**不**保证抓到所有真问题
- **真正能抓全问题的**是：多 agent 独立审阅 + 跨视角 + 代码实测 + 文档/代码一致性 check
- **元层盲区**（如 A-A3.1 跨家族同源风险）需要哲学层审视，不靠 agent 抓
