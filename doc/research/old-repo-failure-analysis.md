# 旧工程仓失败根因复盘

本复盘基于对旧工程仓 sihankor/ 设计文档的系统性阅读，识别哪些设计决策直接导致了信息洪流，即 LLM 的生成速度与人类审查注意力之间的结构性不对称导致治理失控。

本复盘是沉默参考，不继承旧仓的设计决策，只继承其失败教训。失败教训已提炼为 sih-engine 的工程禁止条款，见根 AGENTS.md § 工程基线与禁止条款。

## 概览 {#overview}

- 旧仓已诊断注意力瓶颈但误诊为产出速度问题，用 LLM 并发加速反而加剧不对称::[误诊：注意力瓶颈当作产出速度问题](#misdiagnosis)
- DES-058 多智能体协作框架是信息洪流的结构性主因，三层均有问题::[DES-058 三层失败](#des058-three-layer)
- 多主体协作作为鉴层检验机制是合法的，失败的是把它错位为治理执行框架::[关键区分](#key-distinction)
- 旧仓已点状否决 LLM 直接生产但未覆盖整体层，被 DES-058 在更高抽象层绕过::[被遗忘的反面证据](#forgotten-evidence)
- 失败模式清单收录 12 条，每条标注设计决策层与对应禁止条款::[失败模式清单](#failure-modes)

## 误诊：注意力瓶颈当作产出速度问题 {#misdiagnosis}

旧仓在 2026-07-21 已正式诊断出注意力瓶颈。证据来自两处。

第一处是 OPEN.md 的最早登记。原文：注意力消耗解决方案:降低人脑与文档之间的意图漂移成本,OPEN.md 登记簿已构造,待审阅验证。这是对注意力问题的最早登记，但解决方案是被动留痕，未上升到结构性不对称。

第二处是 sprint-plan 的正式诊断与误诊。原文 sprint-plan-setsp-reuse-2026-07-21.md 第 27 行：用最短时间形成司衡引擎的初步能力,解除人类决策者注意力瓶颈。这是对注意力瓶颈的正式诊断。但解决方案是第 22 行的 T6 集群并发模式:主会话编排 3 个并行子代理。即用更多 LLM 并行产出来解除瓶颈。

这是范畴层的误诊。注意力瓶颈的根因是 LLM 生成速度与人类审查容量的比例失衡。用更多 LLM 并行产出是增加生成端速度，方向相反。生成端越快，审查端越跟不上，不对称越严重。旧仓把注意力瓶颈当作产出速度问题，应答是加速产出，结果是把瓶颈从单个会话扩散到多个并行子代理。

全仓未出现信息洪流一词。最接近的表述是注意力瓶颈、注意力消耗、上下文负担。诊断停留在工程效率层面，未上升到结构性不对称。

## DES-058 三层失败 {#des058-three-layer}

DES-058 多智能体协作框架是信息洪流的结构性主因。它在三个层面都有问题，按严重度排序。

### 范畴归属层：多 Agent 从检验机制错位为治理执行框架 {#des058-category}

DES-058 第 41 行定义了 NPC 体系的核心定位：司衡不是让多个 LLM 互相聊天,而是让多个 actor 在四柱石加元层加形迹的六范畴骨架上各司其职,经 MCP 工具与鉴应通道协作,由人类签署兜底。

这六个字由人类签署兜底是范畴根因。它把人类定位为整个自动化生产线的末端兜底，而非前置审批者。鉴层被降格为执行框架的内部子步骤，不再是独立的检验关卡。

第 481 行的 P2 目标把全链条自动化明确化：意图陈述由 NPC 自动产生、规约草稿由 NPC 自动起草、代码由 NPC 自动生成、形迹由 NPC 自动审计、异常由应几自动感知、人类只签署元规则变更。全链条自动化，人类被压缩到只剩元规则签署。

按 PRO-07 鉴层命题，多主体协作的真实形态记录是打破自证循环的部分缓解路径。多主体协作是检验机制，用于鉴层。DES-058 把它从检验机制提升为治理执行框架，这是范畴错位。

### 运行时层：L7 与 L9 自动批准 {#des058-runtime}

DES-058 第 167 行：自动化阶段元规则变更可由鉴层 L7 自动批准。第 483 行：生产阶段元规则变更由 L9 闭环鉴自动批准,仍需人类事后审计。

自动批准加事后审计是信息洪流的典型模式。LLM 高速自动批准产生大量事件，人类只能在事后审计堆积的日志。鉴层从检验降格为自动签字器。

第 166 至 168 行的 F-G-J 比例随阶段下滑加剧了这个问题。手动阶段 F 级阻断约 60%，自动化阶段降到 40%，生产阶段降到 25%。J 级即仅记录不干预从 10% 升到 35%。阻断越来越少，仅记录的越来越多，人类要过滤的 J 级事件膨胀。

### 实现方式层：事后审计合法化 {#des058-implementation}

DES-058 第 161 行把注意力当作可调度的资源：A NPC 注意力集中在某子任务时,治益要求 B NPC 接管 A 忽略的元规则检查。这把人类注意力不对称问题转移给 NPC 之间互补，而非解决不对称本身。转移不等于解决，人类端的注意力不对称仍在。

事后审计作为合法治理形态是实现方式的失败。事后审计的前提是人类有足够的注意力去审。在信息洪流下，事后审计退化为橡皮图章或积压。

## 关键区分 {#key-distinction}

本节明确区分两个容易被混淆的概念。如果混淆，禁止条款会误伤合法机制。

多主体协作是鉴层打破自证循环的哲学机制。PRO-07 鉴层原文：自证循环无法从内部打破,只能通过外部锚定和多主体协作的真实形态记录来部分缓解。多主体协作是检验机制，用于鉴层去蔽、客观、映照。它是合法的，不是失败对象。

多 Agent 调用堆叠是用更多 LLM 调用对抗 LLM 不确定性的工程模式。它用于治理决策的执行环节，替代确定性验证。它的产出不可复现、不可审计，加速信息洪流。这是禁止对象。

旧仓 DES-058 的失败不是多主体协作这个机制本身的失败，而是两类错误。第一类是把多主体协作从检验机制错位为治理执行框架，见 § DES-058 三层失败 范畴归属层。第二类是用不可复现的借脑机制即 claim_task 与 submit_reasoning 作为 NPC 协作的核心 Tool，见 DES-058 第 302 至 306 行与第 429 至 433 行。

sih-engine 的禁止条款精确边界是：禁止多 Agent 调用堆叠用于治理决策的执行环节，保留多主体协作用于鉴层检验环节。前者是制造信息洪流，后者是打破自证循环。

## 被遗忘的反面证据 {#forgotten-evidence}

旧仓在多处明确否决了 LLM 直接生产。这些决策与 DES-058 的方向相反，但 DES-058 没有引用它们。

DEC-008 第 23 行否决 synthesize_knowledge 调用 LLM 生成草稿。原文：否决理由是当前手动阶段强调确定性可复现,LLM 生成不可复现。

DEC-009 第 46 行否决 analyze_document 调用 LLM 做语义级意图恢复。原文：LLM 输出不可复现、不可审计,与 SETSP 确定性引擎冲突。

DEC-016 第 46 行否决 index_rebuild 调用 LLM 做语义级索引。原文：LLM 输出不可复现、不可审计,相同输入可能产生不同输出,与索引架构规格的自建轻量索引确定性原则冲突。

这三处否决是旧仓对 LLM 自主生产的点状防御。但它们都针对单个 Tool，即 synthesize 与 analyze 与 index，没有覆盖多 Agent 协作框架这一整体层。DES-058 在更高的抽象层重新引入了 LLM 自主生产，即意图与规约与代码与形迹全链条，绕过了这些点状否决。

这说明旧仓的失败不是缺乏防御决策，而是防御决策未形成体系。点状否决被整体层的重新设计绕过，是结构性盲区。

## 失败模式清单 {#failure-modes}

每条按统一模板：编号、失败描述、证据、设计决策层、预期效果与实际后果、新仓对应禁止条款。

### FM-01 人类签署兜底定位 {#fm01}

DES-058 第 41 行。把人类定位为多 Agent 自动化生产线的末端签署兜底。设计决策层：范畴归属层。预期效果是把人类作为最终防线。实际后果是人类审查速率被 LLM 产出速率压制，签署退化为橡皮图章。新仓对应禁止条款：AGENTS.md 工程基线第一条，确定性程序是治理操作的唯一执行者，LLM 只生成符号材料不拥有写入权限。

### FM-02 全链条自动化 {#fm02}

DES-058 第 481 行。P2 目标设计意图与规约与代码与形迹全链条由 NPC 自动产生。设计决策层：运行时层。预期效果是解放人类。实际后果是 LLM 高速产出，人类签署速率跟不上。新仓对应禁止条款：AGENTS.md 工程基线第五条，治理延伸是减少 LLM 参与而非增加。

### FM-03 L7 自动批准元规则变更 {#fm03}

DES-058 第 167 行。自动化阶段元规则变更可由鉴层 L7 自动批准。设计决策层：范畴归属层与运行时层。预期效果是减少人类负担。实际后果是鉴层从检验降格为自动签字器，绕过人类。新仓对应禁止条款：AGENTS.md 工程禁止条款，禁止 LLM 直接修改知识包或意图锚定。

### FM-04 L9 闭环鉴自动批准加事后审计 {#fm04}

DES-058 第 483 行。生产阶段元规则变更由 L9 闭环鉴自动批准,仍需人类事后审计。设计决策层：实现方式层。预期效果是自动批准加人类事后把关。实际后果是事后审计是信息洪流典型模式，审计堆积。新仓对应禁止条款：AGENTS.md 工程基线第三条，人类只在视图告警时介入不看原始日志。

### FM-05 F-G-J 比例随阶段下滑 {#fm05}

DES-058 第 166 至 168 行。F 级阻断从 60% 降到 25%，J 级仅记录从 10% 升到 35%。设计决策层：实现方式层。预期效果是顺势即阶段越后越宽松。实际后果是阻断越来越少，仅记录的越来越多，人类要过滤的 J 级事件膨胀。新仓对应禁止条款：AGENTS.md 工程基线第三条，人类注意力只投向异常信号。

### FM-06 注意力当作可调度资源 {#fm06}

DES-058 第 161 行。注意力损补让 NPC 之间互补注意力。设计决策层：范畴归属层。预期效果是转移注意力负担。实际后果是转移而非解决，人类端的注意力不对称仍在。新仓对应禁止条款：AGENTS.md 工程基线第二条，信息洪流是结构性约束不可消除。

### FM-07 HumanReview 宽泛触发加最高优先级 {#fm07}

DES-018 第 144 行与第 150 行。所有困难 case 即 MetaLevel 与分类低于 0.60 与证据链冲突与 Actor 权限不足全部归 HumanReview，且 HumanReview 置于最高保护优先级。设计决策层：实现方式层。预期效果是保护核心规约。实际后果是所有最耗注意力的工作被集中堆给人类。新仓对应禁止条款：AGENTS.md 工程基线第三条，确定性程序自动处理绝大多数操作。

### FM-08 应几预警不构成决策依据但仍产生 {#fm08}

DES-018 第 66 行。应几输出模式与预警与风险预测,处置仅供参考。设计决策层：运行时层。预期效果是谨慎标注。实际后果是信号洪流，每条都不构成决策依据但仍需人类过滤。新仓对应禁止条款：AGENTS.md 工程基线第三条，人类只看异常信号。

### FM-09 事后拒绝而非事前审批 {#fm09}

DES-020 第 66 行。写 Tool 必须保留人类拒绝能力与审计记录。设计决策层：实现方式层。预期效果是保留人类否决权。实际后果是事后拒绝而非事前审批，LLM 可持续写人类只能逐条拒绝。新仓对应禁止条款：AGENTS.md 工程基线第一条，LLM 不拥有写入权限。

### FM-10 应几五维度被动信号堆叠 {#fm10}

PRO-010 第 209 行。应几检测不直接阻断治理动作,而是写入应几事件供人类或裁决层处理。设计决策层：运行时层。预期效果是被动观察。实际后果是五类异常信号全部堆给人类。新仓对应禁止条款：AGENTS.md 工程基线第三条，人类只通过视图介入不看原始日志。

### FM-11 用 LLM 并发解除注意力瓶颈 {#fm11}

sprint-plan-setsp-reuse-2026-07-21.md 第 22 行与第 27 行。用 T6 集群并发即 3 个并行子代理解除人类决策者注意力瓶颈。设计决策层：范畴归属层。预期效果是加速交付解除瓶颈。实际后果是把注意力瓶颈当作产出速度问题，用 LLM 并发产出反而加剧不对称。新仓对应禁止条款：AGENTS.md 工程基线第五条，治理延伸是减少 LLM 参与而非增加。

### FM-12 点状否决被整体层绕过 {#fm12}

DEC-008 第 23 行、DEC-009 第 46 行、DEC-016 第 46 行。三处否决 LLM 直接生产，但针对单个 Tool 未覆盖多 Agent 框架整体层。设计决策层：结构性盲区。预期效果是点状防御 LLM 不可复现产出。实际后果是 DES-058 在更高抽象层重新引入 LLM 自主生产，绕过这些点状否决。新仓对应禁止条款：AGENTS.md 工程禁止条款，禁止用 LLM 调用堆叠替代确定性验证，防御须成体系不在单点。

## 失败模式按层面汇总 {#summary-by-layer}

范畴归属层 4 条：FM-01 人类签署兜底定位、FM-03 L7 自动批准、FM-06 注意力当作可调度资源、FM-11 用 LLM 并发解除注意力瓶颈。这一层的失败是根本性的，涉及对治理架构本身的错误定位。

实现方式层 4 条：FM-04 事后审计合法化、FM-05 F-G-J 比例下滑、FM-07 HumanReview 宽泛触发、FM-09 事后拒绝而非事前审批。这一层的失败是正确的范畴定位下选择了错误的工程实现。

运行时层 3 条：FM-02 全链条自动化、FM-08 应几信号不构成决策依据、FM-10 应几五维度被动信号堆叠。这一层的失败是系统运行时产生过多需要人类处理的信号。

结构性盲区 1 条：FM-12 点状否决被整体层绕过。这一条不是某个设计决策的失败，而是防御体系未覆盖整体层的系统性缺陷。

## 范畴排除 {#scope-exclusion}

本复盘不收录以下内容：

- 旧仓的文档格式规范、命名规范等与信息洪流无关的设计决策。这些是旧仓的可复用经验，已在 sih-engine 的 DES-001 文档格式设计中继承。
- 旧仓的 sih-doclint 工具。这是可复用的静态审计工具，sih-engine 暂借其二进制。
- 旧仓的哲学对齐工作。哲学仓 sih-philosophy/ 已独立成仓，承载完整的司衡哲学体系，与旧仓的工程失败无关。
- 旧仓的 proposal 层设计。proposal 层基本干净，无 LLM 拥有 Ratify 权限的设计，自动批准旁路只出现在 DES-058 这一份高层设计文档里。
