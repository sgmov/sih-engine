## 信封 schema {#schema}

信封文件名恒为 envelope.json，UTF-8 无 BOM，单 JSON 对象五字段：

- envelope_version：整数恒 1，非 1 拒包
- id：非空字符串即包名，与所在目录语义一致
- family：枚举四值即 scrutinator 与 attractor 与 formatter 与 nomenclator，族外值拒包
- body_type：枚举两值即 config 与 doc_spec，本批十四包全 config，doc_spec 预留
- bodies：非空字符串数组即族内配置体文件名清单，所列文件必须存在于包目录，缺体拒包

字段多余不拒即前向兼容；字段缺失或类型不合即拒包。

## 正文两型 {#body-types}

配置型即族内谓词与操作与词条等机器消费配置，本批十四包全此型。文档规格型即以规格文档为正文的包形，承 pk-067 两型分立为本枚举预留位，本批零实装。正文格式族内不变即信封层零触碰族内文件内容，字节纪律由迁移对账表逐包承载。

## 校验 {#validation}

校验三规则按序：其一包目录无 envelope.json 即拒包，报文形「envelope missing: <目录路径>」；其二信封字段非法即拒包，报文形「envelope invalid: <目录路径>: <原因>」；其三 bodies 所列配置体缺席即拒包，报文形「envelope body missing: <目录路径>: <文件名>」。校验发生在族加载器读任何配置体之前即先信封后正文。

## 加载器 {#loaders}

六加载器硬切换：工具四族即核阅 packs.py 与路择 pack.py 与化格 packs.py 与检词 pack.py 各自包加载入口先读信封；引擎两族即 attractor route.rs load_pack 运行时目录形与 scrutinator asset.rs 编译期内嵌形各加信封装配与校验。硬切换语义即旧无信封包形不再被接受，缺信封报错为拒绝非降级。双模并存面照各工具 CONTRACT 既有形态即围堰兼容调用位不因信封改变调用形。

## manifest 收编取舍 {#manifest-decision}

设计裁决点即得一与化格与检词既有 manifest 收编为信封正典形或映射改造。本件裁映射改造形：envelope.json 为正典信封，各族 manifest 留族内配置体字节不动并列入 bodies 清单。据实理由三即正文与既有族内元数据字节级零动使迁移风险最小、信封单点正典避免双正典漂移、族内 manifest 继续服务族内既有读形零改动。此取舍无真两难即字节纪律风险单向可比，不另走测量。

## 金向量与双跑 {#golden}

受影响金向量判据即 findings 语义零变：引擎 route 金向量八场景重放逐字节比对，findings 语义零变则零重录，结构断言变即随冻重录；四工具同参双跑逐字节一致读数随批落档。主树裸调为接线验收硬性项。

## 大白话 {#plain}

四个家族的规则包原来是四种格式各说各话，现在统一发一张身份证即 envelope.json，上面写我是谁几岁哪个家族身体里有哪些文件。六个看门人即加载器，改成先查身份证再开门，没身份证或者身份证造假的一律拒收。包里的规则文件即正文，一个字不动，改的只是门卫流程。以后新包先领身份证再上岗。

## 投影件契约 {#projection}

机器可读投影 packs-envelope.json 落批材料：每包一行即族与包位与信封字段与正文类型与校验读数，随批认证上链。
