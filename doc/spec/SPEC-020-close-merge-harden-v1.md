## 失败史 {#failure-history}

sih-tools/lease/ledger/sessions.ndjson 中 close_failed 事件自 2026-08-29 dose01-solo 至 2026-09-04 measure-poly-rev1-progdoc 共 184 件。三类形态：

- **形态 a**：主树本地修改撞合并（"Your local changes would be overwritten by merge"），撞的是 scribe/CALL-LOG.md、PARKING-v1.md、sih-engine/sih/event/trail/*.ndjson
- **形态 b**：主树未跟踪文件撞合并（"untracked working tree files would be overwritten"）
- **形态 c**：工地移除被脏位阻断（"worktree contains modified or untracked files, use --force to delete it"）

三类形态的共同点是：批中主树合法活写（书简认证追加链文件、泊界材料、CALL-LOG 尾行、台账），close 假设批写入只在工地，主树必然脏，merge 拒绝覆盖即死。

## 根因 {#root-cause}

**机制缺陷**：治理架构存在合法的批中主树活写（书简认证追加链文件、泊界材料、CALL-LOG 尾行、台账），而 lease close 假设批的写入只在工地——收约时主树在这些路径上必然脏，merge 拒绝覆盖即死，撤销收场。

**非代理执行病**：根因是机制缺陷，非代理执行病；仅形态 c 含代理卫生成分（工地存在未提交修改或未跟踪文件）。

## 机制设计要求 {#mechanism}

### close 前置机械对表（零 LLM）

**步骤一**：枚举主树脏位（本地修改加未跟踪）中与合并目标路径相交的逐件清单

**步骤二**：脏位内容与分支对应内容逐件 diff——同内容即让位放行（备份后移除/还原再合并）；异内容即纯追加形走让位归并加透出补笔清单（备份保全、可经书简复认证对账），非纯追加形即整批拒并回显事由

**步骤三**：工地卫生检查——工地存在未提交修改或未跟踪文件即拦收约并回显可行动清单（提交归代理责任，工具不代提交）

### 判定语义保守

净态路径的收约语义零变化；只有撞线路径获得新处置。

### 数学锚纪律（mathpipe 口径）

处置策略中改变治理判定的新常数与边界（让位/补笔/拒的三分界）逐件登记——已有载体即挂（ORD-019 版本偏序与外化存储为首选对挂候选），无载体即按 M-3 冻结登记带清账路径，零裸奔入版控。

## 命题层 {#proposition}

**立题立场**：本批的立题是"数学唯一归因 → 机械对表 → 确定性处置"——收约失败归因于机制缺陷（脏位预判缺失），处置策略由机械对表与三态判别（同/追加/异）承载，人不出现在定位链上。

**应用命题映射**：PRO-07 鉴要求检验由可重复程序承载，前置机械对表与三态判别即其应用；A-A3.1 鉴层破自证循环——M-2 失败三态以金向量独立复算证伪实现，不以实现自述替代机械定位；A-A4.1 候选建议生成器——M-3 只产清账或冻结候选，不代立载体；A-A4.2 裁决权归确定性引擎——归因判定由机械复算承载，裁决权不下放给 LLM。

**治理贡献**：本批把收约失败从「碰运气」转为「确定性处置」——对人注意力预算的降维：每批验收只对四条不变量，人类只在边界条件介入、不看原始日志，治理贡献即信息洪流降维与权责归一。
