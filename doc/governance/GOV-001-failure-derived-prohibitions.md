# 失败推导的禁止条款与设计约束

本规约将旧工程仓 sihankor/ 的 12 条失败模式归类为禁止条款与设计约束，标注在新仓 sih-engine 中的落地位置。本规约承接根 AGENTS.md 工程基线与禁止条款，是其细化展开。

失败复盘详见 sih-engine/tmp/old-repo-failure-analysis.md，收录 FM-01 至 FM-12 共 12 条失败模式。本规约不重复复盘，只做归类与落地。

## 概览 {#overview}

- 失败模式按设计决策层归类为三类：范畴归属层、实现方式层、运行时层::[归类总则](#classification-general)
- 范畴归属层失败对应架构决策，是禁止条款::[范畴归属层归类](#category-layer)
- 实现方式层失败对应设计规范，是设计约束::[实现方式层归类](#implementation-layer)
- 运行时层失败对应运行时约束，是设计约束::[运行时层归类](#runtime-layer)
- 结构性盲区对应防御体系要求，是禁止条款::[结构性盲区归类](#blind-spot-layer)

## 归类总则 {#classification-general}

归类维度按设计决策层。不同层的失败对应不同类型的工程产出。

范畴归属层的失败是治理架构本身的错误定位，对应架构决策，产出为禁止条款。禁止条款是硬约束，agent 必须遵守，不可放宽。

实现方式层的失败是正确范畴定位下的错误工程实现，对应设计规范，产出为设计约束。设计约束是软约束，指导工程实现的方向，可在具体设计中调整。

运行时层的失败是系统运行时产生过多需要人类处理的信号，对应运行时约束，产出为设计约束。

结构性盲区是防御体系未覆盖整体层的系统性缺陷，对应防御体系要求，产出为禁止条款。

## 范畴归属层归类 {#category-layer}

本层 4 条失败模式，全部归类为禁止条款。

FM-01 人类签署兜底定位。旧仓 DES-058 第 41 行把人类定位为自动化生产线末端兜底。禁止条款：确定性程序是治理操作的唯一执行者，LLM 只生成符号材料不拥有写入权限。落地位置：根 AGENTS.md 工程基线第一条。

FM-03 L7 自动批准元规则变更。旧仓 DES-058 第 167 行允许鉴层 L7 自动批准。禁止条款：禁止 LLM 直接修改知识包或意图锚定。落地位置：根 AGENTS.md 工程禁止条款。

FM-06 注意力当作可调度资源。旧仓 DES-058 第 161 行把人类注意力转移给 NPC 互补。禁止条款：信息洪流是结构性约束不可消除，治理系统须假设人类注意力是稀缺资源。落地位置：根 AGENTS.md 工程基线第二条。

FM-11 用 LLM 并发解除注意力瓶颈。旧仓 sprint-plan 第 22 行与第 27 行用 T6 集群并发解除瓶颈。禁止条款：治理延伸是减少 LLM 参与而非增加。落地位置：根 AGENTS.md 工程基线第五条。

## 实现方式层归类 {#implementation-layer}

本层 4 条失败模式，全部归类为设计约束。

FM-04 事后审计合法化。旧仓 DES-058 第 483 行把事后审计作为合法治理形态。设计约束：人类只在视图告警时介入，不看原始日志。事件流设计须支持异常信号聚合，不要求人类逐条审计。落地位置：根 AGENTS.md 工程基线第三条，组件协议设计须落实。

FM-05 F-G-J 比例随阶段下滑。旧仓 DES-058 第 166 至 168 行让仅记录的 J 级事件从 10% 升到 35%。设计约束：视图告警的阈值须由确定性规则定义，告警只承载异常信号。事件流设计须区分可消费事件与仅记录事件，仅记录事件不进入人类视图。落地位置：参验组件协议设计。

FM-07 HumanReview 宽泛触发加最高优先级。旧仓 DES-018 第 144 行与第 150 行把所有困难 case 集中堆给人类。设计约束：确定性程序自动处理绝大多数操作，只有确定性程序无法处理的异常才进入人类视图。事件流设计须定义异常判据，异常判据由确定性规则承载。落地位置：参验组件协议设计。

FM-09 事后拒绝而非事前审批。旧仓 DES-020 第 66 行保留人类拒绝能力但是事后。设计约束：写入权限归确定性程序，LLM 产出在写入前须经确定性校验，不依赖人类事后拒绝。落地位置：事件流组件协议设计。

## 运行时层归类 {#runtime-layer}

本层 3 条失败模式，全部归类为设计约束。

FM-02 全链条自动化。旧仓 DES-058 第 481 行设计意图与规约与代码与形迹全链条由 NPC 自动产生。设计约束：第一阶段不引入多 Agent 协同组件。LLM 只在单会话中生成符号材料，不经多 Agent 编排。落地位置：组件清单第一阶段范围。

FM-08 应几预警不构成决策依据但仍产生。旧仓 DES-018 第 66 行产生大量仅供参考的预警。设计约束：视图告警只承载构成决策依据的异常信号，不承载仅供参考的预警。预警若不构成决策依据，归入仅记录事件不进入人类视图。落地位置：视图组件协议设计。

FM-10 应几五维度被动信号堆叠。旧仓 PRO-010 第 209 行把五类异常信号全部写入事件供人类处理。设计约束：异常信号须经聚合后进入人类视图，不逐条堆叠。微积分引擎组件若启用，负责信号聚合与趋势指标产出。落地位置：视图组件协议设计。

## 结构性盲区归类 {#blind-spot-layer}

本层 1 条失败模式，归类为禁止条款。

FM-12 点状否决被整体层绕过。旧仓 DEC-008 第 23 行、DEC-009 第 46 行、DEC-016 第 46 行三处否决 LLM 直接生产，但被 DES-058 在更高抽象层绕过。禁止条款：禁止用 LLM 调用堆叠替代确定性验证。防御须成体系不在单点。任何允许 LLM 参与的环节须在组件协议中显式声明其边界，不可依赖点状否决覆盖整体层。落地位置：根 AGENTS.md 工程禁止条款，组件协议设计须显式声明边界。

## 认识论立场 {#epistemic-stance}

本规约为 design-corollary，是工程设计选择。失败模式的归类维度与禁止条款的力度分级是工程约定，承接旧仓失败复盘的经验归纳。

可证伪条件：若新仓实践中某条设计约束被证明过紧导致工程无法推进，则该约束需重新评估是否放宽。禁止条款不可放宽，除非对应的失败模式在新仓中不再成立。
