# SiHankor Intent Refine

生成实质内容前，把模糊或诱导性的用户意图，提炼为精确的生成契约。

## 定位

本 skill 是三问组件（正式名三问，代码标识符 ask3repeater，内部代号 ASK3）在手动阶段的正式载体，承接其前向约束职能，经 DEC-006 升格裁定，机制语义与三层诘察协议对齐 DES-013，接口与锚点格式对表 SPEC-005。引擎组件落地 src 后本 skill 降回辅助，降回时点另行裁决。命名血统承旧仓 DEC-035 五件套经名实复审登记在案，历史曾用名追问引擎。

哲学承接。承接应层（08-on-settle.md 应而不藏、应辨应几）。应几为主：在生成前预判微兆，即意图歧义、提示诱导、任务特定格式缺失这些尚未抵达但即将导致塌缩的风险。应辨为辅：识别已抵达的意图错位或范畴混淆。本 skill 不承接鉴层——它不做生成后的相容性核验，那是鉴层的事后动作。

实验依据。承接 sih-engine/sih/state/calibration/agents-revision-effect/CONCLUSION.md。三问修正把 user prompt 从模糊状态提炼为精确版，在提案、经验记录、代码生成三类任务上验证有效，跨 DeepSeek、MiniMax、GLM 三个模型方向一致。ROI 是 AGENTS.md 措辞修订的 3 到 5 倍。

## 触发时机

触发。用户意图满足以下任一条件时，先提炼，后产出：

- 意图模糊。用户表达宽泛（如"帮我审一下"），未明确审什么、用什么标准、产出什么形态
- 提示诱导。用户的措辞预设了答案方向，可能把生成导向单极塌缩
- 任务特定精度未显。用户未说明该任务类型的产出格式或约束（提案需候选与拒绝、经验记录需结构、代码需可编译含测试）
- 治理动作。用户请求起草、修订、命名、决策类治理产出

不触发。事实陈述、确认理解、单步工具调用、纯检索查询。

## 提炼动作

提炼是三个动作，一次完成，不机械分三轮：

一，析出显层诉求。用户字面要什么。一句话复述，不展开。

二，挖掘隐含前提与歧义。显层诉求背后有哪些未言明的假设、哪些分支歧义、哪些范畴边界。特别识别：

- 提示诱导。用户措辞是否预设了答案
- 范畴混淆。是否把不同层面的概念混在一起
- 配对极缺失。是否只取了一极，丢了配对极（如只说不做什么，没说因此要做什么）
- 任务格式缺失。该任务类型的产出格式约束是否未声明

三，生成精确契约。把提炼结果固化为生成契约，含：

- 意图边界。做什么，不做什么，显式声明排除项
- 任务格式。该任务的产出形态约束
- 约束注入。相关的哲学命题约束（从 AGENTS.md 与哲学仓已立命题出发）
- 令源约束。决策档规范级条款须令源引用，凡公式、惯例、既裁、已立类规范表述的生成契约必注入令源核验约束即条款须显式引用已签令或链上意图事件，无令源即降格为待签表述，2026-08-28 用户裁定入列
- 命名查档约束。工程命名动作即立名、改名、英文对推导与双签落档，生成契约必注入命名前查档约束即动作前查检词登记 terms 与 dead 与 candidates 及本仓与旧仓立名档，命中既有英文对或五件套即阻断并呈报既有条目，零命中方进推导，2026-08-28 用户裁定入列

契约生成后，与用户确认或直接进入产出，视契约复杂度与歧义程度而定。歧义度高时先确认，歧义度低时直接产出并在产出顶部标注契约。

## 执行约束

禁止向外部人类提问。三问的 Ask 是向内诘察，是 AI 自己审视自己的推理过程，不是向用户发问。本 skill 的产出是生成契约，不是问题清单。挖掘歧义是 AI 内部的认知动作，产出的是已收窄的契约，不是把歧义抛回给用户。

唯一例外：当歧义涉及用户的核心意图且无法从上下文推断时，可以提一个确认问题，但必须附上 AI 自己的倾向判断，不能空问。

禁止堆叠。提炼的产出是一份精确契约，不是检查清单的叠加。契约的每一行都必须有生成约束力，去掉它会让产出犯错。堆叠检查项是旧仓信息洪流失败模式的复现。

不替代自检。本 skill 是生成前的前向约束，sihankor-pre-output-self-check 是生成后的自检。两者时序不同，职能不同，不替代。

## 与 AGENTS.md 的分工

AGENTS.md 是每次会话加载的构成性约束，管基础约束四维（constraint、active_gen、passive_ref、philosophy_correct），长期生效，与任务无关。

本 skill 是每次产出前的意图提炼，管任务特定精度（候选方案、五段结构、可编译代码等），按任务类型变化。

两者互补不替代。AGENTS.md 修订已落地不需过度优化，本 skill 每次执行。

## 失败模式

模式一，空问。把提炼产出做成问题清单抛回用户。守护：产出是契约不是问题，唯一例外必须附倾向判断。

模式二，堆叠。把契约做成检查项叠加。守护：每行去掉会犯错吗，承接自检第 5 项。

模式三，越界鉴层。提炼中夹带生成后的相容性核验。守护：本 skill 只管前向约束，鉴层是事后动作。

模式四，单极塌缩。提炼中只取用户措辞的一极。守护：配对极核验，用户只说一极时主动补配对极。

## 全流程五步

手动期正式载体的完整调用不止于产出契约，五步钉死：

一，诘察产契约即提炼动作。治理批即起草、修订、命名、决策类产出必触发，不得跳过，跳过即违本 skill。

二，检索加载即温故 recall 机械在场。落锚前按批主题词跑检索面取命题先例，调用即 cd sih-engine 后 target/debug/retriever recall --topic <批主题词> --archive conclusion --archive experience --archive intent --at <实日> --out <输出件路径>，输出件随 ask3 材料入档，锚定理据须对其中先例取材或如实记零命中，检索缺席即违本 skill。承 SPEC-007 消费侧一与 wenguwire-solo 批，宿主命令名 retriever 即检词查证 memgate 死档旧名禁复用。检索后即叩问 check 出信号件：cd sih-tools/elicit 后 uv run --project . elicit check --packs ../nomenclator/packs/core --words <草稿新词逐个> --topics <批主题词> --recall-face <召回面件> --out <信号件> --at <实日>，信号件随批材料入档。

三，落记录即照 SPEC-005 产输出记录。锚点行号先 grep 核验后落记录，血统三件套即哲学引文、理据、证据行号逐条齐备，禁熔断即低置信锚点保留。

四，机械验收即核阅 ask3 包过记录，调用即 cd sih-tools/scrutinator 后 uv run python -m scrutinator --pack packs/ask3 <记录.json>，退出码非零即修记录重验，校验失败不入流。核阅过闸后即叩问 digest 消化闸：cd sih-tools/elicit 后 uv run --project . elicit digest --signals <信号件> --contract <记录件>，退出码一即契约未消化信号、补叩问处置标记或声明升级追问后重验，过闸方可入流；零信号即零处置直过。

五，上链即书简 intent 子命令写 intent_refined 事件，调用即 cd sih-engine 后 target/debug/scribe intent --record <记录.json> --validation <验收报告.json> --trail sih-engine/sih/event/trail/<日期>.ndjson --locks sih-tools/lease/ledger/locks.ndjson，doc_id 用会话标识，引擎现役形即旧工具侧调用已于 2026-08-27 退役。

## 叩问升级位

三问在前即自审为正位，叩问为自审合不拢时的人工介入升级位，时序承用户 2026-08-29 裁定。升级扳机三件全机械产出、不由自审自信拍板：一未登记词即输入或契约携带检词登记面之外的新词，二召回矛盾即温故归档面零命中或命中与请求相抵，三裁定冲突即当前请求与在档历史裁定相抵。扳机由检索加载步与检词查档机械产出并随契约材料在场。消化义务即契约必须逐信号处置：解释清楚即声明消解，或声明升级追问并把问题列明交人作答；信号未消化而契约过闸即闸失守，机械验收步查此条。叩问轮次纪律即编号全问、等答、答案落人类输入日志、答后重炼契约。人机无高下之分即升级是合作接口不是降级处置。
