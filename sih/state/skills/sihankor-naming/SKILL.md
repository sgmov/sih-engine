# Skill: sihankor-naming（立名）

司衡立名流程的调用入口：本质段材料制备、纪律加载后的推导核验、人类裁决登记三段。本 skill 只机械化收账与核验，不裁决名。权威源是哲学仓立名本体论与已立体例原理；血统档当前暂承分支会话记录，命名登记 DEC 落盘后改指 DEC。skill 文件不受 scrutinator 治理域约束。

## 触发时机

- 用户要整理某实体的本质、职责、边界，无论是否已到立名
- 用户要为实体立名、改名、复审名实关系
- 分支立名会话开始，或任何新词将进入登记之前

不触发：临时描述用语，未到登记点，走懒波。

## 第一段：本质段，材料制备，可多 agent 协作

1. 整理四件东西：一句话定义；职责，含不变职责与可变扩展；
   边界，不做什么逐条显式；适用域，开放则写原则不写清单。
2. 附认识论状态：哪些已裁、哪些待裁、可证伪点各一。
3. 产出自包含评审稿，不依赖会话上下文，可交其他 agent 协作或评审。
4. 本段不产候选，不携命名判断。
5. 协作红线：多 agent 协作限于材料制备与评审；
   治理决策依据须可复现，裁决人签。

## 第二段：推导段，命名会话，纪律加载后进行

1. 收账加载：sih-philosophy/emanation/proodos/01-ontology-of-names.md，
   含立名本体论、血统判定（新建、保留档、改述、废弃）、or 语素第 256 行；
   已立体例，英文正名、双名并行、造词复活用 or 承接而借词原形豁免；
   已立原理，立名防漂移不防债、命名承诺不被撤回；
   血统档，死名与死因，翻案须显式推翻原死因。
2. 名前钉实复查：第一段材料为输入。位阶上职责边界先于名，顺序不可反。
3. 候选不超过三，各带推导与风险。反候选死因一并入档。
4. 词义核验三层不混层：词典义项、行业用例、词源。
   义项可引为义，行业例证只为例证。
5. 碰撞核验三层：全仓 grep 零占用；屋内词汇，词根是否仓内活词、何义；
   外部生态，标准 API 与既有工具名。
6. 裸名测试：词条不在场的场合（命令行、trail 行、提交信息），
   名不带错向。零先验优于带错先验。
7. 钉义不对称原则：钉义只能削噪声，不能补缺口，
   缺口的词义永远由词条背。

## 第三段：裁决与登记，人类权威

1. agent 出材料不出裁决，每名逐裁，禁止批量签。
2. 人签才立，签署前一切材料零持久化。
3. 立名完成后：登记词条、更新血统档、列连带改写清单。
4. 派生纪律：名下不自动派生词族，新词按懒波登记。

## 边界

本 skill 不裁决名，只制备与核验材料。
权威链：哲学仓立名本体论，已立体例与原理（登记 DEC），
本 skill 居末。skill 文件不受 scrutinator 治理域约束。
