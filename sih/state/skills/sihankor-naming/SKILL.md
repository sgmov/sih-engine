# Skill: sihankor-naming（立名）

司衡立名流程的调用入口：本质段材料制备、纪律加载后的推导核验、人类裁决登记三段。本 skill 只机械化收账与核验，不裁决名。权威源是哲学仓立名本体论与已立体例原理；血统档当前暂承分支会话记录，命名登记 DEC 落盘后改指 DEC。skill 文件不受 scrutinator 治理域约束。

## 触发时机

- 用户要整理某实体的本质、职责、边界，无论是否已到立名
- 用户要为实体立名、改名、名实关系复审
- 分支立名会话开始，或任何新词将进入登记之前

不触发：临时描述用语，未到登记点，走懒波。

## 第一段：本质段，材料制备，可多 agent 协作

1. 整理四件东西：一句话定义；职责，含不变职责与可变扩展；
   边界，不做什么逐条显式；适用域，开放则写原则不写清单。
2. 附认识论状态：哪些已裁、哪些待裁、可证伪点各一。
3. 产出自包含评审稿，不依赖会话上下文，可交其他 agent 协作或评审。
4. 本段不产候选，不携命名判断。
5. 协作红线：多 agent 协作限于材料制备与评审；
   治理决策依据须可复现，裁决人签。

## 第二段：推导段，命名会话，纪律加载后进行

1. 收账加载：sih-philosophy/emanation/proodos/01-ontology-of-names.md，
   含立名本体论、血统判定（新建、保留档、改述、废弃）、or 语素第 256 行；
   已立体例，英文正名、双名并行、造词复活用 or 承接而借词原形豁免；
   已立原理，立名防漂移不防债、命名承诺不被撤回；
   血统档，死名与死因，翻案须显式推翻原死因。
2. 命名前查档：查检词登记即 terms 与 dead 与 candidates 三件，
   查本仓与旧仓立名档即 DEC-017 与 DEC-035；对象已有英文对或
   五件套即呈报既有条目阻断重推，零命中方进候选。
   承用户 2026-08-28 立令即工程命名动作前查命名集与检词。
3. 名前钉实复查：第一段材料为输入。位阶上职责边界先于名，顺序不可反。
4. 候选不超过三，各带推导与风险。反候选死因一并入档。
5. 词义核验三层不混层：词典义项、行业用例、词源。
   义项可引为义，行业例证只为例证。
6. 碰撞核验三层：全仓 grep 零占用；屋内词汇，词根是否仓内活词、何义；
   外部生态，标准 API 与既有工具名。
7. 裸名测试：词条不在场的场合（命令行、trail 行、提交信息），
   名不带错向。零先验优于带错先验。
8. 钉义不对称原则：钉义只能削噪声，不能补缺口，
   缺口的词义永远由词条背。
9. 反推约束交集：先于候选定稿，枚举名的署名位（命令行、trail 行、
   报告名、commit、席位行、分工句、收敛句、重放句）逐位提取硬约束
   成句，交集过滤候选；正向推导与反推交集会师为过，分叉即如实呈报
   不隐。承执契立名反推唯一解实战。
10. 覆盖面审计：从本质段列实体语义面清单，候选逐面建覆盖矩阵；
    组件名对工具辖区面的让渡是正确空缺非缺失；定义面不满格即名不
    称职。承组件立名七面矩阵实战。
11. 层级复活与词场：工具层死因不当然延伸组件层，层级升位后原死因
    可被本质推翻，翻案须显式推翻原死因并留痕；候选被仓内高频活词
    义淹没（词场淹没）即出列入反候选死因档。承鉴裁翻案与归一出列
    实战。

## 第三段：裁决与登记，收敛即立，人武装与异常

1. agent 出材料不出裁决，每名逐裁，禁止批量签。
2. 机器签署即为人授权（硬件钥匙模型，用户 2026-08-30 裁定承 DEC-020）：名实相副经 facet 测量 stable_clear 且执契核对裁决通过者，机器落据即名立，签署前评审稿可持久化而名不预立；未收敛或核对未过仍归人。原「人签才立」条款显式接替留痕不抹；agent 一字不签不变（P3）。
3. 立名完成后：登记词条、更新血统档、列连带改写清单。
4. 派生纪律：名下不自动派生词族，新词按懒波登记。
