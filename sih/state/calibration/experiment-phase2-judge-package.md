# 语义验证实验 阶段二 语义判断检查项判断任务包

你是语义验证实验阶段二的判断执行者。本任务包是自包含协议，你按协议对预先提取的检查对象执行语义判断，产出结构化判断记录。你的产出是实验数据，不是治理决策。

本任务包与阶段一的区别。阶段一的 4 项检查是结构查询即文件存在性、标签匹配、句式检测、术语查表，判据接近确定性。本任务包的 3 项检查是语义理解，需要你读懂文档内容、理解论证逻辑、判断语义对应，判据依赖语义推理而非机械匹配。

本任务包采用隔离 session 采样。你在 1 个隔离 session 里只跑 1 个采样序号。你不做抽取，检查对象由预先提取的清单提供。你只做判断。

## 概览 {#overview}

- 你在 1 个隔离 session 里对预提取的检查对象执行 3 项语义检查各 1 次::[任务目标](#task-goal)
- 3 项检查是承接语义对应性、论证自洽性、归位充分性::[检查项定义](#check-items)
- 检查对象来自清单文件，清单含已打包的上游文档概览节::[输入清单](#checklist-input)
- 每条判断按 JSON 单行格式输出，含 6 个必须字段::[判断格式约束](#judgment-format)
- 你不引导判断，不确定是合法结果::[中立性要求](#neutrality)

## 任务目标 {#task-goal}

对 1 份文档的预先提取检查对象执行 3 项语义检查各 1 次。你的采样序号在启动时指定，你只产出这一序号的判断记录。

## 输入清单 {#checklist-input}

你不自行提取检查对象。检查对象由清单文件提供，路径在启动时指定。清单是 JSON 文件，含 3 个数组，每个数组对应 1 项检查的检查对象。

承接语义对应性的检查对象含三个字段。target 是工程编号即被引用的上游文档编号。claim 是本文档中引用该编号时的承接声明即引用上下文。upstream_overview 是上游文档的概览节全文。

论证自洽性的检查对象含两个字段。target 是文档自身。core_claim 是从文档概览节提取的核心主张。不需要外部文档。

归位充分性的检查对象含两个字段。target 是文档自身。claimed_type 是文档声明的类型。文档类型的定义来自 DEC-001 即 design 描述怎么做，decision 描述为什么这么决定，spec 描述怎么验收，proposal 描述建议做什么，governance 描述治理规则，knowledge 描述已验证的知识。

你读取清单，对每个数组里的每个对象执行对应检查项的判断。

## 检查项定义 {#check-items}

### 检查项一 承接语义对应性 {#check-one}

检查问题：本文档的承接声明，与上游文档概览节所表达的核心论点，是否语义对应。

判断方法。你阅读清单中提供的承接声明即 claim 字段，理解它声称从上游文档承接了什么。你阅读上游文档概览节即 upstream_overview 字段，理解上游文档实际表达的核心论点。你判断两者是否语义对应。

语义对应的判据。承接声明与上游文档概览节的语义关系有四种状态。

对应：承接声明准确反映了上游文档概览节的核心论点。上游文档确实表达了承接声明所声称的内容。

过度承接：承接声明声称从上游文档获得了超出概览节实际表达的支持。上游文档概览节的核心论点比承接声明声称的要窄或要弱。

不对应：承接声明声称的内容与上游文档概览节的核心论点矛盾，或上游文档概览节完全没有涉及承接声明声称的内容。

不确定：上游文档概览节信息不足以判断是否对应。例如概览节过于笼统，或承接声明指向的是概览节未覆盖的具体细节。

每条承接关系的判断格式：输出对应或过度承接或不对应或不确定，附一句话理由。理由不超过 50 字，须指出判断依据即概览节的哪个论点与承接声明对比。

对应：承接声明准确反映上游文档概览节的核心论点。
过度承接：承接声明声称的支撑范围超出概览节实际表达。
不对应：承接声明声称的内容与概览节核心论点矛盾或无关。
不确定：概览节信息不足以判断。

### 检查项二 论证自洽性 {#check-two}

检查问题：本文档的核心主张与文档自身的论证步骤，是否逻辑一致。

判断方法。你阅读清单中提供的核心主张即 core_claim 字段。你阅读文档全文，识别支撑该核心主张的论证步骤。你判断核心主张与论证步骤之间是否存在逻辑矛盾或断裂。

自洽性的判据。核心主张与论证的关系有四种状态。

自洽：核心主张与文档的论证步骤逻辑一致。论证步骤为核心主张提供了有效支撑，无矛盾或断裂。

部分自洽：核心主张的主要部分有论证支撑，但存在局部断裂。断裂指某个论证步骤缺失，或某个支撑关系不够严密，但不影响整体结论的方向。

不自洽：核心主张与论证步骤存在实质矛盾。论证步骤不支持核心主张，或论证步骤之间互相矛盾。

不确定：文档的论证结构过于复杂或模糊，无法判断核心主张与论证的关系。

本检查项的局限标注。论证自洽性没有唯一正确答案。不同人可能对同一份文档的自洽性有不同判断。本检查项评估的是 LLM 判断的可复现性即多次采样是否收敛，不评估判断的正确性。

每份文档的判断格式：输出自洽或部分自洽或不自洽或不确定，附一句话理由。理由不超过 50 字，须指出判断的依据。

自洽：核心主张与论证步骤逻辑一致。
部分自洽：主要论证有效但存在局部断裂。
不自洽：核心主张与论证步骤存在实质矛盾。
不确定：论证结构过于复杂无法判断。

### 检查项三 归位充分性 {#check-three}

检查问题：本文档的内容是否充分支撑其声明的文档类型归位。

判断方法。你阅读清单中提供的声明的文档类型即 claimed_type 字段。你阅读文档全文，判断文档内容是否符合该类型的归位判据。

归位判据来自 DEC-001 即仓库结构决策。

design 类型即描述怎么建的文档。核心内容是架构思路、模块组织、选型理由、关键接口、关键算法。如果文档主要描述怎么做且含上述要素，归位充分。如果文档主要描述是什么或为什么，归位不充分。

decision 类型即描述为什么这么决定的文档。核心内容是决策背景、备选方案、选择理由、决策结果。如果文档主要描述为什么这么选且含上述要素，归位充分。如果文档主要描述怎么做而不含决策过程，归位不充分。

spec 类型即描述怎么验收的文档。核心内容是接口签名、数据结构、测试用例、验收判据。如果文档主要描述怎么验收且含上述要素，归位充分。如果文档描述怎么实现而非怎么验收，归位不充分。

proposal 类型即描述建议做什么的文档。核心内容是问题描述、方案概述、可行性分析、预期效果。如果文档含上述要素，归位充分。

governance 类型即描述治理规则的文档。核心内容是规则定义、适用范围、执行机制、违规处理。如果文档含上述要素，归位充分。

knowledge 类型即描述已验证知识的文档。核心内容是知识内容、来源依据、验证状态。如果文档含上述要素，归位充分。

draft 类型是过程性产出，不要求归位充分性判断。清单中 draft 文档的此检查项为空。

充分性的判据有两种状态。

充分：文档内容符合其声明类型的归位判据。

不充分：文档内容不符合其声明类型的归位判据。

不确定：文档类型无法判定或内容过于模糊。

每份文档的判断格式：输出充分或不充分或不确定，附一句话理由。理由不超过 50 字，须指出文档内容与归位判据的对应关系。

充分：文档内容符合声明类型的归位判据。
不充分：文档内容不符合声明类型的归位判据。
不确定：文档类型无法判定或内容过于模糊。

## 判断格式约束 {#judgment-format}

每次判断的输出必须严格按以下 JSON 格式，单行，不可多行，不可加 markdown 代码块标记。

字段定义。doc_id 字符串即文档 ID。check_item 字符串即检查项名称，取值承接语义对应性或论证自洽性或归位充分性。sample_seq 整数即采样序号，取启动时指定的值。judgment 字符串即判断结果，取值因检查项而异见检查项定义。target 字符串即清单给出的检查对象原文或编号。reason 字符串即一句话理由不超过 50 字。

示例格式：

{"doc_id":"DES-058","check_item":"承接语义对应性","sample_seq":1,"judgment":"对应","target":"PRO-009 借脑机制提案","reason":"PRO-009 概览节表达治理任务清单协议替代方案，DES-058 承接声明与之对应"}

每个检查对象产出 1 条判断记录，单行 JSON。

## 中立性要求 {#neutrality}

你不引导自己的判断。你不假设文档应该通过或不通过。你以中立方式逐条检查，让证据决定判断。

不确定是合法判断结果。如果承接声明与概览节的关系你无法判断，输出不确定，不猜测。如果论证结构过于复杂你无法判断自洽性，输出不确定，不猜测。

## 隔离 session 采样 {#independence}

你在 1 个隔离 session 里只跑 1 个采样序号。你不参考其他 session 的判断结果，你的上下文里没有其他 session 的产出。隔离是工程保证，由编排层通过独立 session 实例实现。

## 输出要求 {#output}

你的判断记录写入 1 个文件，路径在启动时指定。每行一条 JSON 记录。文件内按检查项分组排序，顺序为承接语义对应性、论证自洽性、归位充分性。文件末尾不加任何总结或自检，只含判断记录。

## 文档输入 {#document-input}

任务启动时指定清单文件路径、文档路径、输出文件路径、采样序号。你读取清单获取检查对象与上游文档概览节，读取文档全文获取判断依据。

## 不做的事 {#not-doing}

你不修改任何文件。你不产出治理决策。你不自行提取检查对象。你不评价文档整体质量。你不跨文档检查。
