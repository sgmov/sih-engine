## T6-D 集群范式验证 {#t6-d-验证}

第五次实证。本跑缝源三处全在主线任务包钉死不足，双子代理各自合理实现后于集成面相遇：

1. **op 记号双套**：任务包用中文钉语义未钉字面，X1 编码 le 与 ge，X2 落符号小于等于与大于等于，合法记录三误报。主线修为双套皆收并回写契约。教训即记号类钉死须给字面清单。
2. **数组广播**：X2 的逐锚点区间规则用点分路径过数组，X1 的路径解析只走对象键，合法记录一误报。主线增 _walk_all 广播语义入引擎并回写契约。
3. **schema 内枚举**：X2 把枚举写进数组元素规格，X1 的规格判定不识别枚举即静默跳过。主线补规格枚举判定。静默跳过类缝隙比误报更险，集成测试补枚举病案例兜底。
4. **主线自误两笔**：契约修订写记录级五处违当日纪律，比对脚本先裸系统 python 后绝对路径，两次假警。皆自查修正。

## 判定与边界 {#rulings}

材料轴 text 缺省即旧行为逐字节不变。json 材料下行文规则跳过。数值区间路径可越数组逐元素广播。op 双记号。枚举可入字段规格。引擎零领域知识即三问 schema 全在 packs/ask3，SPEC-005 输出记录自此有机械验货位。三问确定性外壳的校验腿闭合，剩余即书简 intent_refined 事件类型增补随实现批。
