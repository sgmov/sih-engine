# identity 正身模块调研任务书（委外）

## 背景与定位

你在为 SiHankor 治理工作区（/Users/moc/workspaces/SiHankor）调研一个具体工程问题。这是一次**纯调研任务**：只读、只分析、只产报告，零代码修改、零文件写入（你的报告除外）、零治理流程操作。

**正身（identity）是什么**：sih-tools/identity 是司衡引擎的"操作者身份核验"工具。每次治理批开工，执行代理要跑 `identity verify` 产一份身份报告（十二个环境组件拼成身份串、加盐做 SHA-256），租约系统用这个哈希绑定"本次写入操作是谁在哪个会话里做的"。它是链上留痕可追溯性的锚点之一——治理系统防"LLM 不可复现写入"的第一道身份闸。

**要调研的问题**：这个工具的哈希在同一天、同一台机器、同一席位上**连续漂移**。2026-09-02 一天之内实测四个不同哈希：`58e22070`（autoflow2 前）→ `14cfa9c2`（autoflow2 时）→ `9634b1de`（predspec2 时）→ `d9fd7386`（sweepclea6 时）。每次漂移都触发"重标定"（用 20 发探针重新建立当日基线），虽然流程扛住了，但说明**身份串里混进了不稳定组件**——同一逻辑身份在一天内被识别成了四个不同的"人"。这对一个以"可追溯、不可抵赖"为设计目标的治理系统是地基级问题：溯源时"今天的批和上午的批是不是同一个执行者"需要人工对照才能确认。

## 已知事实（你的调研起点，已核实勿重复验证）

1. 工具：sih-tools/identity/src/identity/{core.py, cli.py}，共 349 行，单子命令 verify 双模式（采集/对表）。
2. 十二组件键序固定：pid、ppid、hostname、mac、user、sandbox_id、session_id、boottime、parent_start、ancestry、net_time、timestamp。前四必到，其余可缺席（空串不判败）。
3. 身份串规范 identity_string_v3：`v3|pid=...|ppid=...|...` 竖线连接，哈希 = SHA-256(盐 + "|" + 身份串)。
4. 盐缺省随机 32 字节——**生产路径每次调用哈希必然不同，这是设计内行为**；显式 --salt 才可复现。
5. 已知的高漂移嫌疑组件：pid/ppid（每个进程不同）、timestamp/net_time（每次调用不同）、ancestry（父链进程名序列，代理的嵌套层数变化即变）、net_time（HTTP 外部钟，缺席即空串）。
6. 已立异常点三件：net_time_missing_while_reachable、clock_skew（>300s）、timestamp_before_boottime。
7. 治理系统对"同一席位"的实际语义：同一操作者（同一人类用户 + 同一 AI 席位如 ZCode:GLM-5.3-Flash）在同一天内的多次批操作应可被机械认定为一。

**Q2 业界做法对照**：调研以下对象对"代理/进程身份"的处理方式，各写一段（它们如何平衡防伪与连认）：(a) SSH 证书与短期凭据的 identity 绑定；(b) TEE/attestation 的测量寄存器思路（哪些进测量、哪些不进）；(c) Web 的设备指纹与 session token 二分；(d) 供应链的 SLSA provenance（provenance 里什么进签名什么进元数据）；(e) 你知道的其他 multi-agent 系统对 agent identity 的处理（如有开源实现可引）。重点不是罗列，是提取"什么组件该进身份哈希、什么该进会话元数据"的**可借鉴分层原则**。

**Q3 修复方案候选**：给出至少三个候选方案，各带利弊与迁移成本。必须覆盖的方向：(a) 组件分层——把十二件拆成"身份核"（稳定、进主哈希）与"会话面"（易变、进报告但不进哈希或进次级哈希），主哈希同席同日稳定可连认；(b) 双哈希制——long-term identity hash（核组件）+ session hash（全组件），租约绑后者、审计连认用前者；(c) 你自拟的其他方案（如组件加权、通配组件、声明式身份等）。每方案回答：防冒充能力降多少？连认能力升多少？对现有租约/链上已存报告的兼容性？

**Q4 与司衡约束的适配**：方案必须过的硬约束逐条自查——零 LLM 零网络依赖（net_time 的 HTTP 探针是否该保留？）；复演确定性（--salt 加 --inject 同参双跑逐字节一致）；退出码三值钉死；零写路径；跨 harness 血统区分（ancestry 的原始意图）不能丢。指出你的首选方案在这几条上各怎么过。

**Q5 迁移路径草案**：若采纳首选方案，给一个不破坏存量（今日链上 300+ 事件的身份引用）的迁移路径——新旧哈希并存期多长、租约侧要改什么（sih-tools/lease 的会话绑定读哪个哈希）、链上审计怎么双认。
