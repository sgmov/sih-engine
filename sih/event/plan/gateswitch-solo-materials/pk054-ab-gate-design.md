## 一、对象与现状 {#object}

**老路径（A，拟退役）**：温度探针标定路径。facet 测量的判据 v3 闸 V3-T 位以
家族体温（family_temperatures，冻结表 _FAMILY_TEMPERATURES_FROZEN v1-2026-08-15）
对每席位 boundary 率做调整后判读；体温的更新通路是 LLM 探针采样——模式一
（agent 框架适配，temp_probe export-pack → agent 逐发作答 → 程序计分入
probes/calibration/ledger.jsonl，现 16 行）与模式二（facet 后台席位，走
facet/.env 的 MINIMAX key，非 MiniMax 席位产生积分消耗）。基线 flip 率
（_BASELINE_FLIP_RATES_FROZEN）同源同通路。

**新路径（B，拟替代）**：上下文注入。席位标定事实不再以新鲜 LLM 采样度量，
而以在档上下文注入测量链：正身报告（identity_hash 与 core_hash 与 summary）
与标定账本历史读数（ledger.jsonl 在档行）与 pack_version 以注入形进入
测量材料上下文，V3-T 温度数值来源改为账本在档最近可用读数（零新鲜采样），
漂移判读改为账本内历史配对（同席位同 pack_version 逐行对表），探针采样通路
整体退役。

## 二、A/B 门设计 {#design}

**同场对比**：冻结在档语料（现行可复算 904 件，见批内 recheck 复算读数）
双路对跑——A 路以现行冻结体温表驱动 assess_maturation_v3；B 路以账本在档
读数注入（禁新鲜采样）驱动同函数；逐件比对 verdict_v3 与 near_flags 与
basis 指标。

**判据（切换门槛，显式）**：
1. 双路 verdict 一致率 = 100%（904/904，逐件三态全同；低于 100% 即不切换，
   差异件逐件列差异表呈裁）；
2. 双路体温读数与基线 flip 率逐席位一致（注入值与冻结表数值逐位相等）；
3. 漂移告警零（drift_alarm 空两路皆然）；
4. 契约纪律不变：注入路径的测量材料仍带 identity_hash 与合同哈希绑定
   （pk-035 语义不因退役松动）。

**切换条件（三条全过方切换，批内零代落）**：
1. 上列四判据全过且对跑读数双跑逐字节一致；
2. pk-044 独立性来源先裁：facet 重采独立性的来源问题（跨厂模型差 vs 同模型
   多发随机性）经用户裁定后，上下文注入路径的独立性依据才成立——次序不可倒，
   本条为硬前置；
3. 实装批以 T6 批形承接，拔闸动作（temp_probe 两模式退役与 .env 键位处置）
   随实装批落地，本设计批零实装。

## 三、键位与账本面处置实情申报 {#keys}

- 模式二 MINIMAX key 在 facet/.env，退役方向为**键不随件走**：key 从 facet
  面移除而非随退役组件迁移到新路径；移除动作属实装批，本批不动 .env。
- 标定账本 ledger.jsonl 16 行在档历史**零改写**，新路径只读消费；
- 模式一 agent 侧标定（本批 seat-baseline-zcode-2026-09-05-gateswitch.json
  即其产物）在切换前仍为 R5 执契核对的在役依据，退役后由账本在档读数承接。

## 四、风险与边界 {#risks}

- 体温注入若与冻结表数值出现逐位不一致（账本读数落后于冻结表版本），B 路
  会翻转 verdict——一致性判据即此风险的拦截闸；
- 上下文注入若被误用为「把更多散文塞进采样上下文」，即违反唯一桥梁裁定
  （工程生成层合法语义消费面是数学仓映射表与条目）——注入物限于正身件与
  在档账本读数等可机械校验工件，不含哲学散文；
- 本设计若得一裁否决，pk-054 出泊证据包照常呈报（出泊与否由人节点裁）。
