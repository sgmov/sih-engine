# Skill: sihankor-incubation

司衡引擎外切孵化融回范式的调用入口：引擎新能力开发经外切 sih-tools 分解、skills 手工调用验证、可证伪验收、可插拔融回四步环。本 skill 承载环的执行纪律，权威源是 PRO-005 全态节与 GOV-002 主线锁，本 skill 不替代登记。名称待用户签署，登记前以工作名运行。

## 触发时机 {#trigger}

- 引擎新能力开发动议，须判定外切还是仓内实现
- 外切工具的接口契约与验收判据登记
- 孵化期调用纪律检查与融回门检查
- 用户表达"切一个工具出来"、"这个能力外切"、"融回检查"类意图

不触发：引擎核心组件本体的仓内开发，外切对象为可通用化的确定性能力或经用户裁定的未建组件本体；facet 测量本身走 sihankor-facet-measure。

## 环四步 {#loop}

第一步外切判定。判据：能力是通用的、纯确定性的、可跨仓复用、可带退出码的，候选外切；承载引擎核心治理职能的组件本体，留仓实现。入环方式有两种：能力外切即已建或可通用化的确定性能力切出，组件先建即未实装组件的施工地经用户裁定选在围堰内建成再回迁，书简为组件先建首例即 2026-08-21 裁定。组件先建的前提是该组件名契已立而工程零落地，且融回前置含引擎侧模块实装的主线依赖。判定结果留痕。命名次序提示：外切立项时若该实体未立名，agent 须在施工前向用户提示次序选项即先立名后施工、或工作名先行并明示连带改写面，用户择一再开工，2026-08-25 用户裁定入列。

第二步接口契约登记。外切时即定组件接口与退出码，融回只搬实现不改接口。契约落工具仓内文档，引擎侧留引用。回迁债的根源是融回时重谈判接口，此步即为其预防。

第三步验收判据登记。可证伪条件，形态仿 facet 先例即指标加闸门验收。判据在外切时登记，融回时对表，不以感觉替代。

第四步融回门。三查：验收判据全过、接口契约未变、回迁债已评估。三查过后经可插拔机制落为组件模块实现，单独发布能力并行保留，或按知止退役。融回评估主判据为贡献度，2026-08-22 用户裁定：贡献度即工具在真实治理工作中的实际作用与产出，空转的调用量不计入；2026-09-04 用户裁定「融合贡献度应该走数学公理，不走人节点」，达标由检验判据承载不由用户裁量——贡献度为承重事件计数测度（认证引用与闸门改流与材料引用三判据并集，可加性承 PROB-016），达标为承重率二项检验对空转基线加控制图连续窗判读两腿合取（gauge contrib 只读子命令 formula gd-1 承载，规格 SPEC-017），原体量与时间两重门槛降级为贡献度的观察窗参数；判据全绿开启融回评估，融回评估启动仍走批令留痕与三查，不以判据全绿代裁融回动作本身；判变不溯往，已融回件不改写不重评。

## 纪律 {#discipline}

- 孵化期工具治理自治，不受引擎文档流程约束，但 skills 调用须留痕
- 三纪律随环携带：接口契约先于工具本体、验证判据前置、治理自增殖守望
- 融回不自动发生，融回门是人节点裁决
- 本 skill 不豁免化格核阅管线、书简认证与 facet 测量

## 边界 {#boundary}

本 skill 是范式的手动期载体。按 PRO-003 模式，职能成立后可正式化为引擎开发治理组件，其自身也走外切孵化融回环。权威源在 PRO-005 全态节与 GOV-002 主线锁，与权威源冲突时以权威源为准。
