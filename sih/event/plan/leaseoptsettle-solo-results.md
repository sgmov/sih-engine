令源即用户 2026-09-05 会话裁定，逐字留档：「1、读数异常，非本会话的文件，核验一遍烧一轮token，人节点的插入检查到直接报，人类同意后直接上链，不同意（误操作）直接回滚。这个人类节点不值得烧token，后期因为人类节点独自上链导致治理收敛下降甚至崩溃，人类置信度评分下降，检测到读数异常后不能直接上链，要求人类走司衡治理通道，人类可以继续拒绝直接上链 2、agent的修改和人类的修改无法区别，异常点出现，人类无印象，直接回滚，agent不允许无治理的操作，奖惩机制，让agent愿意主动上链。」

裁定展开：

- 零 token 异常协议：watch 检出无主修改即机械呈报（文件清单加时间戳，零核验零调查轮次，人节点不值得烧 token），人节点二值裁决即「我的」与「不是我的」；「不是我的」即机械回滚（git restore 确定性操作零动作代价）；「我的」不走直接上链，走司衡治理通道（域内文档管线三步加链笔，免全套租约仪式但免不了治理）。
- 人节点同受置信度约束：独自上链绕治理通道即治理收敛稀释，人节点置信度随之下降；人节点保留一票否决即可拒绝通道坚持直接上链，但否决留痕且置信度扣减，权威保留、代价显性。此条修正第六节追记中「补笔即销账」的宽形为通道必经形。
- 检测时不可区分生产者：watch 对无主修改单协议处置，不预设生产者身份，此前「人补笔、agent 违规」的双轨分叉撤销；生产者身份只在认领后的通道处理中经正身记录沉淀，并入置信度账。
- agent 无治理操作禁止与奖惩：agent 无声明写入一经发现即回滚即工作损毁即 token 白烧；主动走通道（写时声明）置信度加分。奖惩由置信度组件承载，机制目标即 agent 愿意主动上链。
- 技术前提两条：watch 豁免面须显式枚举（trail 与台账与 meter counts 与 scribe reports 为合法活写面，缺豁免则每批自鸣）；信封正身绑定先行（无身份锚则置信度账无从记）。
