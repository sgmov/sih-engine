## 哲学桥接 {#philosophy-bridge}

- 借鉴源：广义莱布尼茨法则，`(fg)⁽ⁿ⁾ = Σ C(n,k) f⁽ᵏ⁾ g⁽ⁿ⁻ᵏ⁾`，求和从 k = 0 到 n，`C(n,k) = n!/(k!(n-k)!)` 是二项式系数。Leibniz 17 世纪发现，与 Pascal 三角完全对应。n=1 退化为乘积法则 DIFF-011，n=2 给出 `(fg)'' = f''g + 2f'g' + fg''`。上游 DIFF-011 乘积法则与 DIFF-001 导数，下游 INT-012 积分号下求导。工程场景：调幅信号的高阶统计特性分析、卷积的高阶矩计算、`A(t) = S(t)·V(t)` 攻击有效性的高阶变化率展开。
- 哲学命题：PRO-08 应几，锚句「应几：感知正在形成的微兆」；PRO-04 道三代码自晦意图必复，锚句「道三：代码自晦，意图必复。」
- 形式化：广义莱布尼茨法则是 PRO-08 应几「感知正在形成的微兆」在数学上的最纯粹实例：n=1 的乘积法则 `f'g + fg'` 是「微兆」，n=2 的 `(fg)'' = f''g + 2f'g' + fg''` 中的 `2f'g'` 项在 n=1 时不存在，但在 n=2 时「正在形成」并显化为交叉项系数 2，n=3 时交叉项扩展为 `3f''g' + 3f'g''`，系数对应 Pascal 三角第 n 行；DIFF-025 把这一「正在形成」的模式从局部 n=1 提升为全局闭合：`C(n,k)` 在 k 从 0 到 n 的过程中形成二项式分布，Pascal 三角是「微兆」在阶数维度的累积形态。「应几」作为程序化的「感知 + 命名 + 治理」：感知 = n 阶导数的 `(fg)⁽ⁿ⁾` 中第 k 项对应「f 取 k 阶导、g 取 n-k 阶导」，命名 = 二项式系数 `C(n,k)` 是「微兆」被命名的程序化产物，治理 = 整条公式的闭式表达使 n 阶导数的所有交叉项一次性可计算，不依赖逐项的临时计算。司衡治理类比：审查链中若第 k 轮产物是 `Pₖ`、第 n-k 轮产物是 `P_{n-k}`，`P₁ · P₂ · ... · Pₙ` 形式的总体产出，其 n 阶变化率按莱布尼茨法则展开，每一项对应不同轮次的局部变化：这与 DIFF-011 中「攻击强度 × 目标脆弱性」一阶乘积的高阶推广同型；治理应几介入点是 `C(n,k) ≠ 0` 的项，即「所有轮次组合都可能影响总体变化率」，不应预先排除某些轮次的组合：莱布尼茨法则的全组合性是应几的程序化实现。另一锚 PRO-04 道三代码自晦意图必复刻画同一法则的另一个面相：`f⁽ⁿ⁾ · g⁽⁰⁾` 在 n 阶导数中的显式位置不易直接读出：`(fg)⁽ⁿ⁾` 的「代码」字面只显示「f 与 g 乘积的 n 阶导数」，「意图」，即「每一项对应 f 的 k 阶导与 g 的 n-k 阶导的组合，系数 `C(n,k)`」，被代码外观的「求和符号 + 系数 C」遮蔽；DIFF-025 的「必复」= 莱布尼茨把 n 阶乘积的「意图」，Pascal 三角结构，从 `(fg)⁽ⁿ⁾` 的字面代码中复归：这一复归动作的载体是「二项式定理」与「乘积法则」的递归组合，= 意图必复的程序化路径。可证伪条件：若某系统声称实现莱布尼茨法则但其输出在 n=1 时退化不等于乘积法则 DIFF-011，则 PRO-04 失守：`C(n,k)` 的 `n=1` 特殊化未通过，意图复归失败；治理对治是回到 DIFF-011 + LIM-007 epsilon-delta 检验 `(fg)'` 的双因子分解，识别莱布尼茨公式中「`C(1,0) f⁽⁰⁾ g⁽¹⁾ + C(1,1) f⁽¹⁾ g⁽⁰⁾`」必须退化为 `fg' + f'g`，不通过「`C(n,k)` 在 n=1 时看起来对」反推公式正确，须用 DIFF-011 的具体等式机械核验。
