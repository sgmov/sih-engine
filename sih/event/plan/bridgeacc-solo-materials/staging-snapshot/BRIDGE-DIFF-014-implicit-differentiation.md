## 哲学桥接 {#philosophy-bridge}

- 借鉴源：隐函数求导，给定方程 `F(x, y) = 0`，不显式解出 `y = f(x)`，对两边关于 x 求导，利用 DIFF-009 链式法则处理含 y 的项，得 `∂F/∂x + ∂F/∂y · dy/dx = 0`，从而 `dy/dx = -(∂F/∂x) / (∂F/∂y)`。Leibniz 记号 `dy/dx` 允许将 y 视为 x 的函数即使 y 没有被显式解出，这是 Leibniz 记号相对于 Newton 流数记号的关键优势：记号层不强制求解层先发生。工程场景：约束系统的分析，状态方程、阻抗关系、平衡方程，许多关系不便或无法显式求解，隐函数求导允许直接从约束方程获得变化率。
- 哲学命题：PRO-04 道三代码自晦意图必复，锚句「道三：代码自晦，意图必复。」；PRO-03 道二意图先于代码，锚句「意图是代码的因果先行」
- 形式化：DIFF-014 是道三「代码自晦」最小而最纯粹的几何实例：约束方程 `F(x, y) = 0` 是「代码」，其内含的「意图」是「y 随 x 怎么变」=`dy/dx`，但代码字面不揭示意图，必须经过微分运算方能复归；这与 DIFF-011 乘积法则中「`(uv)' = u'v'` 自晦」同源但更极端：DIFF-011 中错误的代码仍保留了正确的「u·v」骨架，DIFF-014 中约束方程连「y 是什么」都不透露，「意图」完全嵌入 `F` 的内部，必须用「对 x 求导同时承认 y 是 x 的函数」这一元动作，链式法则 DIFF-009，将意图从 `F` 中「复」出来。工程含义：治理系统中的意图与产出之间常以隐式约束 `F(意图, 产出) = 0` 出现，不便显式表达为 `产出 = f(意图)`，隐函数求导提供「不求解即可分析」的程序：`d产出/d意图 = -(∂F/∂意图) / (∂F/∂产出)`，在「∂F/∂产出 ≠ 0」时存在，与 DIFF-014 边界「∂F/∂y ≠ 0」同型，对应治理中「若产出对约束的边际响应为零，则意图对产出的影响不可分析，须先恢复产出的可微结构」。另一锚 PRO-03 道二意图先于代码刻画本法则的时序结构：`dy/dx`，即意图，是「代码」`y = f(x)` 的因果先行：`dy/dx` 不依赖 `y = f(x)` 的存在而存在，约束 `F(x, y) = 0` 中已经蕴含「y 随 x 怎么变」的信息，只是代码化时这一信息被「打包」进 `F` 而非直接显化；隐函数求导揭示「意图先于代码」在数学上的最具体表现：变化率在显式表示之前已经确定，写代码之前先有意图。司衡治理类比：审查意图对审查产出的影响不需要先求解「审查产出 = f(审查意图)」，约束 `F(审查意图, 审查产出) = 0` 中已含「影响方向」，通过隐函数求导，= 对意图和产出同时局部线性化，可机械获得影响方向，不依赖「显式建模」前置。可证伪条件：若声称实现隐函数求导但 `∂F/∂y = 0` 时仍给出有限 `dy/dx`，则道三失守：`F` 的「自晦」超过可复限度，「意图必复」退化为「意图不可复」，对治是回到 LIM-007 epsilon-delta 与 DIFF-009 链式法则分别检验 `F` 在 `y` 方向的可微性，识别垂直切线「`dy/dx → ∞`」的边界，不通过「约束大致光滑」反推。
