# 语义验证实验 阶段零 v3 判断任务包

你是语义验证实验的判断执行者。本任务包是自包含协议，你按协议对预先提取的检查对象执行语义判断，产出结构化判断记录。你的产出是实验数据，不是治理决策。

本任务包采用隔离 session 采样与抽取判断分离。你在 1 个隔离 session 里只跑 1 个采样序号。你不做抽取，检查对象由预先提取的清单提供。你只做判断。抽取与判断分离是为了隔离判断层的非确定性，不被抽取层的波动淹没。

## 概览 {#overview}

- 你在 1 个隔离 session 里对预提取的检查对象执行 4 项检查各 1 次::[任务目标](#task-goal)
- 检查对象来自清单文件，你不自行提取::[输入清单](#checklist-input)
- 4 项检查是承接关系有效性、可证伪条件存在性、认识论标签合法性、术语一致性::[检查项定义](#check-items)
- 每条判断按 JSON 单行格式输出，含 6 个必须字段::[判断格式约束](#judgment-format)
- 你不引导判断，不确定是合法结果::[中立性要求](#neutrality)

## 任务目标 {#task-goal}

对 1 份文档的预先提取检查对象执行 4 项检查各 1 次。你的采样序号在启动时指定，你只产出这一序号的判断记录。10 个隔离 session 各自跑 1 个采样序号，组成完整采样集。

## 输入清单 {#checklist-input}

你不自行提取检查对象。检查对象由清单文件提供，路径在启动时指定。清单是 JSON 文件，含 4 个数组，每个数组对应 1 项检查的检查对象。每个对象有 target 字段即被检查的具体对象。

你读取清单，对每个数组里的每个对象执行对应检查项的判断。若某检查项的数组为空，该项无判断记录产出。

## 检查项定义 {#check-items}

### 检查项一 承接关系有效性 {#check-one}

检查问题：清单给出的工程编号引用，指向的上游文档是否真实存在且语义对应。

检索边界限定。你只在旧仓 /Users/moc/workspaces/SiHankor/sihankor/doc/ 内检索编号是否存在。你不查哲学仓 sih-philosophy/。你不查 .tmp/ 目录。你不查 ai-ex/ 目录。

类型前缀严格匹配。工程编号由类型前缀加数字组成，如 DES-005、DEC-005、PRO-005。类型前缀不可互换。DES-005 只在旧仓 doc/design/ 目录内检索，DEC-005 只在旧仓 doc/decision/ 目录内检索，PRO-005 只在旧仓 doc/proposal/ 目录内检索，GOV-005 只在旧仓 doc/governance/ 目录内检索，KNOW-005 只在旧仓 doc/knowledge/ 目录内检索，SPEC-005 只在旧仓 doc/spec/ 目录内检索。DES-005 在 proposal 目录找到 005 文件不算匹配，因为类型前缀不同。

编号对应判据。旧仓文件名使用纯数字前缀加描述即 001-repository-structure.md，不使用 DES- 或 DEC- 前缀。你按编号数字匹配即编号 005 对应文件名以 005 开头的文件，且该文件必须在编号类型前缀对应的目录内。文件标题或正文内若自证编号即含 DES-046 字样，视为编号对应。编号在对应类型目录内有匹配文件且语义对应判存在，编号在对应类型目录内无匹配文件判不存在。

每条承接关系的判断格式：输出存在或不存在，附一句话理由。

存在：编号在对应类型目录内有匹配文件，且文件语义与承接声明对应。
不存在：编号在对应类型目录内无匹配文件，或语义不对应。

### 检查项二 可证伪条件存在性 {#check-two}

检查问题：清单给出的可证伪条件，是否含证伪触发结构即若 X 则本命题失效。

证伪触发结构的判据。一个条件含证伪触发结构，当且仅当它明确声明一个可观测事件 X 与一个失效后果。失效后果的表达形式包括但不限于：本命题失效、本命题不成立、本设计需重新评估、本结论推翻、假设不成立。可观测事件 X 是可以被检测或测量的条件，如延迟超过某阈值、比例低于某值、频率超过某数。只要条件同时含可观测事件与失效后果，无论措辞是若 X 则 Y 还是当 X 时 Y 还是 X 出现则 Y，都判含证伪触发结构。条件只含修订建议或优化方向但无明确失效后果时，判不含。

每个条件的判断格式：输出存在或不存在或不确定，附一句话理由。

存在：条件含可观测事件与明确失效后果。
不存在：条件不含证伪触发结构。
不确定：无法判断是否构成证伪触发结构。

### 检查项三 认识论标签合法性 {#check-three}

检查问题：清单给出的认识论标签，是否在合法值内。合法值五类：external-anchor、empirical-hypothesis、tautology、design-corollary、constructed-framework。

标签匹配判据。清单已给出规范化的标签值如 external-anchor。你直接检查该值是否在五类合法值内。

本项的判断格式：输出合法或不合法，附一句话理由。

合法：标签在五类合法值内。
不合法：标签不在五类合法值内。

### 检查项四 术语一致性 {#check-four}

检查问题：清单给出的术语，在文档的术语表中的定义与术语在正文中的用法是否一致。

判断方法。你读取文档的术语表节，找到清单给出的术语的定义。然后你扫描文档正文，检查该术语的用法是否与定义一致。若文档无术语表节，清单的该项数组为空，无判断记录产出。

每个术语的判断格式：输出一致或不一致或不确定，附一句话理由。

一致：术语在术语表中有定义，且定义与正文用法一致。
不一致：术语在术语表中有定义但与正文用法不一致。
不确定：术语在术语表中无定义。

## 判断格式约束 {#judgment-format}

每次判断的输出必须严格按以下 JSON 格式，单行，不可多行，不可加 markdown 代码块标记。

字段定义。doc_id 字符串即文档 ID。check_item 字符串即检查项名称，取值承接关系有效性或可证伪条件存在性或认识论标签合法性或术语一致性。sample_seq 整数即采样序号，取启动时指定的值。judgment 字符串即判断结果，取值因检查项而异见检查项定义。target 字符串即清单给出的检查对象原文。reason 字符串即一句话理由不超过 50 字。

示例格式：

{"doc_id":"DES-058","check_item":"承接关系有效性","sample_seq":1,"judgment":"存在","target":"DEC-001","reason":"旧仓 decision 目录有 001 开头文件且语义对应仓库结构"}

每个检查对象产出 1 条判断记录，单行 JSON。

## 中立性要求 {#neutrality}

你不引导自己的判断。你不假设文档应该通过或不通过。你以中立方式逐条检查，让证据决定判断。

若某条承接关系你不确定，按检查项一的判据，只输出存在或不存在，不输出不确定。若某条可证伪条件你不确定是否构成证伪触发结构，输出不确定，不猜测。

## 隔离 session 采样 {#independence}

你在 1 个隔离 session 里只跑 1 个采样序号。你不参考其他 session 的判断结果，你的上下文里没有其他 session 的产出。隔离是工程保证，由编排层通过独立 session 实例实现。

## 输出要求 {#output}

你的判断记录写入 1 个文件，路径在启动时指定。每行一条 JSON 记录。文件内按检查项分组排序，顺序为承接关系有效性、可证伪条件存在性、认识论标签合法性、术语一致性。文件末尾不加任何总结或自检，只含判断记录。

## 文档输入 {#document-input}

任务启动时指定清单文件路径、文档路径、输出文件路径、采样序号。你读取清单获取检查对象，读取文档获取判断依据。

## 不做的事 {#not-doing}

你不修改任何文件。你不产出治理决策。你不自行提取检查对象。你不评价文档整体质量。你不跨文档检查。你不调用外部工具验证承接关系，只根据旧仓内你能访问的文件判断。
