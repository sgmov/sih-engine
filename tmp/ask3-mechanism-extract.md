# 三问单元机制：从治理工程到法律咨询的可迁移拆解

本文档从 SiHankor 工程仓的三问单元 Ask3Repeater 中提取核心机制，剥离哲学特定术语，重组为可被其他项目借鉴的通用框架，并以法律咨询为示例场景演示正向意图拆解与反向意图恢复。

## 一、机制本质

三问单元解决一个核心问题：用户输入的自然语言意图是多层的、含混的、带隐含前提的。直接对原始输入做判断或生成回答，会遗漏隐层意图、放过逻辑裂隙、忽略歧义分支。

三问单元不向用户提问。它是一个向内诘察的递归推演引擎——对 LLM 自己的推演过程发问，逐层拆解意图，逼近原子命题。

与苏格拉底式追问的区别：苏格拉底追问是向外的，向对话方提问。三问单元是向内的，向推演过程本身发问，用户不参与中间过程，只在最终结果上决策。

## 二、三层推演架构

### 一问：显层诉求析出

输入：用户原始文本。

处理：模板匹配加关键词提取加候选分类，产出显层命题集合。这一步不深入推理，只做表面诉求的结构化。每条命题标注诘察阶段等于一。

输出：一级命题集合。

法律咨询示例。用户说「我想起诉前公司」。一问析出的显层命题：

- 命题 1：用户有意对前雇主提起诉讼
- 命题 2：诉讼对象是前公司即雇主
- 命题 3：用户认为存在可诉讼的事由

这些是用户字面说的内容，还没有挖掘背后的隐含信息。

### 二问：挖掘隐含前提

输入：一级命题集合。

处理：对每条一级命题沿三个维度挖掘隐层。

维度一，隐含前提。用户没有说出来但假设成立的条件。命题「用户有意对前公司提起诉讼」的隐含前提可能是：用户认为前公司做了违法的事、用户已经离开公司、用户认为诉讼是最佳解决途径。

维度二，逻辑裂隙。一级命题之间或命题内部存在的逻辑跳跃或矛盾。比如用户说「想起诉」但没有说起诉理由，这是一个从意向到行动的逻辑裂隙。又如用户说「前公司」但没有说明离职时间，这影响诉讼时效的判断。

维度三，歧义分支。同一表述可能指向不同的法律路径。「起诉前公司」可能是劳动争议、合同纠纷、知识产权争议、侵权责任，每条路径的法律要件、程序、时效完全不同。

输出：二级命题集合，每条标注诘察阶段等于二，标注来源维度即隐含前提或逻辑裂隙或歧义分支。

法律咨询示例。对「想起诉前公司」的二问产出：

隐含前提：

- 前提 A：用户认为前公司有违法行为（未验证）
- 前提 B：用户已离职（未验证，影响劳动争议仲裁前置）
- 前提 C：用户认为诉讼比协商或仲裁更有效（未验证）

逻辑裂隙：

- 裂隙 A：意向到行动——有起诉意向但未说明具体事由
- 裂隙 B：时效——未说明离职时间，无法判断是否超过仲裁时效或诉讼时效
- 裂隙 C：管辖——未说明地点与合同管辖条款

歧义分支：

- 分支 A：劳动争议路径——需先仲裁后诉讼，时效一年
- 分支 B：合同纠纷路径——按合同约定管辖与时效
- 分支 C：侵权责任路径——按侵权地管辖，时效三年
- 分支 D：知识产权路径——若涉及职务发明或竞业限制

### 三问：递归细化

输入：二级命题中的核心命题。

处理：对每条需要深化的二级命题递归调用细化，每生成一条子命题立即判定是否需要继续拆解。收敛条件是某命题生成新子命题时，判定无有效新增，或子命题已经达到可操作的原子粒度。

输出：三级及 N 级命题集合，每条标注诘察阶段等于三或更高。收敛时生成推理锚点。

法律咨询示例。对歧义分支 A 即劳动争议路径的三问产出：

- 子命题 A1：用户需确认是否曾签订劳动合同（影响事实劳动关系认定）
- 子命题 A2：用户需确认离职时间是否在一年内（影响仲裁时效）
- 子命题 A3：用户需确认争议类型是工资、经济补偿、违法解除、工伤（影响法律适用）
- 子命题 A4：子命题 A3 中违法解除的举证责任分配——用户需初步证明解除事实，用人单位证明解除合法性（无需进一步拆解，已达原子粒度）

## 三、认知域契约：意图拆解的正向控制

三问单元的拆解不是无限制的。认知域契约控制每条命题的拆解边界。

三个域：

target 域即本次求解直接相关。允许递归钻取至原子命题。上面例子中的劳动争议路径如果被判定为 target，会继续三问递归细化。

support 域即背景依赖。允许引用但不允许无限递归。比如用户的情绪状态、经济压力，这些是理解用户处境的背景，但不需要拆解到原子粒度。

isolate 域即无关分支。封存不细化。比如用户提到的前公司行业信息、同事关系，如果与法律路径无直接关联，封存。

域匹配判定有两层。第一层是规则匹配，用关键词或语义相似度做快速分类，无算力开销。第二层是 LLM 兜底，规则无法判定时调用轻量 LLM 做语义判定。

契约锁定有两种模式。渐进模式是低风险默认，先用极简临时契约放行一问，后台异步生成正式契约。前置模式是中高风险强制，必须先锁定完整契约才允许进入二问三问。

## 四、正向意图拆解：从用户输入到原子命题

正向拆解是三问单元的标准流程。完整路径如下。

步骤一，用户输入原始文本。

步骤二，一问析出显层命题，规则匹配产出一级命题集合。

步骤三，域匹配判定，区分 target、support、isolate。

步骤四，二问对 target 命题挖掘隐含前提、逻辑裂隙、歧义分支，产出二级命题集合。

步骤五，域匹配判定二级命题。

步骤六，三问对 target 二级命题递归细化，产出原子命题集合。

步骤七，收敛时生成推理锚点，锚点含完整 DAG 结构，可回溯每个原子命题的推导链。

法律咨询的正向拆解完整示例：

用户输入：「我在公司干了三年，上个月被口头辞退了，没有书面通知，没有给补偿，我能告他们吗？」

一问显层命题：

- 命题 1：用户在公司工作三年
- 命题 2：用户上个月被辞退
- 命题 3：辞退是口头通知无书面文件
- 命题 4：未支付经济补偿
- 命题 5：用户想知道能否起诉

二问隐含前提：

- 前提：存在劳动关系（需确认合同或事实劳动关系）
- 前提：辞退方是用人单位单方解除（需确认非协商一致）
- 前提：口头辞退的法律效力待认定（口头解除可能不发生效力）

二问逻辑裂隙：

- 裂隙：口头辞退后用户是否实际停止工作（影响劳动关系是否已解除的事实判断）
- 裂隙：三年工龄是否连续（影响经济补偿的计算年限）

二问歧义分支：

- 分支 A：违法解除赔偿金路径——若用人单位无法证明合法解除，可主张 2N 赔偿金
- 分支 B：未支付工资路径——若口头辞退后用户仍提供劳动，劳动关系未解除，可主张工资
- 分支 C：要求继续履行路径——若用户不愿解除，可要求恢复劳动关系

三问对分支 A 的原子细化：

- 原子 A1：确认用人单位解除的理由（直接影响合法性审查标准）
- 原子 A2：确认用人单位是否有规章制度依据（劳动合同法第三十九条适用）
- 原子 A3：确认用户是否在医疗期、孕期、工伤期（第四十二条不得解除情形）
- 原子 A4：仲裁时效从被辞退日起算一年，上个月辞退在时效内

推理锚点生成，DAG 结构记录从用户输入到四个原子命题的完整推导链。

## 五、反向意图恢复：从原子命题回溯用户意图

反向恢复是正向拆解的逆操作。场景是：已有原子命题集合或推理锚点，需要回溯用户原始意图，验证拆解是否忠实于原始输入，或向用户呈现「我理解到的是这些」供确认。

反向恢复的三步。

第一步，锚点回溯。从推理锚点读取完整 DAG，沿 parent 边从原子命题逐层回溯到一级命题再到用户输入。

第二步，意图重构。把 DAG 节点按层级重组为自然语言摘要。摘要的结构是：你说了什么，我们理解到什么，我们发现了什么隐含前提，我们识别了什么歧义分支，建议走什么路径。

第三步，偏差检测。比较重构的意图摘要与用户原始输入，检测三类偏差：遗漏（用户提到但拆解链中没有覆盖的内容）、添加（拆解链中有但用户未提及的假设）、扭曲（用户表述被拆解链改变了原意）。

法律咨询的反向恢复示例：

用户原始输入：「我在公司干了三年，上个月被口头辞退了，没有书面通知，没有给补偿，我能告他们吗？」

反向重构摘要：

你提到的核心诉求是能否起诉前公司。我们沿你的输入做了以下理解。

你说了什么：工作三年、上个月被口头辞退、无书面通知、未给补偿、想知道能否起诉。

我们理解到的隐含信息：你假设存在劳动关系、你假设辞退是单位单方行为、口头辞退的法律效力需要进一步确认。

我们识别的歧义：你可以走违法解除赔偿金路径即 2N、可以走要求继续履行路径、如果口头辞退后你仍在上班可能劳动关系未解除可以追工资。

我们建议确认的事项：单位的辞退理由是什么、你是否有劳动合同、你是否实际停止了工作、你是否在特殊保护期。

偏差检测：

- 遗漏检查：用户提到「干了三年」是否被覆盖。是，原子 A 连续工龄确认中。
- 添加检查：拆解链是否假设了用户未说的事实。前提「辞退方是用人单位单方解除」是隐含前提，已标注未验证，不是添加。
- 扭曲检查：用户问「能不能告」，拆解链没有扭曲为「一定要告」，而是拆解出多条法律路径供选择。无扭曲。

反向恢复的意义：用户看到重构摘要后，可以确认「是的，这就是我的意思」或纠正「不，我不是这个意思，我实际想问的是某某」。这是三问单元与用户的唯一交互点——不是在拆解过程中提问，而是在拆解完成后呈现结果供确认。

## 六、法律咨询场景的适配要点

三问单元迁移到法律咨询场景，需要五处适配。

适配一，认知域的语义。target 域对应用户核心法律诉求。support 域对应案件背景事实。isolate 域对应与法律路径无关的信息。

适配二，二问的三维度映射。隐含前提对应法律构成要件中用户未提及但默认成立的要素。逻辑裂隙对应从事实到法律结论之间的证据缺口或推理跳跃。歧义分支对应同一事实可能适用的不同法律路径。

适配三，原子命题的粒度。法律场景的原子命题应是可操作的——每个原子命题对应一个具体的法律要件确认、证据收集动作、或程序选择。

适配四，推理锚点的用途。法律咨询的锚点可以直接转化为法律意见书的大纲——DAG 的层级结构天然对应意见书的章节结构。

适配五，反向恢复的交互设计。法律咨询的反向恢复摘要应包含风险提示——歧义分支中每条路径的胜诉概率、时间成本、经济成本，让用户在确认意图时同时做风险评估。

## 七、与 LLM 的关系

三问单元是 LLM 的使用框架，不是独立于 LLM 的程序。

一问以规则匹配为主，少用或不用 LLM，成本最低。

二问和三问需要 LLM 的语义推理能力，是算力主要消耗点。

域匹配判定的第一层用规则，第二层用 LLM 兜底。

三问单元的价值不在于 LLM 本身的能力，在于用结构化的递归框架约束 LLM 的推演路径，使每次 LLM 调用都有明确的输入边界、输出格式、收敛条件。这防止 LLM 的发散性推理失控，把语义判断的非确定性收敛到可控的结构内。

## 八、关键设计约束

约束一，禁止熔断。三问单元在推演过程中不允许中断放弃。如果某个分支无法继续拆解，标记为收敛而非报错。只有输入本身不合法才拒绝。

约束二，认知域契约必须锁定后才进入二问三问。临时契约只允许一问执行。这防止在意图边界不明确时盲目深入挖掘。

约束三，推理锚点持久化。每次完整推演的 DAG 结构必须持久化，可回溯、可审计。这是反向恢复的前提，也是治理留痕的构成性条件。

约束四，三问单元不向用户提问。所有拆解在内部完成，用户只在最终结果上确认。如果二问发现关键信息缺失，记录为逻辑裂隙而非向用户追问。反向恢复时把裂隙呈现给用户，由用户决定是否补充。

约束五，原子命题不可再分。三问的收敛判据是命题达到原子粒度即不可进一步拆解。法律场景的原子粒度对应单一法律要件的确认，不是复合判断。
