# 过程文档专用检查项判断协议

本协议定义过程文档即 draft 与 research 类型的三项专用语义检查项。核心文档即 governance、spec、decision、proposal、design 使用承接语义对应性、论证自洽性、归位充分性三项检查项，过程文档使用本协议定义的三项。

## 三项检查项

### 检查项一 引用有效性

检查问题：文档中引用的文件路径、文档编号是否存在且可达。逐个检查文档中出现的文件路径引用与文档编号引用。

判断值四元：
- 有效：引用的路径或编号确实存在
- 无效：引用的路径或编号不存在
- 不确定：无法判断是否存在

注意：文档编号分两类。文件编号即 DEC、DES、SPEC、GOV、KNOW 等对应 doc 目录下的实际文件，引用这类编号检查文件是否存在。哲学命题编号即 PRO 系列对应哲学仓命题，这类编号是概念标识不是文件，不检查文件存在性，判不确定。

### 检查项二 操作完整性

检查问题：文档作为操作指令、任务包、调研报告，其核心功能是否完整可执行。完整指有明确的输入要求、执行步骤、输出要求。对调研报告，输入对应调研问题，步骤对应调研方法，输出对应调研结论。

判断值三元：
- 完整：输入、步骤、输出三者齐全
- 不完整：缺少其中一项或多项
- 不确定：无法判断是否完整

### 检查项三 约束一致性

检查问题：文档内部的约束、规则、要求是否自相矛盾。

判断值三元：
- 一致：内部约束无矛盾
- 矛盾：存在互相冲突的约束
- 不确定：无法判断

## 判断方法

对每个检查项，你读取文档全文，逐项检查，给出判断与一句话理由。

判断须中立。不预设文档应该通过或不通过。不引导判断方向。如实反映文档的实际状态。

## 输出格式

每个检查对象输出一行 JSON，结构如下：

{"sample_seq": 1, "check_item": "引用有效性", "target": "文档内引用", "judgment": "有效", "reason": "一句话理由"}

每份文档输出至少三行，每项检查项一行。target 统一填文档内引用。sample_seq 填你的采样序号。

输出纯 JSON 行，每行一个记录，不含其他文字。
