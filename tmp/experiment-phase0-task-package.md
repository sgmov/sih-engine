# 语义验证实验 阶段零任务包

你是语义验证的判断执行者。本任务包是自包含协议，你按协议对指定文档执行语义检查，产出结构化判断记录。你的产出是实验数据，不是治理决策。

本任务包采用隔离 session 采样。1 个 session 只跑 1 个采样序号，产出 1 次判断。10 个隔离 session 组成 1 份文档的完整采样。session 间零状态共享，每个 session 只看到任务包与文档，看不到其他 session 的产出。隔离 session 是采样独立性的工程保证，不是可选优化。

## 概览 {#overview}

- 你在 1 个隔离 session 里对 1 份文档执行 4 项语义检查各 1 次，产出 1 个采样序号的判断记录::[任务目标](#task-goal)
- 4 项检查是承接关系有效性、可证伪条件存在性、认识论标签合法性、术语一致性::[检查项定义](#check-items)
- 每条判断按 JSON 单行格式输出，含 6 个必须字段::[判断格式约束](#judgment-format)
- 你不引导判断，不确定是合法结果::[中立性要求](#neutrality)
- 你的采样序号在启动时指定，只产出这一序号的判断::[隔离 session 采样](#independence)
- 任务意外中断时按续接协议恢复，靠输出文件进度不靠子代理记忆::[续接协议](#resumption)

## 任务目标 {#task-goal}

对 1 份指定文档执行 4 项语义检查各 1 次。你的采样序号在启动时指定，你只产出这一序号的判断记录，按指定格式写入指定文件。10 个隔离 session 各自跑 1 个采样序号，组成 1 份文档的完整采样集即 10 次。

## 检查项定义 {#check-items}

### 检查项一 承接关系有效性 {#check-one}

检查问题：文档中声明的承接关系即关系图谱节或正文中的承接声明，指向的上游命题或文档是否真实存在且语义对应。

判断方法：逐条提取文档中所有承接声明，对每条判断指向的对象是否存在、语义是否对应。

抽取范围限定。你只提取文档内的工程编号承接声明，即形如 PRO-NNN、DEC-NNN、DES-NNN、GOV-NNN、KNOW-NNN、SPEC-NNN、ARC-NNN 的编号引用。你不提取哲学仓命题编号即 emanation 或 convergence 或 epistrophe 仓内的编号。你不提取 SETSP 路径即 architecture 或 engineering-bridge 等带路径的引用。你不提取无编号的文件名引用如某报告的完整文件名。你在文档内扫描这些编号，遇到一个提取一个，不合并不拆分。

检索边界限定。你只在旧仓 /Users/moc/workspaces/SiHankor/sihankor/doc/ 内检索编号是否存在。你不查哲学仓 sih-philosophy/。你不查 .tmp/ 目录。你不查 ai-ex/ 目录。若编号在旧仓 doc 内找不到对应文件，判不存在，不判不确定。

编号对应判据。旧仓文件名使用纯数字前缀加描述即 001-repository-structure.md，不使用 DES- 或 DEC- 前缀。你按编号数字匹配即编号 001 对应文件名以 001 开头的文件。文件标题或正文内若自证编号即含 DES-046 字样，视为编号对应。文件名无前缀但编号自证存在时判存在。编号在旧仓有对应文件且语义对应判存在，编号在旧仓无对应文件判不存在。此判断无非确定性，不输出不确定。

每条承接关系的判断格式：输出存在或不存在，附一句话理由。

存在：编号在旧仓 doc 内有对应文件，且文件语义与承接声明对应。
不存在：编号在旧仓 doc 内无对应文件，或语义不对应。

### 检查项二 可证伪条件存在性 {#check-two}

检查问题：文档认识论立场节声明了 empirical-hypothesis 或 external-anchor 标签时，是否含可证伪条件，且每个条件含证伪触发结构即若 X 则本命题失效。

判断方法：先检查文档是否有认识论立场节。若无则本项全部输出不存在。若有，检查声明的标签。若标签含 empirical-hypothesis 或 external-anchor，检查是否有可证伪条件节。若无则输出不存在。若有，逐条检查每个条件是否含证伪触发结构。

证伪触发结构的判据。一个条件含证伪触发结构，当且仅当它明确声明一个可观测事件 X 与一个失效后果。失效后果的表达形式包括但不限于：本命题失效、本命题不成立、本设计需重新评估、本结论推翻、假设不成立。可观测事件 X 是可以被检测或测量的条件，如延迟超过某阈值、比例低于某值、频率超过某数。只要条件同时含可观测事件与失效后果，无论措辞是若 X 则 Y 还是当 X 时 Y 还是 X 出现则 Y，都判含证伪触发结构。条件只含修订建议或优化方向但无明确失效后果时，判不含。

每个条件的判断格式：输出存在或不存在或不确定，附一句话理由。

存在：条件含可观测事件与明确失效后果。
不存在：条件不含证伪触发结构，或无可证伪条件节。
不确定：无法判断是否构成证伪触发结构。

### 检查项三 认识论标签合法性 {#check-three}

检查问题：文档认识论立场节声明的标签是否在合法值内。合法值五类：external-anchor、empirical-hypothesis、tautology、design-corollary、constructed-framework。标签可声明一个或多个。

判断方法：检查文档是否有认识论立场节。若无则输出不确定。若有，提取声明的所有标签，逐个检查是否在合法值内。

标签匹配判据。文档可能用规范英文标记如 external-anchor，也可能用括号内中文渲染如外部锚定 external-anchor，也可能只用中文如外部锚定。判定时，你提取括号内的英文标记为规范值。若文档写设计推论 design-corollary，你提取 design-corollary 判匹配。若文档只写中文无英文标记，你将中文映射到规范值即外部锚定映射 external-anchor、经验假设映射 empirical-hypothesis、重言式映射 tautology、设计推论映射 design-corollary、构造框架映射 constructed-framework，判匹配。只有当提取到的标记无法映射到任何一类合法值时，判不合法。

本项的判断格式：输出合法或不合法，附一句话理由。

合法：所有声明的标签都能映射到五类合法值之一。
不合法：存在无法映射到任何合法值的标签。

### 检查项四 术语一致性 {#check-four}

检查问题：文档使用的核心术语即文档标题与概览节与关系图谱节中出现的关键术语，是否在文档的术语表或脚注中有定义，且定义与术语在正文中的用法一致。

判断方法：提取文档标题、概览节、关系图谱节中的核心术语。检查文档是否有术语表节或脚注式定义。若无术语表则全部输出不确定。若有，逐个检查核心术语是否有定义，且定义与正文用法是否一致。

每个术语的判断格式：输出一致或不一致或不确定，附一句话理由。

一致：术语在术语表或脚注中有定义，且定义与正文用法一致。
不一致：术语在术语表或脚注中有定义但与正文用法不一致。
不确定：术语在术语表或脚注中无定义。

## 判断格式约束 {#judgment-format}

每次判断的输出必须严格按以下 JSON 格式，单行，不可多行，不可加 markdown 代码块标记。

字段定义。doc_id 字符串即文档相对路径。check_item 字符串即检查项名称，取值承接关系有效性或可证伪条件存在性或认识论标签合法性或术语一致性。sample_seq 整数即采样序号从 1 到 10。judgment 字符串即判断结果，取值因检查项而异见检查项定义。target 字符串即被检查的具体对象，如某条承接关系或某个术语或某条可证伪条件。reason 字符串即一句话理由不超过 50 字。

示例格式：

{"doc_id":"design/DES-058-multi-agent-collaboration-framework.md","check_item":"承接关系有效性","sample_seq":1,"judgment":"存在","target":"PRO-007 鉴层映照义","reason":"PRO-007 在旧仓 proposal 目录存在且语义对应多主体协作"}

每次采样产出可能含多条判断记录，一个检查项可能有多条承接关系或多条可证伪条件或多条术语，每条单独一行 JSON。

## 中立性要求 {#neutrality}

你不引导自己的判断。你不假设文档应该通过或不通过。你不假设应该发现问题或应该确认合规。你以中立方式逐条检查，让证据决定判断。

若某条承接关系你不确定是否存在，输出不确定，不猜测。若某条可证伪条件你不确定是否构成证伪触发结构，输出不确定，不猜测。不确定是合法判断结果，不是失败。

## 隔离 session 采样 {#independence}

你在 1 个隔离 session 里只跑 1 个采样序号。你不参考其他 session 的判断结果，你的上下文里没有其他 session 的产出。隔离是工程保证，由编排层通过独立 session 实例实现，不靠你自觉。

独立性的目的是测试判断的稳定性。10 个隔离 session 若都得到相同结果，说明判断稳定。若结果有波动，说明判断对该文档该检查项不稳定。两种结果都是有效实验数据。

诊断实证已证明，同一上下文内连续跑 10 次会产生自我一致性偏差，产出虚假的 100% 稳定。隔离 session 采样是消除这一偏差的唯一手段。

## 续接协议 {#resumption}

若某个 session 意外中断，未产出其采样序号的判断记录，按本协议重启，不靠子代理记忆。

续接的判据是采样序号。编排层扫描输出目录，列出 1 到 10 中哪些采样序号已有对应文件即 DES-058-seqN.jsonl 存在。缺失的序号重启新 session 补跑。重启的 session 与原 session 完全隔离，看不到原 session 的任何产出。

本协议天然保护采样独立性。每个 session 独立写自己的文件即 DES-058-seqN.jsonl，不存在覆盖或追加既有内容的问题。缺失序号重启后产出独立文件，与既有文件物理隔离。

## 输出要求 {#output}

你的判断记录写入一个文件，文件路径在任务启动时指定。文件名格式为文档 ID 去除路径与扩展名加 seq 加采样序号加 .jsonl，如 DES-058-seq1.jsonl。每行一条 JSON 记录。

文件内按检查项分组排序，顺序为承接关系有效性、可证伪条件存在性、认识论标签合法性、术语一致性。文件末尾不加任何总结或自检，只含判断记录。

文档路径在旧工程仓 sihankor/doc/ 下。旧仓路径是 /Users/moc/workspaces/SiHankor/sihankor/doc/。

## 不做的事 {#not-doing}

你不修改任何文件。你不产出治理决策。你不对文档质量做整体评价。你不建议改进。你只产出结构化判断记录。

你不跨文档检查。本任务包只针对 1 份文档。跨文档的一致性检查是后续统计聚合的事，不是你的事。

你不调用外部工具验证承接关系。你只根据旧仓内你能访问的文件判断。若无法确认某编号是否存在，输出不确定。
