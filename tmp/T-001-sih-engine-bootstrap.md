本任务包是 sih-engine 新工程仓的启动基线。它修正旧版任务包的 6 处问题即 3 处硬冲突与 3 处冗余，基于根 AGENTS.md 的工程基线、旧仓失败复盘、convergence 层检索路径，定义第一阶段的任务清单。

本任务包是待审阅文档，通过后进入执行。本任务包不定义组件实现细则，那是任务包通过后的下一轮工作。

## 身份与范畴 {#identity-scope}

哲学身份是司衡即 SiHankor，治理实体，承接哲学仓全部命题与铁律，命名承诺不被撤回。哲学权威归属于 sih-philosophy/，工程层所有操作受其约束。

工程产物是 sih-engine，本轮基础设施，AGENTS.md 与所有工程层声明即组件协议与校验规则与写入权限的身份锚定。

旧工程仓 sihankor/ 的实现已被废弃。失败设计不继承，失败经验已提炼为禁止条款，详见 sih-engine/tmp/old-repo-failure-analysis.md。

术语登记。司衡即 SiHankor 等于哲学身份即治理实体。司衡引擎即 sih-engine 等于工程产物即本轮基础设施。哲学仓即 sih-philosophy/ 等于唯一权威指导源。旧工程仓即 sihankor/ 等于已废弃沉默参考。

## 核心理念基线 {#core-principles}

五条基线，每条标注来源类型。来源类型四类：哲学命题承接流衍段或复归段命题条目标注命题 ID，convergence 层对照命题承接单盲推导体系工程命题标注命题编号与原文定位，工程实证经验来自失败复盘哲学仓无对应流衍命题标注待哲学锚定，工程基线是本工作区对话共识无哲学命题直接支撑。

### 第一条 确定性程序是治理操作的唯一执行者 {#principle-one}

LLM 只生成符号材料，不拥有写入知识包、事件流、意图锚定的权限。治理操作的执行归确定性程序，LLM 产出仅作为待校验的符号材料。

来源类型：工程基线即对话共识。convergence 层对照基础：D003 提议权对主对话关闭，定位 witness-archive/03-philosophy-skeleton.md 第 491 行。哲学相邻命题：PRO-07 鉴，检验由可重复程序承载。

### 第二条 信息洪流是旧仓失败根因 {#principle-two}

LLM 的生成速度与人类审查注意力之间存在结构性不对称，不是工程失误，是结构性约束。治理系统必须假设人类注意力是稀缺资源，将人类介入点限制在确定性程序无法自动处理的异常范围内。

来源类型：工程实证经验，来自旧 sihankor 仓失败复盘，详见 sih-engine/tmp/old-repo-failure-analysis.md。convergence 层对照基础：P2.1 速度不对称论证了不对称不可消除，定位 witness-archive/00-ai-coding-governance-principles.md 第 320 行。P3.1 退化机制论证了注意力预算的结构性稀释，定位该文件第 201 行。哲学相邻命题：PRO-03 道二与 PRO-08 应，为相邻但未精确覆盖。说明：convergence 层有对照基础，但 llm-friendly-build 检索路径暂未覆盖，须通过 sih-engine/doc/knowledge/KNOW-001-convergence-retrieval-map.md 回到 convergence 原文核验。

### 第三条 人类注意力只投向异常信号 {#principle-three}

治理系统的设计须确保确定性程序自动处理绝大多数操作，人类只在视图告警时介入，不看原始日志。

来源类型：工程基线，由第二条直接推论。convergence 层对照基础：P3.1.3 软退化先兆信号论证了纵向审查而非横向审查，定位 witness-archive/00-ai-coding-governance-principles.md 第 229 行。R7 交付度量原则论证了度量交付结果而非生成指标，定位该文件第 65 行。

### 第四条 可验证性约束 {#principle-four}

所有写入操作须满足三条：操作来源可追溯、操作结果可机械校验、操作历史不可篡改。LLM 的不可复现输出不得作为治理决策的最终依据。

来源类型：工程实证经验。convergence 层对照基础：P3.2 外化管理论证了外化三性质即持久性与版本化与可审计性，定位 witness-archive/00-ai-coding-governance-principles.md 第 242 行。P4.2 责任归属界定论证了四个可即 可追溯与可审计与可反驳与可继承，定位该文件第 472 行。说明一：本条与 convergence 层铁律 #6 方法学可重现原则同源精神，但指称域不同。铁律 #6 约束的是核心洞察层收敛率算法的可重现，本条约束的是工程写入操作的可验证，不构成对铁律 #6 的承接。说明二：convergence 层有对照基础，但 llm-friendly-build 检索路径暂未覆盖，须通过检索路径文件回到 convergence 原文核验。

### 第五条 治理延伸是减少 LLM 参与，而非增加 {#principle-five}

用更多 LLM 调用对抗 LLM 不确定性的模式，在治理核心中不采用。治理靠确定性程序，LLM 只作为符号材料的生成器。

来源类型：工程基线即对话共识。旧仓失败佐证：FM-11 用 LLM 并发解除注意力瓶颈反而加剧不对称，详见 sih-engine/tmp/old-repo-failure-analysis.md § FM-11。

## 工程禁止条款 {#prohibitions}

以下条款由工程基线与失败复盘直接推导。详细失败模式清单见 sih-engine/tmp/old-repo-failure-analysis.md。

禁止一：禁止 LLM 直接修改知识包或意图锚定。对应 AGENTS.md 工程禁止条款。对应失败模式 FM-03 与 FM-09。

禁止二：禁止用不可复现的多 Agent 交互产出作为治理决策依据。多主体协作本身是鉴层打破自证循环的哲学机制即 PRO-07，不是禁止对象。禁止的是不可复现的交互实现与用 LLM 调用堆叠替代确定性验证。对应失败模式 FM-01 与 FM-02 与 FM-12。关键区分见旧仓失败复盘 § 关键区分。

禁止三：禁止用 LLM 调用堆叠替代确定性验证。多 Agent 协同与红蓝对抗等模式若用于治理决策的执行环节，属于此类。用于鉴层检验环节则保留。

禁止四：所有治理操作必须写入事件流，留痕不可篡改。承接 PRO-08 应而不藏，留痕是应鉴循环的构成性条件。对应 convergence 层 P4.2 与 P4.3。

禁止五：人类只通过视图介入，不看原始日志。对应失败模式 FM-04 与 FM-05 与 FM-08 与 FM-10。

## 第一阶段目标 {#phase-one-goal}

第一阶段的目标是建立最小闭合治理环：打通一次完整的意图到执行到映照到留痕闭环，验证核心机制的可验证性。

最小闭合治理环不追求功能完整，只追求闭环可验证。闭环的每一步都须满足可验证性约束，即来源可追溯与结果可机械校验与历史不可篡改。

第一阶段不引入多 Agent 协同。多主体协作作为鉴层检验机制保留，但不在第一阶段的执行环节启用。第一阶段靠确定性程序与单 LLM 符号材料生成。

第一阶段产出的组件须各给最小语义定义。未定义的工程造词不被其他组件引用。这是对旧仓失败 FM-12 即未定义术语被引用导致骨架塌陷的防御。

## 任务清单 {#task-list}

四个任务定义第一阶段工作范围。每个任务标注输入、目标、范畴排除。

### 任务一 分析 sih-engine 如何消费哲学仓 {#task-one}

输入：sih-philosophy/ 的 llm-friendly-build 知识包、sih-engine/doc/knowledge/KNOW-001-convergence-retrieval-map.md、根 AGENTS.md 哲学仓地位小节。

目标：设计 sih-engine 消费哲学仓的工程路径，覆盖三个层次。第一层是流衍命题消费路径，代理遇到判据承载层与命名本体论与治理必要性等工程问题时查 llm-friendly-build 的 mapping.md 定位命题。第二层是 convergence 层消费路径，代理遇到翻译链与上下文退化与外化管理等工程问题时查 KNOW-001 convergence 检索路径回到 convergence 原文。第三层是消费边界的声明，明确哪些工程问题哲学仓已覆盖、哪些是工程层自行降格映射。

范畴排除：不修改哲学仓。不审哲学仓是否满足工程约束，哲学仓是真理源无义务满足工程仓的写入权限设计。不构建新的知识包，llm-friendly-build 的扩展是哲学仓自身演化程序的事。

### 任务二 旧仓失败根因归类 {#task-two}

输入：sih-engine/tmp/old-repo-failure-analysis.md 的 12 条失败模式清单。

目标：将失败根因归类为可复用的禁止条款与设计约束，每条标注在新仓中的落地位置。归类维度按设计决策层：范畴归属层的失败对应架构决策，实现方式层的失败对应设计规范，运行时层的失败对应运行时约束。

范畴排除：不重复旧仓失败复盘的工作，复盘已完成。不收录旧仓的可复用经验如 sih-doclint，那是工具链迁移的事。

### 任务三 第一阶段组件清单与协议 {#task-three}

输入：核心理念基线五条、convergence 层检索路径、旧仓失败教训。

目标：提出第一阶段的组件清单，按最小闭合治理环的四个节点排序。每个组件给出三样东西。第一是最小语义定义，即这个组件是什么、做什么、不做什么，用一段话讲清。第二是数据格式，含必须字段、可选字段、校验规则。第三是与事件流的集成方式，含哪些操作写入事件流、事件类型、负载结构。

组件间数据流关系须显式定义：从意图锚定写入事件流，从 LLM 消费事件流产出符号材料，从映照引擎校验到偏差记录写入事件流，从事件流事件到视图告警。

第一阶段组件须满足硬约束：每个组件先有最小语义定义再被其他组件引用。组件不使用未定义的工程造词。组件协议的写入权限归确定性程序，LLM 只生成待校验材料。

范畴排除：不定义组件的代码实现。不引入多 Agent 协同组件。不定义视图单元与微积分引擎的完整实现，只给最小语义定义。

### 任务四 sih-engine 目录结构与 AGENTS.md 组件索引 {#task-four}

输入：sih-engine/doc/decision/001-repository-structure.md 的仓库结构决策、第一阶段的组件清单。

目标：提出 sih-engine 的目录结构建议，覆盖事件流存储即 trail、提案区、历史版本等核心目录。目录结构须承接 DEC-001 仓库结构决策的五顶层节点，即文档区与治理区与源码与测试与工具集。

AGENTS.md 组件索引须在 sih-engine 的 AGENTS.md 中承载，根 AGENTS.md 不再追加组件索引。组件索引指向各组件协议文件，含组件名、最小语义定义、协议文件路径、哲学对照基础定位。

术语映射须承载哲学命题到工程组件的对应关系，标注来源类型。

范畴排除：不修改根 AGENTS.md。不定义 sih-engine 内 AGENTS.md 的完整内容，只定义组件索引部分的结构。

## 验收标准 {#acceptance-criteria}

全部产出须满足以下标准。

第一条：所有产出文件通过 sih-doclint 校验，退出码 0。

第二条：来源类型标注完整。每条工程原则标注来源类型，是哲学命题或 convergence 层对照命题或工程实证经验或工程基线。不伪托，不把工程实证经验标注为哲学命题，不把 convergence 层对照命题标注为流衍命题。

第三条：无伪锚定。不出现可验证性承接铁律 #6 的措辞。不出现信息洪流作为已有哲学指导的措辞。不出现可复现性是唯一合法性来源的措辞。

第四条：无未定义术语被引用。视图单元与微积分引擎与 ASK3 等工程造词若出现，须先给最小语义定义再被其他部分引用。第一阶段组件清单中的每个组件须先有定义再被数据流引用。

第五条：多主体协作与多 Agent 调用堆叠区分清晰。禁止条款不误伤鉴层检验机制。

第六条：L0 至 L3 若出现，标注来源是 Karpathy LLM Wiki 方法论，不是司衡原创。承接关系待理清，不在第一阶段强行承接。
