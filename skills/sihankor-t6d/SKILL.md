# Skill: sihankor-t6d（T6-D 长程任务集群范式）

T6-D 是工作流范式，即 Twin-agent 双子代理并行、Mainline 主线串行验证、Dependent 依赖收敛，不是任务编号。权威源为 sih-engine/task-packages/README.md 即范式与命名约定、task-packages/TEMPLATE.md 即任务包十节模板、ai-ex/T6-PARADIGMS.md 即四模式谱系与选择判据。本 skill 是调用契约，与权威源冲突时以权威源为准。

## 触发时机 {#trigger}

- 用户点名 T6-D、长程任务模式、集群模式、双子代理
- 用户要求大型批一次性完成且任务可分解为独立并行件
- 用户要求按任务包跑子代理

不触发：单点小改、纯问答、明确指定其他范式的任务。

## 硬性工作流 {#workflow}

用户显式点名 T6-D 时不得静默偏离，六步顺序固定。

一，主线编排。主 agent 分解任务为三类簇：并行簇即子代理可独立完成的件、主线簇即需完整上下文的最复杂件、依赖簇即须待验收后串行执行的件。

二，先写任务包再动手。落 task-packages/「主题-t6d.md」，按 TEMPLATE 十节，问题陈述、关键设计、工作清单按簇、可证伪条件即 F 锚定必须在跑前立文、必读文件、约束、验收标准、风险、范式偏离声明、关联文件。命名为主题前缀加 t6d 后缀，T6D-XX 作为编号用法是 README 已纠正的历史误用，不新用。

三，派双子代理。经 Agent 工具后台并行派发，一代理领一个并行簇。派发提示词自包含，即任务包的问题陈述、必读文件、该簇工作清单、约束、相关 F 锚定的原文，子代理只凭包内容跑，不依赖主会话上下文。

四，主线写最复杂件。主 agent 亲写主线簇，理由即该件需要全局上下文与裁决连续性。

五，主线串行验收。F 锚定逐条实跑验证，测试全绿，文档类产出走 T6 工具链即化格、核阅、检词、书简认证，随后写「主题-t6d-results.md」结果文件，含完成度表、F 锚定验证表、范式验证一行。

六，主线 commit 全部。

## 偏离纪律 {#deviation}

偏离分两类。其一任务类偏离：立文类与清残留类等确定性任务可改单代理直跑，但必须在任务包第九节写明偏离理由与保留项（T6-D 命名约定、F 锚定、跨仓同步），跑前立文，不得跑后补记。其二静默裸跑：不写任务包、不派子代理、主 agent 单线完成全部，此为违约。2026-08-22 用户抓到多次此类违约即本 skill 的成立原因，此后点名 T6-D 而裸跑视为违反本 skill。

## 谱系与经济性 {#lineage}

T6 四模式见 ai-ex/T6-PARADIGMS.md：T6-A 手工、T6-B 单次、T6-C 多轮、T6-D 集群。T6-D 实证数据为 2026-07-21 三文件批八分钟七万五千 token 对 T5 三十四万四千 token，经济性约四倍半。后缀族预留 T7-X 单子代理、T8-S 顺序链，见 README 命名约定表，启用须另立范式说明。

## 边界 {#boundary}

本 skill 固化调用契约不替代权威源。治理写入纪律不因范式豁免：子代理产出仍属符号材料，入库前过主线验收与工具链。子代理不得代人行签核类节点。
