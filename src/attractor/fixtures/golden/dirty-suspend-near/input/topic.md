# 待裁命题

lease 应增 pre-commit 守卫拦无模板 plain git commit，--no-verify 显式留痕放行。即：在 lease 治理的正规提交路径上增设 pre-commit 钩子守卫，凡未经理化提交模板（lease commit 正规路径）的 plain git commit 一律拦截；提交者确需绕过拦截时必须以 --no-verify 显式绕行并在留痕中显式记录绕行事由，显式留痕的绕行放行。病灶实证：2026-09-01 sealwin3-solo 追认档在案 plain git commit 直提违章六笔（engine 三笔 23df965、8f85112、9732b22 加 tools 三笔 0238bc6b、5bfb95b6、0add10f3，均系 goldfix 整改批绕 lease 直提），直提使 settle 前后对表失效、归并无前缀、认证缺席，sealwin2 与 sealwin3 两度封窗界线前移均为同一通道复发买单。守卫语义与工程基线的关系：基线四要求写入操作来源可追溯、结果可机械校验、历史不可篡改，plain commit 绕 lease 即绕开三性质的同时达成通道；拦无模板直提是堵未授权通道，--no-verify 显式留痕放行是保留显式授权通道，定向调节非一刀切。本命题为治理工具改动的应然裁断：判定的是该守卫是否应增设，不是守卫的实装实现。
